# ADR-0003 · 遗物清单外置为数据文件

| 状态 | 日期 | 依据 |
| --- | --- | --- |
| 已接受（补录） | 2026-11-15 | d406d55、e068769、684bf76（feat/relic-catalog，补录时未合入 main） |

## 背景与问题

遗物（可承载真相的实物）需要由内容侧扩展；位置的表达不能与实现层的楼层、部门 id 硬耦合。

## 决策

- 遗物清单外置为 `events/relics.json`：名称、介绍、可能出现的位置、附加属性与抽取预算全部由内容文件声明，改内容不动代码。
- 位置用**文件内词表**表达，锚定既有 Zone 与部门名；不硬引用楼层或部门 id。
- 加载 **fail-closed**：版本、重名、位置引用、权重区间、effects 白名单、碎片白名单、spawn 预算一次校验，错误聚合一次报出，缺失即显式失败，不静默降级。
- 开局实例化落库；**存档存快照，不存对清单的引用**。

## 被否掉的替代方案

- 遗物硬编码在 Go 代码里：内容改动都要改代码重新构建。
- 位置直接引用楼层/部门 id：内容文件耦合实现细节，id 调整即破坏内容。
- 存档存清单引用：后续清单增删会渗入旧档，破坏存档自洽。

## 后果与代价

- 清单成为可独立审查、可被内容扫描覆盖的文件；加载错误在启动时一次暴露。
- 快照语义：开局后清单增删不影响进行中的局。
