# 架构决策记录（ADR）

回答"为什么这么定"：每条裁决的背景、决策本身、被否掉的替代方案、代价。编号按裁决时间先后（0001 最早）；日期列为裁决落入文档或代码的落地日期，两者不一定同日。

## 与知识库的分工

- 知识库八份主题文档回答"**现在是什么样**"，不把旧设计稿或已作废基线写成现状。
- ADR 回答"**为什么这么定、当时否掉了什么、代价是什么**"。
- ADR 不重复机制说明；需要机制细节时引用对应主题文档或设计文档，自己只写决策与理由。
- 决策的现状描述以主题文档与代码为准；ADR 只保留决策过程，决策被取代时新记一条并把旧条标注"被取代"。

## 模板

新决策按 [TEMPLATE.md](TEMPLATE.md) 补录：一条决策一个文件，一眼读完，不抄设计细节。取代更早裁决时写清取代了什么。

## 维护约定

1. 一条裁决一个 ADR，原子提交；新裁决取代旧裁决时新记一条，旧条状态改"被取代"并链接新条，不改写旧条原文。
2. 裁决正文必须先落在设计文档或代码里，ADR 是补录索引，不做裁决的唯一载体。
3. 机制细节进对应主题文档，ADR 只引用不复制；发现 ADR 与现状冲突时以代码为准修正。
