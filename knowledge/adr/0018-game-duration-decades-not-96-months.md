# ADR-0018 · 整局时长以几十年计，96 个月不是标准窗口

| 状态 | 日期 | 依据 |
| --- | --- | --- |
| 已接受 | 2026-11-16 | 项目所有者裁决（会话指令下达） |

## 背景与问题

验收宿主、可玩路线测试与多份设计文档把 **96 个月（8 年）**当成游戏的标准时长窗口：把第 96 月当终点线，把 `acceptanceMaxMonths` 一类测试上限当游戏长度，并用"标准窗口内能否达成"判定结局是否成立。所有者口径：整局时长以几十年计，96 个月（8 年）窗口早已被否定。按被否窗口丈量出来的结论（例如《公议》"在标准窗口内锁不住约章"）是假问题。

## 决策

- **整局时长以几十年为单位**。96 个月 / 8 年 / Y8 不是标准窗口，不是游戏总长度，不是验收门槛，也不是判断机制是否成立的时间尺。
- 明确否定以下用法：把第 96 月当成整局终点线；把 `acceptanceMaxMonths` 等测试默认值或常量当成"游戏长度"；以"96 个月内未达成"判定某结局或机制不成立。
- **不改变**：单局仍是有限日历；同一版本内确定性可复现的要求不变；结局仲裁仍在固定时点触发；被否掉的只是"窗口长度 = 96"这个数，而不是"存在固定仲裁时点"这件事。
- **不以另一个总时长数字替换 96**（例如直接改写成 240 个月）。在所有者另行裁决标准时长之前，只拆除"96 是标准窗口"这一错误假设；不把任何新的月数当成默认答案。
- 剧情锚点恰好落在第 96 月附近时，按"锚点"而不是"窗口终点"对待，单独复核其取值是否只是为了配合 96 月而钉住；未经裁决不得借本 ADR 移动锚点。

## 被否掉的替代方案

- 把第 96 月当终点线：会让几十年尺度的内容、延迟链与长线积累被误判为"来不及"，并用假 deadline 反向压缩设计。
- 把 `acceptanceMaxMonths` / 测试循环上限当游戏长度：测试保护上限是工程常量，不是产品口径；用它评判机制成立与否会稳定产出假问题。
- 直接换成 240 个月等其他数字：只是把同一个错误（用一个固定月数定义整局长度）换个值重犯，且没有所有者裁决支撑。
- 保留 96 作为"验收专用窗口"：验收窗口一旦被当成产品标准，就会继续回流到文档、内容时点与锚点校准里。

## 后果与代价

- 既有以 96 个月窗口为前提的验收结论、基线表与"来不及/锁不住"判断全部作废，需要按真实时长口径重跑或重述；重跑涉及测试断言的，另批处理，不在本裁决内顺手放宽。
- 现有测试循环上限（96 等）只是工程保护边界，保留或调整都必须明确标注"不是游戏长度"；不得因本裁决直接把循环改大来让测试变绿。
- 当前固定锚点（`silo1_destroyed_signal` 在代码 Y130M1、18 号正典链 N9、`pre_fall_choice` / `charter_lock_day` 的相对锚点）暂不移动；它们与"几十年"时长的对齐列入锚点复核清单，另行裁决。
- 禁止：以本裁决为由放宽资格口径、跳过测试或删除断言；禁止继续用"96 个月标准窗口"撰写验收、roadmap 或内容时点表。
