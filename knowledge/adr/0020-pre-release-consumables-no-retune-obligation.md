# ADR-0020 · 上线前种子调优等消耗品不承担即时重调义务

| 状态 | 日期 | 依据 |
| --- | --- | --- |
| 已接受 | 2026-11-19 | 项目所有者裁决（会话指令下达）；[25 测试欠账](../../docs/research/25-v16-test-debt.md) §二/§五/§七的三次推迟与 §九批次 |

## 背景与问题

固定种子的可玩性/验收测试、parity 基线、轨迹转储的通过与否依赖共享 RNG 流的落点。任何新增掷骰点的机制（派系事件化 C1–C11 即是）都会批量平移落点，让这类测试漂移失败。25 篇欠账三次推迟重调（等 C7、等 C9、等合并态），每次推迟的理由都是「机制没定型，现在扫的种子下次还漂，双重返工」——但推迟本身没有裁决固化，重调批次仍被当作机制落地的伴随义务反复立项，消耗会话与 token。

## 决策

- **消耗品清单**：种子调优测试的固定种子及其通过记录、parity 基线、轨迹转储、快照基线。它们的价值依附于当前 RNG 流落点，机制一变即作废，属消耗品而非资产。
- **上线前不承担即时重调义务**：机制改动导致消耗品漂移失败时，只落欠账（失败清单 + 现象 + 原因，如 25 篇），机制本身照常合并；不为种子重调冻结合并，不主动立项批量扫种子，不为此消耗会话与 token。
- **重调只在两个时机发生**：项目所有者明确要求（含宣布机制定型后的批量重调），或正式上线前的验收整备。2026-11-19 批次（25 篇 §九）是所有者批准的收尾例外：成本已沉没（4/5 完成）、扫描设施可复用。
- **重调纪律不变**（一旦执行重调）：不削弱断言、不白盒状态、优先最小改动（只换种子 > 换种子+微调时序）；穷尽合理种子区间仍无命中则留档停止，不硬改。扫描设施（env 门控 sweep）作为可复用工具保留口径，不作为义务。
- **对 [ADR-0011](0011-opening-bias-needs-test-retuning.md) 的调整**：「重调后的通过记录」不再是开局机制合并的前置条件，测试账降级为欠账账（受影响测试清单 + 逐线可达性论证保留，供设计判断）。0011 的其余纪律保留：门控耦合旋钮的混沌边界警觉、结局塌缩时修偏向参数而非删测试——那是设计缺陷，不是消耗品磨损。
- **与 [ADR-0017](0017-no-backward-compat-before-release.md) 的关系**：0017 已允许基线随时作废；本条进一步免除作废后的重建义务与重调投入。同版本内确定性可复现的要求不降低（双跑逐字节一致仍是硬契约）。

## 被否掉的替代方案

- 机制落地必须伴随种子重调（0011 原口径的推广）：派系事件化期间三次证明这是双重返工，重调产出在下次掷骰点变动时归零，成本全落在开发侧。
- 漂移即删测试或放宽断言保绿：消灭的是回归保护本身，机制窗口期内的真实回归将无从暴露；欠账留档保留红信号，比假绿诚实。
- 每次漂移都自动批量扫种子：扫描本身可复用且便宜，但「何时值得扫」是裁决不是默认动作——无所有者指令时不启动。

## 后果与代价

- 接受：上线前可玩性测试会阶段性红着，红信号的含义是「已知漂移欠账」而非「代码回归」；读测试报告必须先对照欠账清单（25 篇）。
- 接受：两次机制改动之间的窗口期里，漂移测试覆盖的链条没有回归保护——这是省下的重调成本对应的真实风险，所有者已裁决承担。
- 禁止：以本裁决为由削弱断言、删除测试、降低同版本确定性要求；禁止把「不折腾消耗品」延伸到正式上线之后（发布后另立恢复纪律，与 0017 同构）。
- 开销账：重调批次的主要成本是扫描机时与会话 token；设施复用后边际成本下降，但是否投入仍由所有者裁决。
