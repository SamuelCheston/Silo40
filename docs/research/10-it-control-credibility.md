# IT 幕后权力：威势、Protocol 能动性与 Judicial 三方附着

> 日期：2026-11-14（机制边界、平衡与碎片生成器修订）
> 性质：机制设计提案，不包含代码改动。
> 目标：实现一个可被熟练玩家打穿、又会按 Protocol 主动自保的 IT； Judicial 可在 IT / Mayor / covenant 间迁移；碎片、检测、公开证据与 Safeguard 各自分层计算。

## 0. 阅读约定与结论摘要

- **【机制边界】**：本项目明确采用的抽象约束，不依赖外部人物或具体剧情。
- **【设计裁决】**：本轮明确的机制取舍；若与旧稿不同，以本节边界为准。
- **【现状事实】**：当前代码行为，不代表目标机制已经实现。
- **【设计提案】**：新增公式与参数；数值均是 sim 起点，`TODO(balance)` 不是实测结论。

核心方案：

1. 指标定名 **幕后威势（Shadow Authority，`W∈[0,100]`）**，衡量极小关键联盟相信 IT 仍能协调、赏罚和收场的程度，不是全民支持或资源存量。
2. IT 的 winning coalition 只有 **Judicial 法警系统**与 **IT 内部人员**。Police、Mayor 幕僚和其他部门忠诚于 Mayor，不属于 IT 联盟；IT 不能收买他们。
3. 常态下上层控制方 不联系本地 IT。IT 依据可能不完整、过时的 **Protocol 文本**行动；直接接触只由明确、可预测的极端门槛触发。
4. Judicial 附着 `A_IT/A_Mayor/A_covenant` 可迁移。Mayor 正统性不能单独开门；`W≤30` 打开人治迁移，`W≤18+公开证据Q` 打开法治迁移，covenant 成立后锁定。
5. IT 维护全部隐蔽：调整档案、控制信息流、以正常执法名义调配法警、选择性执行、让人安静消失、压制异常信号。公开亮相和反上层控制方 一样，均不在选项集。
6. 玩家可通过两条法警调度证据、执行失败和内部忠诚瓦解实际打穿：`TODO(balance)` 目标为 4–5 次有效操作看到首档松动，8–10 次有效操作争取 covenant，而非几十次曝光。
7. 碎片有连续确信 `B` 与版本 `π`；玩家 `B` 不直接加曝光 `E`。检测分 `UNSAMPLED / SAMPLED / DIRECT_PROTOCOL`，矿工是结构性不采样，IT 偏离进入 Protocol 后果而不是普通怀疑倍率。
8. `W` 不直接进入结局加分，只经组织行为、派系、人物和玩家状态进入既有仲裁。

```text
法警调度记录/执行失败/IT 内部事实
  → 玩家 B/π → 分享与公开 → 部门×阶层 B/π → E / Q
K（法警+IT 内部）/ D / P / X / E → 幕后威势 W
W + Mayor 正统性 L + Q → Judicial 三方附着

Protocol 文本 + IT 对上层控制方 的认知 → IT 隐蔽维护
三类 Protocol 偏离 → Safeguard 风险 / 可预测介入
玩家拆台 → IT 消耗有限 R_op 反击 → 反击随资源枯竭衰减
```

## 1. 机制边界、设计裁决与现状差距

### 1.1 抽象机制边界

- 【机制边界】权力链抽象为“上层控制方 → 本地 IT → 其他部门”；本地 IT 的少数关键岗位知悉上层规则，其他部门并不天然知情。
- 【机制边界】公开约章与处置规程是两类信息资产：前者可成为公开法律依据，后者用于受限处置与应急判断。
- 【机制边界】处置规程只覆盖有限情境，未知条件和条款冲突必须显式存在，不能把系统写成全知。
- 【设计裁决】本地 IT 常态只读取处置规程，上层控制方仅在明确、可预测的极端门槛下介入；常态指令、月度外部背书和定期补给不进入机制。
- 【设计裁决】IT 不直接渗透 Judicial 以外部门；日常可观察的暗权证据只来自 IT 直接调度 Judicial 后留下的目击与记录。
- 【设计提案】名称、公式、数值、utility、条款数据结构和认知梯度均为项目原创机制，不对应任何外部作品公式。

### 1.2 不可推翻的机制契约

| 机制 | 边界 |
| --- | --- |
| Mayor / Police / 其他部门 | Mayor 正统性是个人属性；Judicial 以外部门忠诚于 Mayor，不知道 IT 幕后掌权。 |
| IT 联盟 | 仅 Judicial 法警和 IT 内部；任何外部收买、公开施压都结构性不可选。 |
| Judicial 归属 | 玩家可通过摧毁 `W` 翻转；Mayor 高正统性本身永远不能翻转。 |
| Mayor / covenant | Mayor 是个人附着、可回摆；covenant 需更低 `W` 和公开证据，成立后基本不可逆。 |
| Protocol | 文本是常态信息源；违反、未贯彻、未达成目标是三类不同偏离。 |
|上层控制方 | 不在 IT 行动目标集合中；直接接触罕见、确定、可预警，不是随机天罚。 |
| 信息与检测 | 连续确信、分层版本；结构性不采样与普通数值惩罚分开；AP 与怀疑独立。 |
| 结局 | 玩家、驻地派系、具名人物、上层控制方 加权；Safeguard 等硬失败优先。 |

### 1.3 旧稿违背机制契约、必须删除的表述

| 旧设计 | 判定与修正 |
| --- | --- |
| IT 收买 Police 关键岗位、Mayor 幕僚、技术骨干 | **违背设计裁决，全部删除。** 这些部门不属于 IT 联盟，收买即公开亮相。 |
| IT 公关、公开制造外部威胁、公开兑现保障 | **违背隐蔽前提，全部删除。** 改为信息流控制与按 Protocol 隐蔽处置。 |
|上层控制方 常态指令、外部背书月度变化、按 `X` 补充资源 | **违背 Protocol 机制，全部删除。** 常态 `X=0`，只有稀有异常信号。 |
| 玩家与 IT 争夺 Mayor/Police 人员忠诚 | **删除。** 玩家只能争夺 Judicial 法警执行链和 IT 内部人员。 |
| 统一用职业倍率处理所有异常行为 | **不足。** 改为结构性检测类别；矿工不采样，IT 进入 Protocol 后果。 |

### 1.4 当前实现差距

- 当前 `Silo.Legitimacy` 是地堡级派生值，不能复用为 Mayor 个人正统性；见 [mechanics-comparison.md](./mechanics-comparison.md) §1.3。
- 当前 `KnownFragments` 是集合/计数，不足以表达 `B/π/E/Q`；见 [models.go](../../internal/model/models.go)。
- 当前玩家 IT 行动统一增加 Safeguard 风险，见 [03-gameplay-mechanics.md](../../knowledge/03-gameplay-mechanics.md) §4.2；目标系统要改为三类 Protocol 偏离，不能继续一条统一正惩罚覆盖全部情境。
- 当前普通内容事件不能直接修改 SafeguardRisk，见 [04-event-system.md](../../knowledge/04-event-system.md) §7；Protocol 应在 mechanic mutation 层落地，不伪造内容事件权限。
- 行动门控和多主体结局可复用，见 [mechanics-gating-endings.md](../../references/mechanics-gating-endings.md)。

## 3. 威势状态与信息系统

### 3.1 状态变量

| 符号 | 范围 | 含义 |
| --- | --- | --- |
| `W` | `[0,100]` | 幕后威势 |
| `K` | `[0,1]` | Judicial 法警与 IT 内部的加权忠诚 |
| `E` | `[0,1]` | 阴谋曝光高水位 |
| `D/P` | `[-1,1]` | 法警执行履约、人事连续性 |
| `X` | `[-1,1]` | **稀有异常外部信号**；常态为 0，不是月度指令 |
| `R_op` | `[0,100]` | IT 内部操作资源与可用法警时间的统一抽象 |
| `R_s` | `[0,1]` | Safeguard 风险 |

对 `D/P/X` 的渠道 `k`：

```text
V_k,t = clamp(Σe qe·2^(-age_e/half_life_k)·r_e·a_e,t·v_e,t, -1, 1)
```

默认半衰期 12/18/24 月。`r` 是结果，`a` 是 IT 归因，`v` 是联盟内知悉覆盖；同一 `fact_id` 只记一次。

### 3.2 月度更新

```text
K = 0.65·l_Bailiff + 0.35·l_ITInternal

W_eq,t = clamp(50 + 25K_t + 12D_t + 10P_t + 12X_t - 40E_t, 0, 100)
α      = 1 - 2^(-Δt/8)
W_t+1  = clamp(W_t + α(W_eq,t-W_t) + Σδe, 0, 100)
```

初始两块忠诚均为 0.8，`K=0.8`、`W_eq=70`。月 tick `Δt=1`，0 月不做被动漂移；冲击队列只消费一次。`E` 不随时间自动消退，新的履约和忠诚维护可以对冲。

外界通常不知道 IT，因此 `D/P/X` 主要使用法警系统和 IT 内部的知悉与归因，不把 Mayor 或普通部门的评价写进 `K`。

### 3.3 分层事实、版本与曝光

每个观察者 `p` 对事实 `e` 持有：

- `B_e,p∈[0,1]`：事实发生的确信度；
- `π_e,p,v`：事实成立时各解释版本的条件概率，`Σvπ=1`；
- 联合质量 `b_e,p,v=B_e,p·π_e,p,v`。

```text
E_now = clamp(Σe qE_e·Σg w_g·B_e,g·Σv π_e,g,v·a_e,v, 0, 1)
E_t   = max(E_t-1, E_now)
```

`E` 只在部门×阶层与具名人物 belief 层聚合，玩家自己的 `B` 不直接进入。普通事实若要形成“IT 幕后掌权”的外部归因，必须能连接到**法警受 IT 主任直接调度的证据链**；其他事故、档案或传闻本身不自动生成该归因。

Protocol 可以证明存在更高层处置规则，但单独读到 Protocol 仍不能证明当前 IT 正在操纵 Judicial；covenant 所需的公开归因仍需法警调度链。

### 3.4 碎片单次获取成功率

```text
p_get = clamp(
  0.55·f_prof·(1-0.45·mismatch)·(1-0.60·alert_d)
  ·(1+0.35·related_f)·access_c,
  0.05, 0.95
)
```

| 因子 | 范围 | 含义 |
| --- | --- | --- |
| `f_prof` | 0.75–1.25 | 玩家职业与材料的适配，不提供全知 |
| `mismatch` | `[0,1]` | 行为与目标部门规范冲突，见 §7.1 |
| `alert_d` | `[0,1]` | 目标部门戒备；失败探查和信息管控可提高 |
| `related_f` | `[0,1]` | `max_k related(f,k)·B_k,p`，只取最强相关项 |
| `access_c` | 0.60–1.15 | 渠道接触能力，与证据可靠性分开 |

| 渠道 | `access_c` | `reliability_c` |
| --- | ---: | ---: |
| 本职业内部记录 | 1.15 | 0.90 |
| 原始档案/实物 | 0.85 | 0.95 |
| 可信线人 | 1.00 | 0.70 |
| 签署证词 | 0.90 | 0.75 |
| 市面传闻 | 0.60 | 0.35 |

失败不增加 `B`，只结算 AP、检测和戒备；成功产生一次观察而非直接确信。`observation_id` 去重，不能重放 RNG 或收益。

### 3.5 多次吸收与版本更新

```text
s_i   = reliability_c·(0.85+0.15·related_f)·independence_i
B_new = 1 - (1-B_old)·(1 - s_i/(1+0.25·n))
```

`independence_i`：独立来源 1，同源转述 0.25，完全重复 0；`n` 是此前有效观察数。

| `s=0.65` 的有效观察数 | `B` |
| ---: | ---: |
| 1 | 0.650 |
| 2 | 0.832 |
| 3 | 0.905 |
| 4 | 0.940 |
| 5 | 0.960 |

第三次基本确定，第五次仍非 1。版本用贝叶斯更新：

```text
π_new(v) = π_old(v)·likelihood_i(v) / Σu π_old(u)·likelihood_i(u)
```

因此事实确信高，不等于“IT 主导”版本确信也高。

### 3.6 确信度与行动资格

| 玩家 `B` | 可支撑 | 不能支撑 |
| --- | --- | --- |
| `<0.30` | 私人笔记、猜疑 | 作为事实分享 |
| `0.30–0.59` | 带低置信标签的 rumor | 正式举报、归档 |
| `0.60–0.84` | 定向调查、私下对质、交叉取证 | 公开证据、covenant |
| `≥0.85` | 正式举报、申请归档 | 未经核验直接公开 |
| `≥0.90` 且材料可公开 | 核验后发布公开证据 | 绕过发布渠道与受众反应 |

`B≥0.90` 后不再增加行动收益。分享强度 `s_share=B_player·transmit_c·receptivity_g`，接收方再更新自己的 `B/π`，不存在 `E+=B_player`。

### 3.7 公开证据 `Q`

```text
Q = clamp(Σe qP_e·B_e,Judicial·π_e,Judicial,IT_unlawful
          ·public_provenance_e·public_coverage_e, 0, 1)
```

`public_provenance`：私人猜疑 0，匿名传闻 0.3，公开证词/未核验记录 0.6，已核验档案或市面可查原始记录 1。`public_coverage` 是实际公开覆盖率。

covenant 还要求至少两个独立事实满足 `B_Judicial≥0.85`、provenance≥0.8、coverage≥0.60。核心法警调度事实建议 `qP=0.60`，使两份高确信、高覆盖证据能够实际达到 `Q≥0.85`，而不是理论上永远差一点。

公开证据先经 `E` 降 `W`，再经 `Q` 开 covenant 门，是串联效果，不重复扣威势。

## 4. 威势来源与玩家有效杠杆

| 来源 | 公式 | 默认量级 | 边界 |
| --- | --- | --- | --- |
| 法警调度阴谋曝光 | `-40E` | 单个核心事实 `qE=0.20–0.30` | 两份有效公开证据可产生约 `-12…-20` 均衡压力 |
| 法警执行履约 | `+12D` | 单事实 `q=0.25`，四次同级约 `±12` | 经济/事故只有进入法警处置链并被归因时才影响 `W` |
| 人事连续性 | `+10P` | 单事实 `q=0.35` | IT 内部倒戈、主任继承失序、法警指挥链断裂 |
| 二元关键联盟 | `+25K` | 初始 +20；法警忠诚大幅下降可再损失 5–10 | 只有法警与 IT 内部，不含其他部门 |
| 公开能力检验 | 即时 `δe` | 成功 +2…+5；失败/失控 -6…-9 | 熟练玩家可用一次关键失败加速过线 |
| 稀有异常外部信号 | `+12X` | 单次 `q=0.50`；常态 0 | 不是常规背书，不得每月刷新 |

即时冲击 `δe=clamp(base·severity·a·v·novelty,-9,+9)`，单月合计 cap 12。一个核心曝光事实、一次公开执行失败和一次关键忠诚损失必须能合计产生 25–40 点均衡/冲击压力，杜绝“几十次才动一点”。

## 5. IT 的二元 selectorate 与 Protocol 能动性

### 5.1 支撑面只有两块

| 支持者（权重） | 私人物品 | 恐惧 | 前途 | 真相 | 隐蔽边界 |
| --- | ---: | ---: | ---: | ---: | --- |
| Judicial 法警系统（0.65） | 10 | 6 | 9 | 14 | 只能伪装成正常执法资源、晋升和免责，不能以 IT 名义贿赂 |
| IT 内部人员（0.35） | 6 | 7 | 6 | 5 | 可在密室内部使用；真相分享受 clearance 和认知梯度限制 |

```text
l_g,new = l_g + η_method·(1-l_g)
```

`η_goods=0.20`、`η_fear=0.30`、`η_career=0.25`、`η_truth=0.35`。非恐惧维护每月向基线回归 3%，恐惧回归 8%。恐惧短期便宜，长期更脆弱。

Police、Mayor 幕僚、Mechanical 等不在表中：他们没有 `l_g`，不能被收买，也不进入 `K`。

### 5.2 有限资源与弱势成本

```text
R_op,next = clamp(R_op + 8 - Σcost_a, 0, 100)
cost_a = ceil(base_cost_a·(1+3·(1-W/100)^2))
```

初始 `R_op=60`，每月 +8，上限 100。成本倍率在 `W=100/70/30/0` 分别为 `1.00/1.27/2.47/4.00`。

`R_op` 抽象 IT 内部材料、密室操作能力和可隐蔽支配的法警时间。IT 不能从公共 Supplies 暗中无限提款；私人物品只能消耗已划归 IT 的内部配给，法警动作占用真实有限的执法时段。玩家可争夺这些内部配给、档案访问和法警时间，但不能与 IT 争夺 Mayor/Police 忠诚，因为后者从来不是 IT 资源。

### 5.3 隐蔽维护动作与暴露风险

“直接暴露”只可能由 IT 主任直接调用法警产生。其他动作的直接暴露恒为 0，但失控可能迫使 IT 再调用法警，形成二次风险。

| 动作 | 基础成本 | 主要效果 | 直接暴露 | 失控后需法警概率 | Protocol/Safeguard 衔接 |
| --- | ---: | --- | ---: | ---: | --- |
| 伪造与调整档案 | 7 | `W+2`；改变新材料版本 likelihood | 0 | 0.04 | 若篡改必需报告，构成违反或未贯彻；不能修改真实结果 |
| 控制信息流 | 6 | `W+2`；一月内新传播 ×0.7 | 0 | 0.03 | 合规遮蔽可降低异常风险；不得降低 `E` 高水位 |
| 以正常执法名义调配法警 | 10 | `W+4`；控制指定目标/记录 | **0.18** | 已含 | 生成唯一日常 `judicial_dispatch` 泄漏链；成败还进入 `D` |
| 延迟与选择性执行 | 7 | `W+3`；推迟玩家证据生效 | 0 | 0.06 | 若错过 Protocol deadline，转为“未贯彻” |
| 让某人安静地消失 | 12 | `W+6`；阻断指定来源后续传播 | 0 | 0.10 | 若 Protocol 未授权则属违反；失败可迫使法警收场 |
| 压制异常信号 | 8 | `W+3`；降低指定异常信号强度 | 0 | 0.05 | Protocol 要求时 `R_s-0.03`；错误压制必需上报则构成未贯彻 |
| 按 Protocol 隐蔽处置风险 | 7 | `W+2`；恢复一项 Protocol 目标 | 0 | 0.02 | 真正降低风险时 `R_s-0.04`，不自创公开功劳 |

直接暴露概率：

```text
p_expose = clamp(0.18·(1+0.5·alert_target)·(1+0.5·failed_dispatch), 0, 0.85)
```

暴露只生成法警调度事实，仍须经过观察者 `B/π` 和公开传播才影响 `E/Q`。

### 5.4 结构性不可执行：公开亮相与反上层控制方

以下不在 IT 候选生成或执行 schema 中，不是“成本很高”：

- 以 IT 名义公开讲话、公开施压、公开制造威胁叙事；
- 收买 Police、Mayor 幕僚或其他部门；
- 以 IT 名义公开指挥 Judicial；
- 把上层控制方 选作行动目标、加入反上层控制方 联盟。

玩家强行引导时：IT 首先拒绝；持续引导会被误读为知情者威胁，可能触法警反向调查。若已造成公开确认，法警系统可能为自保而反噬，记 `l_Bailiff-0.25`、`W-8` 并生成公开事实，而不是 IT 顺势公开执政。反上层控制方 诱导永远没有成功分支；若进入上层控制方 依赖链，由极端介入规则处理。

### 5.5 双动机 utility

```text
Self(a)    = ΔW_pred(a)/6 + 1.5·RegimeLossAverted(a) + 0.5·ΔK_pred(a)
Public(a)  = -ΔR_s_pred(a)/0.05
Utility(a) = 0.5·Self(a) + 0.5·Public(a) - 0.01·cost_a
```

IT 从自己按 Protocol 与碎片形成的预测中选择 `Utility>0` 的最高分动作，同分按 action ID。它读不到真实全知结果，玩家可通过伪造本地 Protocol 副本或档案影响其判断，但不能修改上层控制方 对真实结果的判定。

- **同向**：按 Protocol 隐蔽处置风险同时 `W+2/R_s-0.04`，看起来像尽责，也确实保护地堡。
- **冲突**：Judicial 即将转向时，安静消失可能因 `RegimeLossAverted≈1` 被选中；若构成违反，则保威势却推高介入风险。
- **选错**：过度清理会推高 Safeguard 并制造法警反噬；不清理则可能失去 Judicial。玩家可从资源消耗、法警调度与后果读出它在保护谁。

反击强度：`R_op≥50` 每月最多两个动作；`12–49` 最多一个；`<12` 只做负担得起的低强度动作；0 不主动维护。成本随 `W` 上升而收入不变，因此反击会随资源枯竭实际衰减，不会锁死玩家。

## 6. Protocol 内容资产、偏离与上层控制方 认知

### 6.1 Protocol 作为内容资产

建议 `events/protocol/*.json`，与公开 Covenant 分离。每条条款：

```text
id / version / category / precondition
required_action_or_forbidden_action / deadline
target_metric / target_range / review_interval
severity / safeguard_delta / intervention_points
reporting_requirement / known_gaps
```

| 条款类别 | 覆盖情境 | 判定例 |
| --- | --- | --- |
| `prohibition` | 未授权越界、隐瞒必需报告、禁止的跨堡接触、禁止清理 | 实际行为匹配禁止谓词即构成违反 |
| `required_response` | 高危处置失败、异常信号、指定目击、失控前兆 | 在 deadline 前完成规定处置与上报 |
| `outcome_target` | 无失控叛乱、官方叙事仍可持续、指定异常被隔离 | 到 review 日读取真实结果，不看 IT 是否努力 |
| `reporting` | 何种异常必须记录、何时留档、何时允许极端接触 | 报告缺失单独计时，不能由伪造本地副本消除 |
| `gap/exception` | Protocol 没写或条件互相冲突 | 标为未知，不自动视为安全；IT 需用碎片推断 |

玩家能否读到：Protocol 不在公共图书馆。IT 学徒即使读遍普通藏书也不会得知上层控制方；主任也只能通过 Protocol、密室日志、任命培训 记忆和稀有接触逐步理解。非 IT 玩家可经法警调度调查找到密室位置、从倒戈 IT 内部人员取得副本、或在 IT 崩解后回收档案。

玩家可篡改/伪造**本地副本**，影响 IT 的 believed Protocol；不能篡改上层控制方 用来判定真实偏离的权威条款与结果。伪造副本同样具有 `B/π/provenance`，被识破会生成新事实。

### 6.2 三类偏离的判定与后果

| 类型 | 确定性判定 | 分级 | 对 `R_s` | 对 `W` | 对介入分 `J` |
| --- | --- | --- | --- | --- | --- |
| **违反 Protocol** | 实际动作命中有效禁止条款 | 轻微/重大/存在级 | +0.02 / +0.08 / +0.25 | 若联盟知悉，-2 / -5 / -10 | +0.2 / +0.6 / +1.2 |
| **未贯彻 Protocol** | 必需动作、清理或报告超过 deadline 未完成 | 轻微/重大/关键 | 每逾期月 +0.01 / +0.03 / +0.06 | -1 / -3 / -5 | +0.15 / +0.40 / +0.80 |
| **未达成 Protocol 目标** | review 日真实目标越界，即使每步合规 | 轻微/重大/关键 | 每次 review +0.02 / +0.05 / +0.10 | -2 / -4 / -6 | +0.25 / +0.60 / +1.00 |

- 违反强调行为本身，未贯彻强调时限，未达成强调结果；同一事件可分别命中，但每个条款每类只记一次。
- IT 对条款不知情不会改变真实判定，只影响其预测；伪造报告可推迟“未贯彻”被发现，不能消除“未达成目标”。
- `W` 惩罚需要关键联盟知悉，`R_s/J` 是权威系统结果，不依赖全民舆论。

### 6.3上层控制方 介入：罕见、确定、可预测

```text
J = Σ intervention_points_of_open_deviations
```

常态无接触。满足以下之一才进入介入链：

1. **存在级违反**：立即进入一次权威审查；
2. `J≥1.0`：生成带具体条款原因的异常预警，给玩家和 IT 可观察征兆；
3. `J≥1.5` 且关键目标连续两个 review 未恢复：进入“限期纠正 → 权威覆写/重置 → Safeguard 评估”序列。

介入不使用随机抽取，不因单月小偏离直接天罚。预警必须显示缺失条款、剩余 review 数和可能后果；上层控制方 有人出于良心直接提醒属于 `J≥1.0` 后的稀有具名事件，不是日常指令通道。`R_s≥1` 仍是独立硬失败。

### 6.4 IT 主任对上层控制方 的认知梯度

主任认知 `G∈[0,1]` 由上层控制方 相关事实的 `B/π` 聚合，不用普通图书数量：

| `G` | 认知 |
| --- | --- |
| `<0.10` | 学徒阶段：不知道上层控制方 存在；普通地堡藏书对 `G` 贡献为 0 |
| `0.10–0.35` | 察觉 Protocol 不是本地经验总结，存在隐藏编写者 |
| `0.35–0.65` | 推断存在跨堡处置网络 |
| `0.65–0.85` | 理解上层控制方、任命培训 与 Protocol 的来源关系 |
| `>0.85` | 理解上层控制方 的人员局限、介入逻辑与非全知性；通常需主任级长期积累 |

`G` 不是读书按钮，也不是主任任命时自动灌入的答案。§6.5 的三类生成器提供 Observation，只有新观察、事后参悟和交叉验证才推进它。玩家提供、扣留或伪造材料可以加速/误导认知：

- 加速可换更准确的介入预警、Protocol gap 判断和更可预测的 IT 行为；
- 误导可诱使 IT 做合规但无效的处置，但真实“未达成目标”仍会反噬；
- 高认知不等于反上层控制方，永远不会解锁该目标。

### 6.5上层控制方 信息碎片的三类生成器

本节与 [11-information-fragments-design.md](./11-information-fragments-design.md) 对齐：

```text
Fact：实际发生了什么
Version：这些事实可能说明什么
Observation：某位观察者经某渠道得到的具体材料
```

三条路径都生成可重复使用的 Observation，不是只能看一次的剧情。它们不直接修改 `G/W/E/Q`：先更新观察者 `B/π`，再按各自主规则生效。

| 路径 | Fact | Version | Observation | 可重复性 | 玩家主动制造 |
| --- | --- | --- | --- | --- | --- |
| Relic | 某实物存在及其记载；硬盘可指向多堡网络 | 旧世界遗物 / 多堡证据 / 需进一步解码 | 对指定实物的一次检查、读取或鉴定 | 每件实物×观察者×检查方式一次；不同实物可继续生成 | 挖掘、回收、搜查、交易、追查没收链 |
| Protocol 参悟 | 一次具体处置与 Protocol 不符、缺条或目标失败 | Protocol 过时 / 存在隐藏作者 / 存在跨堡网络 | 事后边注、回忆、推演记录 | 每个不同 `reflection_key` 一次 | 制造异常、放大结果偏差、诱导错位执行 |
| 控制通道 对话 | 控制通道 在特定时间作出解释、警告或命令 | 自动系统 / 人类管理员 / 更高任命与生死权 | 一段对话记录、录音或主任记忆 | 每个不同 `utterance_id` 一次 | 制造介入条件、提供质问依据、制造继承异常 |

#### A. Relic 遗物生成器

**实物类型清单。** 以下只保留可携带、可检查、可没收和可形成独立观察的抽象机制，不绑定人物、藏品归属或特定解码桥段：

| 实物类型 | 承载信息 | 设计生成地点 | 接触与违法性 |
| --- | --- | --- | --- |
| **禁忌电子存储介质** | 加密历史档案、多堡技术资料；技术资料属于介质内容，不是另造纸质施工图 | 地下封存设施、旧仓库、Recycling；被收缴后在 Judicial 证物库或 IT 密室 | 矿工/回收人员可在作业中发现，Mayor 无隐藏地点线索反而不能凭职位读取；最高违禁品，持有即重罪 |
| **个人随身物品** | 旧时期个人物品与登记制度；本身不直接证明上层控制方 | 居住区、旧仓库、回收设施、地下私人藏点 | 登记合法化后可持有；未登记按一般实物处理，不能提供上层控制方洞察 |
| **日用品与包装** | 旧时期日用品、来源年代和私人关系 | 居住区、旧仓库、回收设施、私人藏点 | 可经实物接触者获得；未登记持有可能违法，无直接上层控制方信息 |
| **影像记录设备** | 可读取旧影像、外部世界或人物活动；具体内容取决于实际影像 Observation | 旧仓库、回收设施、地下封存设施 | 需要可用设备与读取能力；未登记持有违法，IT 可经 Judicial 收缴 |
| **旧世界地理与生活读物** | 旧时期地理、旅行与日常生活；支持“旧世界叙事被改写”，不单独证明当前 IT 掌权 | 民间藏书点、旧书仓、地下封存设施 | 接触依赖民间保存网络而非官职；持有违法，可被 Judicial 没收 |
| **旧版书籍** | 可与加密档案组合产生解码 Observation；不指定书名、页码或特定人物信件 | 旧书仓、私人藏书、Judicial 证物库、IT 档案点 | 按本地书籍登记与关联案件判定，不预设一律违法 |

**明确不列入**：研究没有给出独立“前地堡杂志”或纸质“施工图纸”实物，暂不生成；固定设施上的建造标记和电子介质中的技术资料可形成检查 Observation，但不作为可装进口袋的新 Relic。

**实物与 Observation 分离：**

```text
RelicItem {
  item_id, fact_id, holder, location, condition,
  registration_status, confiscable, observation_seed
}
Observation key = item_id × observer_id × inspection_method
```

- 触发条件：挖掘/回收发现、旧仓搜查、私人交易、证物检查或与关联材料组合鉴定。
- 产出：先创建/转移 `RelicItem`，再生成实物检查 Observation；实物本身不是抽象碎片，也不会因生成文本而复制。
- 可重复性：地点按有限实例表生成多件物品，同一物品同一检查方式不能反复刷 `B`；修复、独立鉴定或与硬盘/解码书组合属于新检查方式。
- 没收：Judicial 可依法收缴，物品改变 holder/location；原观察者的 Observation 保留，但再次出示实物、公开核验和 `Q` 需要能访问原物或已核验档案。
- 接触资格由**地点、关系和物理持有**决定，不由 Mayor 官职自动授予。矿工能在矿层挖掘发现实物，Mayor 没有藏点线索时反而接触不到。
- 例行 Judicial 收缴不产生 IT 归因；只有 IT 主任直接下令针对某件物品的收缴，才额外生成 `judicial_dispatch` Fact/Observation，遵守唯一日常泄漏路径。

#### B. IT 主任参悟 Protocol 生成器

参悟发生在具体事件结算后的回溯阶段，不是点击 Protocol 阅读全文。

**触发条件：**

```text
reflection_key = event_type + clause_id + outcome_signature
触发需同时满足：
  主任参与或事后知悉该事件
  AND actual_outcome 与 believed_Protocol_expectation 有显著偏差
  AND 该 reflection_key 未曾结算
```

可触发的事件类型：

| 事件类型 | 触发样子 | 参悟可能支持的 Version | 玩家间接制造方式 |
| --- | --- | --- | --- |
| `protocol_gap` | 事件超出 Protocol 已载情境，例如高危处置后出现手册未覆盖的新结果 | Protocol 不完整、作者不知道所有未来 | 制造未覆盖异常、组合两个原本独立的条件 |
| `contradictory_clauses` | 两条条款在同一事件要求冲突行动 | 手册存在历史层积或更高优先级未写明 | 诱导时点错位、拖延至两个 deadline 同时到期 |
| `unexpected_outcome` | 按条款执行却明显未达成目标 | 合规不等于理解、处置模型可能过时 | 改变执行环境、扣留关键资源或证据 |
| `unhandled_anomaly` | 出现异常信号但找不到对应条款 | 存在未向本地主任开放的处置层 | 提供异常信号、隐藏上下文再让结果显现 |
| `cross_case_pattern` | 两次以上不同事件出现同类异常 | 异常不是巧合，可能有统一外部来源 | 重复制造同类但不同 `outcome_signature` 的事件 |

**产出形态：** `director_margin_note`、`post_event_recall` 或 `case_comparison`，均是指向实际事件 Fact 的 Observation；它们支持隐藏作者、过时 Protocol、跨堡网络等 Version，不把主任的推断直接写成权威 Fact。

**认知节奏 `TODO(balance)`：**

```text
G_new = G_old + (1-G_old)·(g_base + Σ g_reflection)
g_base：仅主任履职期 0.004/月；学徒普通读书为 0
g_reflection：轻微偏差 0.03 / 条款冲突 0.06 / 重大 gap 0.10 / 控制通道 程序异常 0.15
```

- 学徒到具备主任资格通常为 **8–12 年**，这是训练与晋升，不等于知道上层控制方。
- 主任在自然事件密度下达到 `G>0.85` 通常需 **25–40 年**，接近一生参悟。
- 玩家若能持续制造 **12–20 次真正不同的有效异常**，可把这一过程压缩到约 **3–6 年**；同一 `reflection_key` 重复无效，不能按月刷同一事故。
- 以上是手感目标，不是实测保证；`G` 推进以事件为主，`g_base` 只代表长期职业浸润。

#### C.上层控制方 干预与 控制通道 对话生成器

控制通道 不是孤立 AI，而是连接上层控制方 管理员的界面；主任起初可以以为自己面对机器。本生成器只保留抽象情报机制，不包含具名人物、对白、场景或可识别的具体剧情。

**开启条件：** `J≥1.0` 的异常预警、存在级审查、权威覆写或继承异常。每次对话含稳定 `dialogue_id`，每句有 `utterance_id`；同一句话不重复产出。

**可生成的抽象异常类型：**

| 异常类型 | Fact | Observation 与支持的 Version |
| --- | --- | --- |
| 生死权声明 | 对话通道声称能够终止整个地堡，并在局势压力升高时重复警告 | 对话记录支持“存在一个掌握全堡生死的更高权柄”；其是否为人类管理员仍由后续 Version 竞争 |
| 越级任命 | 正常内部继承程序被对话通道直接越过并指定继任者 | 任命记录支持“存在高于本地主任的任命权”，形成 `g_reflection=0.15` 的程序异常 |
| 主动解释或命令 | 对话通道提供本地主任无从获得的处置依据或跨域信息 | 对话记录支持“存在外部信息来源”，具体内容与泄漏量仍由本次 utterance 决定 |

**泄漏量由什么决定：**

```text
leak_i = clamp(
  base_utterance + 0.20·urgency + 0.20·provocation
  + 0.15·operator_slip + 0.10·G - 0.15·operator_discipline,
  0, 1
)
```

- `base_utterance`：一般警告 0.25、解释 0.35、直接命令 0.45、越级任命 0.60；
- `urgency=min(1,J/1.5)`：局势越紧急，管理员越可能越过标准措辞；
- `provocation∈[0,1]`：主任是否拿具体矛盾质问；
- `operator_slip/discipline∈[0,1]`：人类管理员的失言程度与话术纪律；
- `G` 只影响主任能识别多少异常，低 `G` 仍保留原始对话 Observation，不会把关键句藏掉。

**主任怀疑是事件式而非线性。** 另设 `H_channel∈[0,1]` 表示“控制通道 背后存在人类/更高权柄”的怀疑：

```text
H_channel,new = 1 - (1-H_channel,old)·(1-leak_i·independence_i)
```

独立新命令为 1，同类新措辞为 0.25，完全重复为 0。`H_channel` 跨 0.35/0.65 时解锁更具体的追问；`G` 仍由交叉验证和参悟推进，二者不合并。

**对 `W` 与行为模式分开：**

- 每个不同泄漏若被法警或 IT 内部联盟知悉，产生 `δW_leak=-(2+4·leak_i)`：本地 IT 主任并非最高权柄，联盟对本地权力稳定性的判断受损。
- 泄漏若进一步公开，只再经受众 `B/π→E` 影响 `W`，不得另加一次“公开泄漏 shock”；内部威势损失与外部曝光是不同受众通道。
- `G/H_channel` 不直接给 `W` 正负奖励。认知提高后，主任可能更准确预判介入、减少 Protocol gap，经 `D/P` 间接增强 `W`；也可能因知道对方并非全知而减少高风险清理，短期削弱 `W`。结果由后续行为决定。

**玩家促使质问的手段：**

1. 制造可预警的 Protocol 偏离，使 控制通道 必须反复警告，为主任提供矛盾素材；
2. 向主任投放两份互相冲突的执行结果，提升 `provocation`；
3. 影响继承危机或暴露前任处置，使任命程序成为可见异常；
4. 通过 IT 内部人员提供“生死权来自哪里”“谁有权任命继任者”的问题线索。非 IT 玩家不能直接呼叫 控制通道，除非先获得密室与对话权限。

#### 三条路径与现有设计的衔接

- 三条路径均遵守文档 11：结构化 `Fact/Version` 由内容注册表锁定，Observation 只实例化一次；LLM 若用于润色，也不能改变泄漏量、条款、证据资格或 `B/π`。
- Relic 是可没收实物，Protocol 参悟是事后认知事件，控制通道 对话是独立人际情报渠道；三者不能合并成统一“读书进度”。
- 控制通道 仅作为极端介入中的抽象情报通道，不保留来源人物、对白或具体事件；与“平时只读 Protocol”不冲突。
- 旧版 `G` 的泛化累积被本节的事件式生成器细化，**不改变 S 曲线、Judicial 三方附着、`E/Q` 聚合或 Safeguard 硬失败**。
- 实物没收不会删除已存 Observation，但会影响公开核验；同一实物、同一参悟键、同一句 控制通道 话语均不能反复刷 `G/W/E/Q`。

## 7. Judicial 三方附着与可打穿平衡

### 7.1 威势响应

```text
S(W) = 1 / (1 + exp(-(W-38)/3.5))
F(W) = 1 - S(W)
```

| `W` | 100 | 60 | 50 | 45 | 40 | 38 | 35 | 30 | 20 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `S(W)` | 1.000 | 0.998 | 0.969 | 0.881 | 0.639 | 0.500 | 0.298 | 0.092 | 0.006 |

初始 `A=(0.85,0.10,0.05)`，表示深渗透的历史起点，不是永久锁。始终 `A≥0、ΣA=1`。

### 7.2 两档开门与迁移公式

```text
H_M = 1 当且仅当 W≤30 且 L≥0.35，否则为 0
H_P = 1 当且仅当 W≤18、Q≥0.85 且独立公开事实数≥2，否则为 0
m(L) = 0.75 + 0.25L
```

若 `H_P=0`：

```text
T_Mayor = H_M·F·m(L) + (1-H_M)·0.075·L
T_IT    = 1 - T_Mayor
T_covenant  = 0
```

若 `H_P=1`：

```text
Z_IT    = S + (1-H_M)·F
Z_Mayor = H_M·F·m(L)
Z_covenant  = 1.5·F·Q
T_j     = Z_j/(Z_IT+Z_Mayor+Z_covenant)
```

```text
A_j,next = 0.4·A_j + 0.6·T_j
```

covenant 锁定后 `T_covenant=1`。`W>30` 时 Mayor 目标份额最多 7.5%，高 `L` 不能翻转；`W` 下跌才释放附着。

### 7.3 人治回摆与法治锁定

- **Mayor**：`W≤30/L≥0.35` 连续 2 月且 `A_Mayor≥0.60` 后进入；31–44 保持滞回，同一 Mayor 在任且 `W≥45` 连续 3 月可回 IT。
- Mayor 失势/免职/更替：进入 `SWING`，`A_Mayor×=0.25`，释放权重按当前 IT/covenant 目标分配；新 Mayor 重新积累。
- **covenant**：`W≤18/Q≥0.85/两个独立公开事实` 连续 3 月且 `A_covenant≥0.55` 后进入并写 `covenant_locked=true`。
- covenant 后普通威势恢复、Mayor 更替或舆论回落均不解锁，只有明确的宪法级重写剧情可解除。

实际命令可靠性：`O_IT=A_IT·S(W)`、`O_Mayor=A_Mayor·m(L)`、`O_covenant=A_covenant·Q`（锁定后用 `A_covenant`）。未执行部分是拒令与摩擦，不自动归另一方。

## 8. 检测、AP 与其他机制自洽

### 8.1 行为—部门规范冲突与 AP

令 `a∈[-1,1]` 为行为偏离部门规范的方向和强度，`d∈[-1,1]` 为部门规范倾向：

```text
mismatch = |a|·max(0,-sign(a)·d)
AP_cost  = ceil(base_AP·(1+0.5·mismatch))
```

AP 表示组织行动、找渠道和承受社交阻力的成本，只看行动本身与规范冲突；目击、记录和身份监控不重复塞进 AP。

### 8.2 三类检测流程

| 类别 | 判定 | 后果 |
| --- | --- | --- |
| `UNSAMPLED` | 身份×位置不在监控采样框；矿工普通行为默认属于此类 | **不进入检测流程**：无采样 RNG、无普通怀疑增量、无“很小系数”。AP 仍独立计算 |
| `SAMPLED` | 在监控范围内的普通身份与行为 | 使用 §8.3 数值公式 |
| `DIRECT_PROTOCOL` | 行为触及 Protocol 禁止/必需/目标，IT 的相关行为优先进入此类 | 不生成普通怀疑惩罚，直接按 §6.2 计算 `R_s/W/J` |

矿工若主动制造正式 Judicial 案件或触及 Protocol，不是把系数调大，而是新建相应案件/Protocol 路径；普通监控采样仍保持豁免。

### 8.3 `SAMPLED` 的总怀疑公式

```text
Δsuspicion = base_action·V_identity·F_fit·W_witness·R_record·(1+mismatch)
```

| 因子 | 范围 | 依据 |
| --- | --- | --- |
| `base_action` | 0.01–0.05 | 行为本身的敏感性，不含身份和传播 |
| `V_identity` | 0.5–2.0 | 执行者在该部门/楼层的可见度；Mayor/上层精英高，普通中层低 |
| `F_fit` | 0.6–2.0 | 行为与身份职责的符合度；利用职务正常办事低，身份自相矛盾高 |
| `W_witness` | 私下 0.35 / 小圈子 1.0 / 部门 1.6 / 公开 2.2 | 同时在场目击者与二次传播半径 |
| `R_record` | 无记录 0.7 / 匿名日志 1.0 / 个人档案 1.35 / 监控或告示 1.6 | 可复核记录延长可检测性 |
| `1+mismatch` | 1–2 | 排外规范越强，逆行越显眼；极端时翻倍 |

这些因子只乘普通怀疑，不乘 AP，也不替代 `DIRECT_PROTOCOL`。IT 触及 Protocol 时不是“怀疑度很大”，而是直接发生偏离后果。

### 8.4 信息、门控、结局与确定性

- 玩家 `B` 只决定行动和输出证据强度；`E/Q` 只读相应受众层，无重复曝光。
- LOCKED 行动不能产生观察、Protocol、维护或附着效果；目标校验同时拒绝公开亮相与上层控制方。
- 现有玩家 IT 行动统一加 Safeguard 风险与新三类偏离存在实现冲突；落地时必须改为条款判定，不能把新维护动作继续挂到统一正惩罚上。
- `W/K/A` 不成为第五类结局主体，只经实际状态进入 [weighted_endings.go](../../internal/service/weighted_endings.go)。
- 当前仲裁没有法治候选，需新增 `RULE_OF_LAW`：`covenant_locked=true` 只是该候选的资格条件，不是自动胜利；最终仍由玩家、驻地派系、具名人物和上层控制方 加权选择，Safeguard 等硬失败优先。
- 观察、条款、事实、动作和附着按稳定 ID 排序；获取与暴露判定使用既有单 RNG 流，其余公式不消耗 RNG。
- 存档包含 `B/π`、Protocol believed/true 版本、偏离与 review、`RelicItem/H_channel/reflection_key/dialogue_id/utterance_id`、`G/J/E/Q/W/K/R_op/R_s/A/regime/mayor_id/covenant_locked/计数器/配置版本`。

## 11. 总验收与冲突结论

1. IT 联盟只有法警和 IT 内部；Police、Mayor 幕僚、技术骨干没有收买字段或动作。
2. 唯一直接日常泄漏是 IT 主任调用法警；其他动作只能经二次法警收场间接暴露。
3. Protocol 是常态信息源，三类偏离分别判定，上层控制方 介入稀有、确定、可预警。
4. 学徒与主任的上层控制方 认知不同；Relic、Protocol 参悟和 控制通道 对话均可重复生成但不能刷同一观察，玩家能间接制造条件且不能解锁反上层控制方。
5. 矿工结构性不采样，普通怀疑按五因子计算，IT 触 Protocol 直接进入偏离；AP 与怀疑独立。
6. 玩家可通过少量有效操作加速 `W` 崩塌，IT 反击随资源下降衰减；covenant 路线有明确 `TODO(balance)` 实测目标。
7. 新设计**没有推翻 S 曲线与三方附着公式**：Protocol 改的是 `W/R_s/J` 的输入和 IT 行为语义，Mayor/covenant 两档钥匙保持不变。
8. 真正需要替换的旧实现是“所有 IT 行动统一加 Safeguard 风险”；现有仲裁也需新增以 `covenant_locked` 为资格的 `RULE_OF_LAW` 候选。其他冲突均来自旧稿错误表述，已删除，不是目标机制之间不可调和。
