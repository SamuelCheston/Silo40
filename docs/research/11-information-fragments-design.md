# Silo40 信息碎片：共享视角模板、证据组合与有限 LLM 变体

> 日期：2026-11-14
> 性质：内容与机制设计，不包含代码改动。
> 范围：常规地堡共享的信息碎片；不为每座地堡单写一套，不把 固定时间线场景 正典人物命运改造成随机碎片。
> 目标：让玩家获得碎片时立刻读到有来源、有立场、有后续用途的内容，并使同一内容骨架能在不同局中产生安全的表层变化。

## 0. 阅读约定与最终结论

- **【现状事实】**：已在当前仓库核实的行为。
- **【设计提案】**：本文新增方案，不声称已经实现。
- **【文案示例】**：用于说明写法的原创内容，不是对外部剧情事实的追加断言。

核心结论：

1. 碎片不是“真相 ID”，而是一次有来源的 **Observation**。底层分为 `Fact`（事实骨架）、`Version`（对事实的解释）和 `Observation`（某观察者经某渠道得到的材料）。拥有材料不等于事实为真，事实确信也不等于某一种归因成立。
2. 共享预写库按 **9 个常规部门 × 3 个信息源层级 × 6 个主题 = 162 份视角模板**估算，不乘地堡数量。当前 28 个 ID 先做可读化改造，再扩到 54 份垂直切片，最后才需要补满 162 份。
3. 视角差完全由预写承担。LLM 只把同一份模板改写成不同局中“相似但不同”的表述，不能生成事实、人名、时间、因果、法律条款、证据强度或碎片关系。
4. LLM 在**每局首次获得某块碎片时生成一次，最终文本随该 Observation 入库存档**；之后查看只读存档，绝不每次重算。失败或质量不达标直接使用预写原文，获取与 gameplay 结算不受影响。
5. 可组合证据、互斥立场、NPC 质询、随确信度增加的验证信息，**全部可以纯预写实现**。必须靠 AI 的只有“玩家自由提问并理解任意措辞”或“自由组合任意文本后推断新事实”；这两条均不建议进入近期范围。
6. 最优先不是上 LLM，而是把当前 28 个 ID 变成“标题 + 正文 + 来源 + 指向”的可读卡片。LLM 改善的是重复开局的新鲜度，不解决第一局“拿到了但不知道是什么”的问题。

## 2. 内容模型：事实、解释、观察必须分开

### 2.1 三层对象

```text
Fact：发生了什么
  └─ Version：为什么会发生、谁应负责（可互斥）
       └─ Observation：谁在哪、经什么渠道、以什么口吻看到了哪一部分
            └─ Belief：某个玩家/群体目前有多相信事实与各版本
```

同一个 `Fact` 可以被多个部门、多个层级观察；同一个 `Observation` 可以强力支持“事情发生”，却只弱力支持“IT 主导”。这与 10 篇的 `B/π` 分离一致。

### 2.2 字段设计

| 对象 | 字段 | 含义与锁定规则 |
| --- | --- | --- |
| `Fact` | `fact_id` | 稳定语义 ID，不使用 Mayor_4 这类展示编号作为真相真源。 |
| | `canonical_event_key` | 指向实际事件或原创历史事实；事件已发生的时间从权威状态绑定，不能由文案猜。 |
| | `subject/object/location_scope` | 涉及部门、人物或设施及作用范围；固定时间线场景 正典人物只能引用权威链状态。 |
| | `occurred_at` | 实际发生时间或明确的历史时间区间；实例化后锁定。 |
| | `causal_edges` | 已确认的因果来源与后果；未知动机不得写成事实。 |
| | `content_version/source_ref` | 内容版本与项目内来源；公开库只登记原创机制与原创文案。 |
| | `qE/qP` | 未来进入 `E/Q` 的事实级权重；集中在事实注册表，不复制到每份文案。 |
| `Version` | `version_id/mutex_group` | 例如“必要安全措施 / 例行处置 / 蓄意隐瞒”可互斥；事实本身不在此层争真假。 |
| | `claim_causality/claim_actor` | 该版本主张的因果与责任，不等于权威事实。 |
| | `stance/attribution_to_IT` | 叙事立场及未来 `a_e,v` 归因参数。 |
| | `likelihood_by_channel` | 不同材料对各版本的支持程度，供未来 `π` 更新。 |
| `FragmentTemplate` | `template_id` | 共享模板 ID，不含 silo ID；现有 28 个字符串保留为兼容 alias。 |
| | `fact_id/version_id` | 明确这份材料陈述什么、采用哪个解释。 |
| | `department/tier/theme` | 三个正交分类维度，见 §3。 |
| | `observation/interpretation/blind_spot` | 作者验收字段：直接看到什么、如何解释、不知道什么；防止“同段换皮”。 |
| | `channel/document_form` | 传闻、签署证词、维修单、库存记录、正式档案、实物等。 |
| | `title/body_template/locked_claims` | 预写正文及不可改写的事实锚点。 |
| | `allowed_details` | 允许 LLM 选择并改写的非事实性细节池，例如纸张受潮、楼梯噪声；不得包含新事件。 |
| | `base_reliability/independence_key` | 渠道基础可靠性与独立来源分组；同一来源转述不能刷高确信。 |
| | `related_fact_ids/next_leads` | 与哪些事实咬合、下一步适合找什么渠道；只给方向，不直接剧透答案。 |
| | `legal_refs` | 指向 Covenant/Protocol/Directive 的条款 ID，不在正文里自由编造条号。 |
| | `evidence_form` | 私人猜疑、匿名传闻、公开证词、未核验记录、原始档案等；是否真正成为公开证据仍取决于发布与核验。 |
| `Observation` | `observation_id` | 一次获取的唯一 ID，也是未来观察去重键；重复查看不新建。 |
| | `template_id/silo_id/observer_id` | 共享模板在本局、本堡、本观察者下的实例化。 |
| | `acquired_at/acquisition_event_id` | 何时、由哪个行动或事件获得。 |
| | `source_role/source_location/channel` | 本局实际来源；没有权威楼层时只显示部门或 zone，不虚构地点。 |
| | `base_text/final_text` | 预写原文永远保留；`final_text` 是玩家实际看到的预写或 LLM 版本。 |
| | `render_status/model/prompt_hash/content_hash` | `prewritten/generated/fallback`、模型与模板审计信息；模型变化不改旧档文本。 |
| `BeliefState` | `observer/fact/B/π/observation_ids` | 连续确信、版本分布和已结算观察；不属于正文，不允许 LLM 修改。 |
| `EvidenceCase` | `fact/observations/legal_ref/actor_link` | 可组合证据的结构化引用，不复制正文。 |
| | `public_provenance/public_coverage` | 发布渠道、可核验性与实际受众覆盖；玩家私下 `B` 高不能替代它们。 |

**最小实现不必一次建齐所有表。** 第一阶段只需要 `FragmentTemplate + Observation` 的只读展示子集；`BeliefState/EvidenceCase` 随对应机制落地，避免先造一套没有消费方的数据结构。

## 3. 纯预写方案：162 份共享模板，而不是“堡数 × 部门数”

### 3.1 规模数字

常规部门使用当前九类：Mayor、Judicial、IT、Police、Medical、Supply、Mechanical、Mines、Agricultural。

信息源层级不是 `ELITE/COMMONER`，也不是 Upper/Mid/Lower 楼层，而是：

1. **基层**：直接操作、目击、搬运、维修后留下的物理或口述材料。
2. **中层**：调度、审核、库存、异常单、跨部门流转记录。
3. **决策层**：命令、正式批复、继承安排、保密档案及其自我辩护。

六个主题：

| 主题 | 主要素材 | 对应研究/现有内容 |
| --- | --- | --- |
| 资源与基础设施 | 电力、水、食物、矿、维修、泵、供应链 | 现有资源、事故与维修事件 |
| 高危处置与外部 | 高危处置判决、传感设备、防护装备、外部信号 | 现有高危处置与外部信号机制 |
| Covenant 与执法 | 公开约章、禁令、继承、Judicial/Police 权限 | 现有执法与门控机制 |
| 档案与历史清洗 | 广播、目录抹除、档案打捞、历史包袱、民间记忆 | 现有档案与历史类事件 |
| IT 控制与继承 | 监控、记录、幕后命令、Mayor/Judicial 关系、继任安排 | 10 篇的抽象权力机制 |
| 控制网络与 Safeguard | 上层控制方、断联、跨堡信号、终止与抽象反制 | 现有跨堡事件与硬失败机制 |

因此完整共享库为：

```text
9 departments × 3 tiers × 6 themes = 162 templates
```

这里的 162 是**视角呈现模板数**，不是 162 条互不相干的世界真相。建议用约 18–24 个 `Fact` 和若干互斥 `Version` 支撑它们，让多份材料围绕同一事实咬合。

### 3.2 分批规模与真实文案量

每份正文建议 **120–180 个汉字**，另配 20–40 字来源说明；不依赖插画，使用纸张、印章、维修单、终端日志等排版语义即可。

| 批次 | 模板数 | 正文字数 | 文案与交叉审校工作量估算 |
| --- | ---: | ---: | --- |
| 当前 ID 可读化 | 28 | 3,360–5,040 字 | 约 13–20 人时 |
| 垂直切片：九部门 × 三层级 × 先写 2 个主题 | 54 | 6,480–9,720 字 | 约 24–35 人时 |
| 完整共享库 | 162 | 19,440–29,160 字 | 约 62–93 人时 |

估算按每份成稿、事实核对、视角去重和一轮审校合计 20–30 分钟，再加共享事实/条款注册表工作量；不含程序实现、playtest 返工和 NPC 质询文案。若增加第二套全量预写变体，变量文本工作量近似再增加一倍，因此不作为默认方案。

### 3.3 一份模板怎样分发到各地堡

- 模板只描述**同构制度下的视角与事实骨架**，不写死“这是某堡特有的事件”。
- 获得时实例化 `silo_id、occurred_at、acquired_at、source_location、acquisition_event_id`；这些来自当局状态，不是随机装饰。
- 同一模板在同一观察者 × 地堡内只发一次。重复调查同一材料只追加观察记录或提示已知，不生成一张换皮新卡；跨堡再次获得则属于另一 Observation。
- 不同地堡可以使用同一模板，因为它们的部门、禁令和技术结构相同；本设计不承诺每座地堡都有独特历史。
- 无 AI 时，同一模板跨局正文相同，这是预写方案的真实边界。它能保证同一局不重复发卡和视角差，不能保证跨局措辞新鲜。
- 有 AI 时，每局只改写表层变量文本；事实锚点相同，来源细节和语气可不同。见 §5。
- 固定时间线场景 正典节点与具名人物状态只能由权威链提供，不通过共享模板随机生成生死或事件结果。Archives 若以后开放碎片获取，可少量增加专属模板，但不反向扩张常规库。

### 3.4 视角差的验收方式：不是换称呼，而是换证据

同一“IT 执行第二次档案清洗”的事实，可写成以下四种材料。以下为【文案示例】，具体时间应由实际事件绑定。

| 来源 | 正文示例 | 可靠性与盲点 |
| --- | --- | --- |
| Mines / 基层 / 传闻 | 一张没烧净的目录页跟着废纸包到了矿层。搬运工只认得页脚的“二次清理”，他说上面的名字早被撕走了。大家传的是 IT 在灭证，可这页纸只能证明有东西被送去烧。 | 对“清洗发生”支持弱，对“灭证动机”支持更弱；不知道命令链。 |
| Supply / 中层 / 库存异常单 | 三只封档箱被改记为受污染纸张，出库签收完整，箱内清单却被整页抽走。改记发生在 IT 清洗令当日，经手人没有权限查看原目录。 | 能核验物流和时间，不能仅凭改记证明谁下令。 |
| Mayor / 决策层 / 事后通知 | 通知把删除目录解释为档案霉变处置，并要求市长办公室补签紧急许可。附件没有删除条目，也没有 IT 的原始指令；正式口径与执行记录在此断开。 | 能证明官方解释和补签程序，不能直接证明实际删除范围。 |
| IT / 决策层 / 删除队列 | 队列列明第二批目录、执行时间与保留镜像的位置。备注要求“先移除索引，再处理副本”。它能证明执行方式，但“为了防止恐慌”的备注仍是命令方的自我解释。 | 对事件和内部流程可靠；动机存在立场，镜像位置成为下一线索。 |

四份材料必须具有不同的 `observation、interpretation、blind_spot、document_form、next_leads`。只把“我听说”替换成“经查明”，或把矿工称谓换成 Mayor，不算新视角。

## 4. 呈现设计：先是一份可读档案，再是一套推理工具

### 4.1 获得时与库存中的卡片

**获得时**不再只弹 `Gathered intel on Mayor_4`，而是出现一张可稍后关闭、可从档案重开的卡：

```text
[档案清洗] 被抽走的出库清单
Supply · 中层记录 · 原始单据
正文 120–180 字

来源：本驻地 Supply 异常库存单 · Y124 M2 获得
材料可靠性：较高；对“IT 蓄意灭证”的支持：有限
指向：IT 删除队列；Mayor 的事后许可

[已归档] [查看关联 2] [以后：拿去质询]
```

库存默认按 `Fact/主题` 分组，不按字母 ID 排序；每份卡保留原 ID 作为档案编号。列表显示标题、部门、层级、来源类型、未读状态与关联数量。连续 `B/π` 未实现前，不显示伪造的确信百分比，只显示材料本身的来源与可靠性。

### 4.2 方向 A：碎片作为可组合证据——推荐，纯预写可做到

采用固定三槽，而不是自由拼图板：

1. **发生**：至少两个不同 `independence_key` 的 Observation 支持同一 `Fact`。
2. **责任**：加入能连接行为者与某 `Version` 的材料。
3. **违法/违约**：加入适用 `legal_ref`，并满足公开核验条件。

组合结果是从注册表查出的 `EvidenceCase`，不是模型临时编出的新事实。UI 用三行槽位与缺失条件即可，不需要复杂节点图、连线物理或美术资产。

- 实现复杂度：中；需要事实/来源注册表与组合校验。
- 与现有机制：无根本冲突，但必须等 `B/π` 与公开证据机制落地后才能影响 `E/Q`。
- 体验收益：高；碎片从收集计数变成调查路线。
- 限制：同一来源反复转述不能组合；组合不消耗原碎片；高 `B` 不自动证明 IT 责任。

### 4.3 方向 B：同一事实存在互斥版本——推荐，纯预写可做到

同一 `Fact` 下并列“安全措施 / 例行处置 / 蓄意隐瞒”等 `Version`。不同部门材料不仅措辞不同，还提供不同 likelihood，使玩家的 `π` 发生变化。

- 实现复杂度：中；内容预写不难，难点是版本更新和 UI 不把立场误显为客观真相。
- 与现有机制：正好接入 10 篇的 `B/π`；当前字符串集合无法表达，需要增量状态。
- 体验收益：高；玩家判断“信谁”有实际依据，而非选一段更好听的文本。
- 限制：不能安排一个隐藏的“官方永远假、底层永远真”快捷键；每个渠道都有可靠与自欺的时候。

### 4.4 方向 C：把碎片拿去质询 NPC——后置，纯预写可做到

质询结果由 `fragment theme/legal_ref + NPC department/tier + knowledge access + stance + relation` 查规则生成：确认、否认、回避、认出条款、提供新线索、反向怀疑玩家。AI 可以自由改写反应口吻，但不是必需。

- 实现复杂度：中高；当前没有对话入口，普通快照还裁掉完整 residents，必须先确定可质询的真实 NPC 与权限。
- 与现有机制：无直接冲突；反应必须作为新 Observation 记录，不能反复问同一 NPC 刷 `B`。
- 体验收益：中高；NPC 的回避和措辞本身成为信息，部门立场更可感。
- 成本：可用约 135 条短反应覆盖九部门 × 三层级 × 五类反应，额外约 11–23 人时文案；不需要逐碎片各写九套。
- 限制：否认不自动降低事实 `B`；同一 NPC 对同一 Observation 只结算一次；自由文本提问才需要 AI 理解，不在近期范围。

### 4.5 方向 D：文字随确信度变化——改形式，不重写原材料

不推荐让同一张已获得卡从“模糊传闻”原地变成“清晰记录”。物理档案不会因为玩家更相信它而换字，也会破坏存档与讨论时的共同参照。

推荐做法：

- `base_text/final_text` 永远保留，表示当时获得了什么。
- 低 `B` 时附加预写批注：“一条尚未交叉验证的说法”。
- 中 `B` 时显示：“多项材料支持事情发生，解释仍有分歧”。
- 高 `B` 时追加新的验证记录、独立来源和更清晰的事实摘要；若 `π` 仍分散，明确写“发生较确定，责任未确定”。

这仍然给玩家“越查越清晰”的反馈，但清晰来自**新 Observation 与验证批注**，不是篡改旧文本。三档批注全部可预写，复杂度低中，体验收益中高。

### 4.6 哪些事情必须靠 AI

| 能力 | 纯预写 | 必须 AI | 本文选择 |
| --- | --- | --- | --- |
| 有分量的正文、部门/层级视角、互斥版本 | 可以 | 不需要 | 预写 |
| 证据槽组合、条款匹配、来源去重 | 可以 | 不需要 | 预写规则 |
| 固定选项质询与 NPC 反应 | 可以 | 不需要 | 预写规则 |
| 确信度批注与新增验证记录 | 可以 | 不需要 | 预写分层 |
| 同一模板跨局换语气、措辞和有限细节 | 只能预先写多套 | 动态无限变体需要 AI | 有限 LLM 变体 |
| 玩家任意措辞提问并被理解 | 极难覆盖 | 需要 | 不做 |
| 任意文本自由组合后产生新事实 | 无法穷举 | 需要，且难保证可靠 | 不做 |

## 5. LLM 方案：只做有边界的表层变体

### 5.1 可以与不可以交给模型的部分

**可以生成**：句式、语气、叙述顺序、开场与收尾、来自 `allowed_details` 的感官细节、同一观点的非事实性修辞。

**必须锁死**：`Fact/Version` 的全部语义、人名与实体、时间与数字、因果方向、法律条款、来源类型、可靠性、`independence_key`、关联碎片、证据资格、`B/π/E/Q` 及任何 gameplay 状态。

推荐使用带占位符的受限渲染，而非把世界观一丢让模型自由写：

```text
{{SOURCE_OPENING}}
{{LOCKED_CLAIM_1}}
{{ALLOWED_DETAIL}}
{{LOCKED_CLAIM_2}}
{{SOURCE_CLOSE}}
```

模型只能填写变量槽；锁定段在生成后原样展开。`allowed_details` 也只能从该模板预写的细节池选择和改写。这样“换例子”换的是纸张、楼梯、机器声响等 presentation detail，不是新增一起事故或一个新人物。

### 5.2 变体质量判据

1. **事实保真**：锁定占位符恰好出现一次且顺序正确；变量槽不得引入新数字、日期、人名、部门、条款、因果断言或证据结论。
2. **结构合法**：只返回约定槽位，长度在预算内；缺字段、额外字段、Markdown 代码块或解释性前言均拒绝。
3. **视角不变**：变量文本不能改变 `observation/interpretation/blind_spot`，不能把传闻改成亲见，也不能把他人命令改成自己命令。
4. **同局新鲜度**：排除锁定段后，与已生成卡的变量文本计算字符 4-gram Jaccard；建议初始门槛 `<0.45`。开头 8 字不得与其他卡完全相同，同一 `detail_id` 不得在同部门同主题中重复使用。
5. **模子检测**：连续重复相同开场、相同三段式连接词、相同收尾警句均判失败；不同部门不得只替换称谓。
6. **人工抽检**：自动阈值只是初筛，不是语义正确的数学证明。首批至少按部门 × 层级抽样审读，确认没有“安全地生成了一堆同样腔调”。

同局新鲜度由“唯一模板 + 最近文本指纹 + detail 去重 + 失败回退”共同保证。完全相同的卡片可通过规则禁止；“明显同模”需要上述阈值与人工抽检共同控制，不能只靠提示词承诺。

### 5.3 生成时机与存档

选择：**每局首次获得时生成一次，最终文本随 Observation 存档；查看时不重算。**

流程：

1. 权威引擎先确定 `observation_id/template_id/fact/version/source`，写入预写 `base_text`，完成原有 gameplay 结算。
2. 文本渲染器在显示前请求一次 LLM；请求不接触 RNG，不改变获取、分享或结局状态。
3. 校验通过后把 `final_text/model/prompt_hash/content_hash` 写回该 Observation。
4. 超时、请求失败或校验失败则把预写原文作为 `final_text`，记录 `fallback` 原因。
5. 以后打开、读档、换模型都只读 `final_text`，不重新生成。

若生成中崩溃，已落库的预写实例仍可恢复；未完成的生成任务恢复时标记 fallback，避免反复调用或丢失碎片。开局自带碎片在创建初始 Observation 时走同一流程并计入 `A`。不同存档、不同模型可以表述不同，但共享相同事实锚点；同一存档永远读同一最终文本。

### 5.4 同局一致与矛盾控制

- 所有卡引用同一个 `fact_id/version_id` 注册表；相互补充的事实由作者预先确定。
- 锁定段逐字一致，模型没有权限写出相反时间、人物或责任链。
- 新 Observation 更新 `B/π` 的逻辑只读结构化字段，绝不阅读生成正文。
- 生成时携带本局已用开场、文本指纹和 `detail_id` 作为排除项，不携带玩家未知道的其他秘密。
- 重试最多一次，并带上“避免这些表达”的指纹列表；仍失败就回退，而不是无限生成直到碰巧合格。

### 5.5 成本重算：只乘每局实际获得量

设 `A` 为本局玩家实际取得的 Observation 数，每块最多生成一次、失败重试一次；重复查看不增加调用，仅把模板分发到某地堡也不生成。若玩家在多个地堡实际取得同一模板，则每个地堡的 Observation 分别生成并计入 `A`。当前常规单驻地局的 28 个 ID 全收集只有 `A=28`。未来库扩到 162 份也不意味着一局获得 162 份，另列 `A=36` 仅作预算情形。

假设每次尝试输入 800–1,200 tokens、输出 180–280 tokens；为便于计算，采用**纯示例价格**输入 ¥2/百万 tokens、输出 ¥8/百万 tokens，不指向任何供应商报价。按平均 20% 额外重试，即 `r=1.2`：

```text
单次成功生成成本 = input_tokens × 2 / 1,000,000
                 + output_tokens × 8 / 1,000,000
                 = ¥0.00304–0.00464

每块获得预算 = r × 单次成本 = ¥0.00365–0.00557
每局预算 = A × 每块获得预算
```

| 每局实际获得 `A` | 托管模型估算成本 | 最多调用次数（含一次重试） |
| ---: | ---: | ---: |
| 20 | ¥0.073–0.111 | 40 |
| 28（当前全收集上限） | ¥0.102–0.156 | 56 |
| 36（未来预算情形） | ¥0.131–0.200 | 72 |

以上不含既有 LLM NPC 决策成本，也不含硬件、电费与部署成本。本地模型没有按 token 的边际账单，但仍有相同调用次数与延迟；具体吞吐应实测，不在本文编造。查看已生成碎片的成本恒为 0。若价格不同，直接替换公式中的单价，不改变调用量结论。

### 5.6 退化路径

- 模型未配置、超时、网络失败、schema 错误、事实锚点变化、相似度过高：使用 `base_text`。
- 第一次失败后允许带排除指纹重试一次；第二次失败直接 fallback，不阻塞行动。
- 预写原文本身必须是完整可读的成品，不是“等待 AI 补全”的半成品。
- 玩家看到的是正常档案卡，无需错误弹窗；`render_status=fallback` 与原因进审计日志。
- LLM 开关只影响文本表层，不影响 `KnownFragments`、AP、怀疑、RNG、`B/π/E/Q`、存档恢复或结局。

## 6. 与现有及既定机制的衔接

### 6.1 连续确信度 `B` 与版本 `π`

- `Observation` 是未来 noisy-OR 更新的输入，`base_reliability/independence_key` 决定证据强度与重复折扣。
- 卡片正文是观察材料的呈现，不是 `B` 的存储位置；同一 `observation_id` 只结算一次。
- 高 `B` 只表示“事实发生较可信”；责任归属仍由 `π` 和材料 likelihood 决定。
- 第一阶段没有 `B/π` 时只展示来源类型和基础可靠性，不提前显示虚假的连续确信。

### 6.2 部门分层

- 现有 `KnownFragments` 继续承担拥有与计数；未来部门 × 阶层的 `BeliefState` 另行保存。
- 预写模板的 `tier` 是信息源层级，不等同于部门 `ClassType`，也不伪造当前人口里不存在的具体 NPC。
- 分享时传递结构化 Observation 及其版本 likelihood；不能只把一段 LLM 文本交给接收方重新理解。
- 玩家私下获得不会自动改变部门或阶层 belief，仍必须经过分享/公开。

### 6.3 Covenant / Protocol / Directive 条款

必须区分三类材料，不能统称“Protocol 条款”：

- **Covenant**：堡内公开规则，普通居民可能知道梗概，正式条款可成为公开法律依据。
- **Protocol**：处置与应急手册，知识访问受限；片段可以说明应当怎样处置，但持有它不等于已经发生违法。
- **Directive / Safeguard 材料**：更高层级的终止机制信息，访问与公开核验更严格。

每个 `legal_ref` 包含 `document/clause_id/applicability/public_access/source_version`。证据组合遵循“事实 + 责任 + 适用条款”，条款本身不替代事实。条款注册表只保存项目原创机制文本，不拼接外部来源或搬运长段原文。

### 6.4 阴谋曝光 `E` 与公开证据 `Q`

```text
获得 Observation → 玩家 B/π
分享/公开 → 部门×阶层及具名人物 B/π
部门 belief → conspiracy_exposure E
Judicial 可核验公开材料 + 覆盖 → Q
```

- `E` 只读受众 belief，不存在 `E += player_B`，也不能因 LLM 文案更有说服力而增加。
- 普通事故、档案清洗或传闻不自动形成“IT 幕后掌权”归因；该版本必须连接到 **IT 主任直接调度 Judicial 法警的证据链**。只读到 Protocol 也不足以证明当前 IT 正在操纵 Judicial。
- `Q` 还受 `public_provenance/public_coverage` 约束；私人档案、传闻和 LLM 修辞不能绕过公开核验。
- 同一 `Fact` 的重复材料不重复扣威势；`qE/qP` 在事实层去重。
- 本文的 `E` 是阴谋曝光，与驻地/上层控制方 秘密行动的 `operation_exposure` 完全分开，UI 和存档都不得混用。

### 6.5 当前获取、分享、INFORMATION 与确定性

- 第一阶段保留 28 个 ID、`GATHER_INFO` 随机取未知、分享接受率、unexplained knowledge、全部门 ≥5 的 INFORMATION 条件。
- 内容扩展只增加模板与展示，不暗中调整碎片概率、获取顺序、AP 或结局。
- LLM 不消费 gameplay RNG，不把模型输出作为模拟输入；同种子模拟 parity 不受文本开关影响。
- 文本存档与事实存档分开审计；旧 ID 可保留 alias，新结构不靠解析 `Mayor_4` 猜事实。

## 7. Roadmap：先让第一局有获得感，再投入重玩与推理

### R1：现有 28 个 ID 的可读化——最高优先级

- 为每个现有 ID 配标题、120–180 字正文、来源、主题、可靠性说明和 1–2 条关联线索。
- 获得结果可打开完整卡片，身份 Tooltip 与情报档案都能重读。
- 不改获取、分享、计数、AP、RNG 或结局，不显示尚未实现的 `B/π/E/Q`。
- **收益**：第一局立即从“获得 Mayor_4”变成“读到一份有出处、能指引下一步的材料”。
- **不依赖 LLM**，是后续所有方案的质量地板。

### R2：共享事实注册表与 54 份垂直切片

- 先选“档案与历史清洗、Covenant 与执法”两个主题，完成九部门 × 三层级 = 54 份。
- 把 `Fact/Version/Observation` 和关联线索落实到内容注册表，跑视角去重与事实一致性审校。
- 先做静态关联与“还缺什么材料”的提示，不急着上自由证据板。
- 只有 playtest 证明玩家愿意读、愿意追线索后，才扩到其余四主题和完整 162 份。

### R3：可选 LLM 表层变体——改善重玩，不救内容

- 在 R1/R2 预写成稿后接入受限槽位生成、一次重试、相似度去重、原文 fallback 与最终文本存档。
- 验收同一存档查看零调用、不同局只变表层、同局无明显复写腔、off/on gameplay 状态一致。
- 若预算或质量不达标，永久使用预写也不会损失任何机制。

### R4：`B/π`、验证批注与分层 belief

- 依赖 10 篇 roadmap 的碎片获取与连续确信步骤，先实现观察去重和版本更新，再显示确信批注。
- 保持原材料不变，以新 Observation 和验证批注呈现“越查越清晰”。
- 玩家私人 `B` 仍不直接写 `E/Q`。

### R5：固定槽证据组合、条款引用与 `E/Q`

- 实现发生/责任/条款三槽、独立来源校验、公开 provenance 与覆盖。
- 接入部门 × 阶层 belief、阴谋曝光 `E` 和 Judicial 公开证据 `Q`；再与 10 篇的 `W/Judicial` 路线汇合。
- 没有这些上游机制前，不提前提供会假装产生法律后果的“公开”按钮。

### R6：NPC 质询

- 先补真实可质询 NPC 的只读入口，再接固定反应规则、反应 Observation 与去重。
- 先九部门 × 三层级 × 五类反应的短文案，不做自由聊天。
- LLM 可复用 R3 做口吻变体，但不是成立条件。

## 8. 验收标准

1. 当前 28 个 ID 都能读到标题、完整正文、来源与至少一条有效关联，不出现只有 ID 的空卡。
2. 同一事实的矿工、中层、Mayor、IT 材料在直接观察、解释、盲点、证据形式上至少三项不同，不是同段换皮。
3. 162 份规模不含地堡乘数；同一模板在不同堡只实例化权威来源和时间，不复制内容文件。
4. 预写模式下所有卡片完整可读；LLM off 不影响任何玩法路径。
5. LLM on 时同一 Observation 只生成一次最终文本，查看与读档零调用；失败重试至多一次，fallback 不阻塞获得。
6. 任意模型输出均不能修改事实锚点、人名、时间、因果、条款、关联和 `B/π/E/Q`；变量文本通过同局相似度与细节去重。
7. 旧文本不会因 `B` 增加而被重写；高事实确信与低 IT 归因可以同时成立。
8. 证据组合拒绝同一 `independence_key` 刷数，玩家私下高 `B` 不直接增加 `E/Q`，条款不替代事实。
9. `conspiracy_exposure E` 与现有 operation `Exposure` 在字段、UI 和公式中都可区分。
10. LLM off/on、生成成功/fallback 的 gameplay 同种子轨迹一致；文本变化不消费 RNG，不进入模拟公式。

## 9. 明确不做

- 不为每座地堡复制一套部门 × 层级 × 主题文本。
- 不让 LLM 自由发明事实、人物、日期、条款、证据关系或 NPC 生死。
- 不在每次查看时重新生成，不用“同模型同 seed”代替最终文本入档。
- 不用 AI 弥补预写正文尚未完成的问题，也不把模型互评当作绝对事实保证。
- 不做自由文本质询、自由文本证据推理或复杂拼图棋盘。
- 不因确信度变化篡改原材料，不把否认自动当作反证。
- 不把 Covenant、Protocol、Directive 混成一本手册，不把 operation Exposure 与阴谋曝光 `E` 合并。
- 不在第一阶段修改现有获取概率、分享接受率、INFORMATION 计数、固定时间线场景 正典链或结局语义。
