# Silo40 准备度→成果换算机制设计：逃跑与外溢

> 范围：玩家在逃跑（《越岭》路线）或外溢（《共证》评分项）之前的准备投入，如何换算为终局实际成果。
> 本轮边界：确定准备度的量化口径、投入→产出的换算结构、失败与部分成功分级、与既有仲裁的接口和实现切入点。凡需平衡校准的阈值一律标 `TODO(balance)`，不给平衡数值。

> **【用户裁决 · 2026-11-15，本册前提，醒目】**
> **裁决一**：从原著看，逃跑只有一种成立路径——地堡的顶层必须齐心，最起码市长和 IT 要达成一致、都要跑。原型是书中 18 号地堡。
> **裁决二**：叛乱路线成立。镇压方——也就是 IT——镇压叛乱失败之后会转向。叛乱胜利，IT 转向，双方达成一致，逃离才成立。这道组织门不是开局就必须满足的静态条件，而是可以被叛乱创造出来的时序条件：先有胜负，再有转向，最后有一致。
> 两条裁决落实为本册的**顶层立场**（§3.2）：市长与 IT 的立场是逃离的唯一组织前提；准备项相应从"决定成不成"降为"决定成得多好"。后续裁决把立场定案为**三档**（"都要跑"＝都不阻挠别人跑：阻挠/不阻挠/配合），用**带权重的随机决策**表达（种子随档、可复现），市长有镇压/谈判/妥协三条路，外溢重定位为逃跑失败后的退路（§3.5）。**最终裁决（F）把门降为结果层**：配合与否不是玩家按钮、也不是显式判定闸，立场只通过影响实际能带走多少人来体现，**结算只看逃出人数**，阻挠即人数 0。受影响小节均标注"裁决更新"；凡会改变结局资格口径、需要用户拍板的判断，集中在 §3.2 末尾的【待裁决】清单，本册不代为决定。

- **【原著可支撑】**：本地研究资料能由小说三部曲支撑的事实或母题。
- **【项目外推】**：为 Silo40 新增的规则，不冒充原著事实。
- **【用户指定】**：本轮明确要求，必须作为设计约束采用。
- **【用户裁决】**：2026-11-15 两条裁决（卷首誊录），是高于本册早期口径的约束；与之冲突的早期表述已按裁决重排。

## 1. 命题与总判断

**命题**【用户指定】：在逃跑之前、或者外溢之前，准备了防护服多少套？应急预案做到多到位？用这类前期投入，换算最后逃跑或外溢的实际成果。成果不是一个成功率数字，而是分侧面的事实：能带走多少人、路上活下来多少、出去之后能不能维持、外溢能触及几个堡、被追踪到的风险有多大。

**总判断（推荐方案）**：准备度是**事实账本**，不是成功率系数。逃跑与外溢各挂一本准备账本；终局结算时，账本经**容量门 + 侧面结算**产出结果事实，写入既有的逃出群体状态（`EscapedGroup`）与出站信号日志（`OutboundSignals`）；结局仲裁照旧只读事实，不读账本。其中**"成不成"不由任何显式门投票，由逃出人数自然结算**【用户裁决 F】：市长与 IT 的立场（阻挠/不阻挠/配合）是影响人数的成因层，不是玩家按钮、也不是判定闸；阻挠则人数趋 0，配合则带走更多（§3.2）。外溢重定位为逃跑失败后的退路，不是并行的第二套准备（§3.5）。

三条理由，也是拒绝"单一总系数"的根据（详见 §3.1）：

1. **资格先于加权**【现状，结局体系 12 §2.2】：《越岭》资格读的是"逃出群体存续"这一事实。准备度若做成一个进加权的总系数，等于让准备度成为第五类投票主体，违反"不成为独立贡献者"的既有纪律（12 §7.5）。正确形态是：准备度塑造事实（走了多少人、活了多少、能不能维持），仲裁读事实。
2. **失败模式结构不同**：防护服不够是路上损耗，补给不够是落地即散，信道太多是被追踪。单一系数只能说"整体更成/更不成"，说不出"败在哪一面"；而仲裁、尾声与三线交叉全部要求分侧面的事实。
3. **跨线耦合需要独立接口**：逃跑会带走宿主的复制者与开放人口（拆《共证》《无人裁决》），外溢会暴露宿主（威胁全部本地线）。只有多侧面模型能表达这些权衡；单一系数必然重复计分或漏计。

**明确不做**：不新增结局类型；不让准备度直接进胜负判定；不做概率摇骰（项目要求同种子逐字节复现，结算必须是账本＋事实的确定性函数）；不让准备度随月份被动积累（阶段推进必须由玩家实际动作触发）。

## 2. 准备度怎么量化

准备度分两类：**可数实物**（整数或带单位的量，获取即有机会成本）与**程度事实**（0–1 或分档，必须由具体动作/事件生产）。逐项说明当前项目里哪些已有状态可挂、哪些需要新建。

### 2.1 逃跑准备：可数实物

| 项 | 性质 | 现状可挂 | 是否新建 | 来源与世界观约束 |
| --- | --- | --- | --- | --- |
| 可用防护服（套） | 整数 | 无 | **新建** | 双来源，见 §2.4 |
| 便携补给（人·月单位） | 量 | 堡级 `Supplies` 资源 | 新建账本字段，资源侧复用 | 筹备时从 `Supplies` 划拨，划拨即扣减 |
| 装备材料与生产起点载体（单位） | 量 | 堡级 `Materials` 资源 | 新建账本字段，资源侧复用 | 筹备时从 `Materials` 划拨 |
| 路线事实（分段） | 分档布尔 | 完成键体系 | 不新建 | 《越岭》链已设计：`route_survey_step` → `route_confirmed` → `advance_party_report`（完好/受损） |
| 接应储备（分档） | 分档枚举 | 无 | **新建** | none / surveyed / confirmed / stocked 四档 |

**便携补给与装备的划拨语义**【项目外推】：准备不是"记账时凭空多出物资"，而是**筹备时刻真实扣减堡内资源、转入封存账本**。机会成本立即生效：划拨补给会喂大既有的 `supplies_shortage` 规则（物资短缺→恐慌），划拨材料会挤压维修与生产。这是"准备有代价"的机制投影，也防止准备度变成无成本的胜利进度条。

### 2.2 逃跑准备：程度事实

| 项 | 性质 | 现状可挂 | 是否新建 | 说明 |
| --- | --- | --- | --- | --- |
| 预案完备度 | 0–1 | 无 | **新建** | 定义为**功能位覆盖率**，不做抽象标量，见下 |
| 演练水平 | 0–1（按次累积） | 无 | **新建** | 每次演练事件 +delta；演练有可见性成本（积累筹备暴露） |
| 照护能力 | 0–1 | 无 | **新建** | Medical 对接＋医疗储备 |
| 信息掌握 | 分档事实集合 | 完成键体系 | 不新建 | 拆解为路线事实＋接应档位，不单设标量 |

**预案完备度 = 功能位覆盖率**【项目外推，推荐设计】：《越岭》剧情台阶 R-2 已经给出撤离所需的功能位清单——Mechanical（出口与设备可重复使用）、Mines（通行限制与结构影响）、Supply（多批次物资换算）、Medical（暴露风险与照护）、Agricultural（可携带食物与生产起点）、Mayor/Police（公开秩序，可争取非必须）。预案完备度不是玩家"写了一份文件"的抽象分，而是**这些功能位中有多少已经完成实质对接**（每个功能位由对应的准备动作/事件写入，权重 `TODO(balance)`）。这个口径让程度量有明确生产者、可审计、可在 UI 上显示"还缺哪个位"，避免无内容的标量积累。

**信息掌握不单设标量**【项目外推】：用户命题中的"信息掌握"在本设计中拆成两组分档事实——路线侧（已勘察/已确认/先遣往返完好或受损）与接应侧（四档）。理由：分档事实每一档都有明确的生产事件与审计痕迹；一个笼统的"信息水平"标量允许无来源积累，违背"一个键只记录事实"的内容纪律（22 分册 §2）。

### 2.3 外溢准备

| 项 | 性质 | 现状可挂 | 是否新建 | 说明 |
| --- | --- | --- | --- | --- |
| 受限信道（逐条） | 条目表：种类/目标堡/可靠度/暴露成本 | 无（投递结果已有 `OutboundSignals` 日志） | **新建**（信道建立侧） | 三种信道，见下 |
| 包裹质量（五种能力完备度） | 0–1 | 碎片体系提供材料侧 | **新建**（完备度结算） | 事实与来源/独立核验/反制方法/隐匿与交接/再传递 |
| 暴露记账 | 量 | `StationOps.Exposure`、`Silo1State.Attention` | 不新建 | 信道建立与使用累加进既有反谍轨道 |

**三种受限信道**【项目外推，与《共证》I-6 台阶一致】：

1. **IT 专线类**：借本地 IT 的受限知情层与上层控制网络的例行流量夹带。可靠度最高，暴露成本最高（直接喂 Silo 1 异常观察）。
2. **跨堡信号类**：经既有/建立的信号能力向邻堡投递。受 `Topology` 邻接约束；可靠度中等。
3. **实体交接类**：由人或物物理携带。**与逃跑的耦合点**：逃出群体可以携带包裹，但按三线交叉裁决（04-crossovers §3-B/§5），逃出者带走的材料**首先归《越岭》幸存事实**；要计入外溢，必须有显式的"再传递任务"交接动作，不能自动双算。

**包裹质量 = 五种能力完备度**【项目外推】：《共证》I-3 已定义每个传播单元必须包含的五种能力。包裹质量结算的是发包前这五类各自是否由实际材料/动作补齐（每类一个完成键或账本布尔，汇总为 0–1，权重 `TODO(balance)`）。它决定目标堡"独立接收"结算时的基准成功率（见 §3.5），不决定本地资格。

### 2.4 防护服：世界观硬约束下的双来源

【现状设定】防护服是处刑工具：IT 用劣质热封胶带让所有防护服必然失效；机械师换优质胶带才可能存活；气闸还可以用纳米虫云专门腐蚀劣质胶带（01-worldbuilding §4.2）。处刑工具的供应链本身就是 IT 的暗权（05 母题分册 §1.4）。因此防护服**不可能丰饶**，每一套可用防护服都必须有机械事实与暴露代价。

**来源一：特工预置进入层**【项目外推，接枝设定】：the Graft 的"进入层"是覆灭前外勤组实地预置的物理条件——埋藏的防护服、测绘好的传感盲区与气闸节奏；堡体相距仅数百米，但硬件随时间劣化。玩家苏醒时身份完好、进入手段可能部分失效。机制投影：

- 驻地附近存在一个**初始预置缓存**：防护服总量小（`TODO(balance)`），其中可用套数按劣化结算（种子确定的固定值或一次性判定，不做月度衰减）；
- 缓存位置与状态**必须经任务线发现**（碎片/观察/职务动作），不自动入账——发现预置缓存本身是特工剧情台阶；
- 传感盲区与气闸节奏属于路线知识，折入路线事实的"先遣"档位，不重复立字段。

**来源二：本地清洁服转化**【项目外推】：堡内清洁服总量稀缺（清洁是低频处刑，不是库存物资，`TODO(balance)`：全堡总量），且全部被 IT 做了必坏处理。转化链：

1. 取得服体：接触 IT 管控的供应链（关系/黑市/职务便利），每次获取有暴露成本；
2. 修复密封：Mechanical 关系门控下的换胶带动作（05 母题分册已预留"暗中改良防护服"动作位与"IT 审计胶带库存"反制位）；
3. **修复可被反制**：IT 审计事件可以把已修复套数打回不可用（换回劣质胶带/没收）。可用套数不是只增不减的存款。

这两条来源保证：防护服数量天然受限、获取有部门依赖（Mechanical/IT 侧）、持有有暴露风险——与"地堡封闭、外界有毒、防护装备稀缺且有既有设定"的约束完全一致。

**立场口径变化（裁决 F 更新）**：IT 立场为"不阻挠"（§3.2）时，IT 不再破坏，来源二的暴露风险下降；若立场为"配合"，IT 开清洁服库且破坏者停止破坏：可用套数 = 库存 × 完好率，不再需要逐套暗中修复，来源二的暴露成本消失。来源一（预置缓存）在立场转变前仍然有效，并可作为与顶层谈判的可行性筹码。稀缺上限不变。

### 2.5 账本通用纪律

1. **每一条账本记录必须有明确生产者**（玩家动作、内容事件），禁止月度被动积累，禁止 AP 直接兑换准备度。
2. **可数实物获取即付成本**：资源划拨即扣减、暴露即累积；程度事实有 AP 与关系/阶段门控。
3. **账本是堡级状态**，挂在 Silo 聚合下；外溢信道属于玩家驻地。
4. **空账本 = 旧行为逐位不变**：新字段零值即旧档语义，与 v9 底座的新增字段口径一致。

## 3. 投入→产出换算

### 3.1 为什么是多侧面换算，而不是单一总系数

对五个问题的正面回答：

1. **资格是事实，不是分数**。《越岭》资格 = 逃出群体存续【现状】。准备度要影响的是"这个群体长什么样"（多少人走出去、路上剩多少、落地后活不活），而不是在加权里多投一票。单一总系数只能进加权，等于把准备度做成投票主体，与 12 §7.5"不成为独立贡献者"直接冲突。
2. **部分成功是向量，不是标量**。"少带走一些／路上损耗／落地即散"是三个独立降级方向，加上硬失败共四类结局形态（§4）。任何单一数字都无法区分"带走了但路上折半"与"带走很少但全员落地"，而这两种情形在尾声叙事、三线耦合与后续模拟上完全不同。
3. **侧面内部互补、侧面之间独立**。路上存活需要防护服**也**需要路线知识：有服无路是走进致命区，有路无服同样走不出去——所以侧面内部取短板（门/乘积）；但"路上活下来"与"落地能维持"是两件事，补给充足不能替防护服挡毒——所以侧面之间不做加权平均，各自结算。单一系数必然把互补与独立混成一团。
4. **跨线耦合要求每个侧面单独可寻址**。逃出群体带走多少人，直接决定《共证》宿主失去多少复制者、《无人裁决》快照失去多少开放人口（04-crossovers §3-B）；外溢信道用几条，直接决定 Silo 1 异常观察涨多少。这些耦合点都是按侧面读的。
5. **确定性与审计**。项目要求同种子双跑逐字节一致，`EndingDecision` 必须可解释（12 §9）。多侧面结算让每个输入→侧面的因果可追溯；单一系数是黑箱，无法写进审计。

### 3.2 顶层立场：影响人数的成因层（原"顶层一致门"，裁决更新）

**【用户裁决 · 2026-11-15-A】** 从原著看，逃跑只有一种成立路径——地堡的顶层必须齐心，最起码市长和 IT 要达成一致、都要跑。原型是书中 18 号地堡。

**【用户裁决 · 2026-11-15-B】** 叛乱路线成立。镇压方——也就是 IT——镇压叛乱失败之后会转向。叛乱胜利，IT 转向，双方达成一致，逃离才成立。组织门不是开局就必须满足的静态条件，而是可以被叛乱创造出来的时序条件：先有胜负，再有转向，最后有一致。

**【用户裁决 · 2026-11-15-C，"都要跑"定案】** "市长和 IT 都要跑"的意思是：**他们两个都不阻挠别人跑**。两人**本人不一定**要逃出去，可以留在堡里。真正需要他们的是：搞防护服、搞物资、瞒过 1 号的监控——这些没有市长和 IT 的配合，别人做不到。但门槛比"配合"更低：**甚至不需要配合，只要不阻挠就可以**。

**【用户裁决 · 2026-11-15-D，立场分三档】** 立场分三档：**阻挠／不阻挠／配合（开防护服库、放物资、压监控）**。"承诺并归属于逃离"的说法删除。

**【用户裁决 · 2026-11-15-E，市长立场】** 读**现任市长那一刻的立场**，不是职位归属。**不要求叛乱方接管或争取到市长职位**：只要市长妥协，即使职位还在原市长手里，也可以推进逃跑。

**【用户裁决 · 2026-11-15-F，门降为结果层】** 市长与 IT 是否配合，**不是玩家去按一个"配合／不配合"的按钮，也不该是一个显式的判定闸。最终结算只看逃出去了多少人。** 立场继续存在、继续由带权重的随机决策产生，但不再产生"门通过／不通过"的显式结论，也不再作为独立的否决步骤；它只通过影响**实际能带走多少人**来体现。阻挠的后果是没人出得去、人数为 0，不需要额外的判定去宣布"失败"。

- **不**作为出发结算前的独立否决步骤；
- **不**对玩家呈现为交互选项（没有"配合／不配合"按钮）；
- **不**是仲裁前的独立闸门。

立场只通过影响**实际能带走多少人**来体现——拿不拿得到防护服、物资扣不扣、监控压不压得住、行动会不会被审计反制——最后都落到人数和过程损耗上。**结算的唯一读取对象是逃出人数。** 阻挠的后果是人数为 0，不需要额外判定去宣布"失败"。立场由此从"**成败的开关**"重新表述为"**影响人数的成因**"。

**为什么是这两方、为什么是这个读法**【用户裁决＋项目外推】：

- IT 掌握离开的物理手段（气闸、封闸、传感、防护服库、专线）。没有 IT 至少不阻挠，离开在物理上不可行或变成处刑现场（气闸纳米虫、封闸、隧道灌毒）。
- 市长掌握离开的正当性。市长阻挠时，"离开"被定义为叛乱与出逃，秩序侧追缉正当，群体无法构成"社会关系的延续"。
- "都要跑"字面容易被读成"两个头面人物亲身离开"。裁决 C 定案：真正需要的是市长与 IT 对三件事的立场——**防护服、物资、瞒过 1 号监控**——这些没有他们的配合别人做不到，所以门槛是"不阻挠"，"配合"是加成。原型 18 号的 IT 主管（Lukas）死于终止、并未亲身逃离，恰好印证"本人不一定跑"。

**立场是带权重的随机决策，不是阈值触发**【用户裁决＋项目外推】：本游戏的决策本来就不是 if-else，而是**带权重的随机决策**，每个人物天然有自由裁量能力。市长与 IT 的立场（阻挠/不阻挠/配合）用带权重的随机决策表达：

- **权重读状态，但不被状态锁死**：权重由可读状态塑形——市长个人正统性（叛乱降低正统性，接既有 `MayorLegitimacy`）、叛乱水平、IT 残余力量 `W`、Silo 1 状态、叛乱方保障的可信度等——但这些是**权重的输入**，不是强制阈值。不存在"叛乱 ≥ X → 必须妥协"。
- **种子随档、可复现**：立场决策的随机源走地堡 RNG 种子，随存档持久、可复现。同种子＋同动作序列 → 同样的立场轨迹。这就是"确定性框架下的裁量"：裁量来自权重随机，确定性来自种子。
- **不另造裁量机制或固定阈值**：不新设一套裁量系统，也不设固定阈值；带权重的随机决策本身就是裁量。

**市长的三条路**【用户裁决】：面对叛乱，现任市长有三条路：

1. **镇压**：动用秩序合法性与执法装置镇压叛乱。这是妥协前的默认路径。镇压成功则叛乱路线失败；镇压失败（叛乱胜利）则市长正统性消耗、妥协权重上升。
2. **谈判**：与叛乱方谈判，寻求中间方案。**谈判复杂，本期不做，留空占位**（机制与内容留待后续设计）。
3. **妥协**：接受叛乱现实，不阻挠逃离（可进一步配合）。这是产出市长一侧"不阻挠/配合"立场的路径。

**叛乱降低市长正统性**【用户裁决】：叛乱侵蚀现任市长的个人正统性，**接既有 `MayorLegitimacy` 状态，不新造状态**。正统性越低，市长越难维持镇压，妥协的权重越高——但这是权重输入，不是强制阈值。

**磋商是持续过程，不是机械触发**【用户裁决】：市长与叛乱方可以一直通气，不存在"叛乱方报了实力，市长就必须立刻表态"的规则。哪怕叛乱方已经打到市长办公室，市长那时才妥协，只要叛乱方接受也成立。机制上：立场的带权重随机决策**可反复重估**（随磋商推进与状态变化漂移），不是一次性触发；妥协的时点是权重与随机种子的产物，不是阈值跨过。

**市长立场读现任，不读职位归属**【用户裁决 E】：门读**现任市长那一刻的立场**，不读职位归属，也不读任何历史持有者。**不要求叛乱方接管或争取市长职位**：原市长妥协即可（职位仍在原市长手里也成立）；原市长被更替（接《人治》线 `mayor_crisis_stage` 继承链）则读继任者立场；叛乱方接管职位（原型：Juliette 当选市长）则读接管者立场。三种子状态都合法，门只认那一刻的现任立场。

**IT 一侧：叛乱胜利如何把立场从阻挠推向不阻挠/配合**【项目外推】：IT 不是意识形态派系，而是结构性服从的本地代理（世界观口径：各堡专线的另一头在 IT 主任眼中只是一套系统；IT 按 Protocol 与幕后威势 `W` 行动）。叛乱胜利拆掉 IT 继续维持阻挠立场的三根支柱：

1. **执法合法性失效**：开窗意味着法警/警察体系已事实抗命或瘫痪（对接既有权威状态：`W` 跌落、Judicial 迁移、警察服从转移）。IT 仍握系统控制权，但失去执法手段，继续阻挠在物理上不可行。
2. **命令源枯竭**：IT 的服从是结构性的，指向专线与 Silo 1。叛乱胜利常与 Silo 1 的衰弱、静默或覆灭重叠（世界 flag `network_jammed`、`termination_channel_disrupted` 等既有内容）；"为谁镇压"消失时，阻挠的组织前提自行瓦解。
3. **生存算计**：叛乱胜利后 IT 人员面临被清算的风险（暗权责任链、《共证》暴露证据链）。不阻挠乃至配合本身就是 IT 的求生路径：他们握着逃离所需的一切（气闸、库、盲区、专线知识），以此换取安全与新秩序中的位置。

**立场转变是过程，不是瞬时布尔**【项目外推，设计判断】：从镇压失败到立场稳定在"不阻挠/配合"，要经过停火／谈判／交接／立场确立的阶段完成键，历时数月漂移，漂移的权重读三类输入（各自 `TODO(balance)`）：

- **残余力量**：`W` 越高、Protocol 执行核心越完整，转向"不阻挠"越慢，且存在玉石俱焚（回摆到阻挠）的概率（见残余情况）；
- **保障动作**：叛乱方/玩家给出可信保障（赦免谈判、职能保留、公开证据不用于清算）提高"不阻挠/配合"权重；逼迫过甚（立即清算）提高鱼死网破（阻挠）权重；

**"人数为 0"与"从未出发"**【裁决 F 更新】：两者在**资格/仲裁层不需要区分**——都意味着没有存续的逃出群体，仲裁照旧读 `EscapedGroup`（人数 > 0 且 Surviving）；人数 0 = 无群体，从未出发 = 同样无群体，结果相同，不需要额外的结算类别。两者的差别在**过程层**：出发事件是否发生过、它写过什么过程事实。出发尝试过（事件发生）而人数为 0，尝试本身的副作用（损耗、结构损坏、暴露、尝试中死亡）已由级联写出，并喂其他线（《断层》、恐慌、追缉）；从未出发则这些都不存在。这一区别由"出发事件是否发生、它写了什么副作用"承载，不做单独的结算判定。一个实质的模拟差异：尝试出发而人数为 0，可能已有人死于尝试（人口损耗），从未出发则没有——这由级联的记账承载（Departed 与幸存数、尝试死亡），不由门承载。

| **能带走多少人**（容量 D） | 路线吞吐（路线事实档位）、组织动员（预案完备度＋演练＋派系凝聚力）、防护服覆盖（仅当路线含暴露段） | 门（取短板） |
| **路上活下来多少**（存活率 S） | 防护服覆盖率（可用套数/出发人数）、路线知识（先遣完好/受损/未确认）、演练水平、撤离秩序（有序占用 vs 全面暴乱，R-D 选择键） | 系数连乘 |
| **出去之后能不能维持**（维存 M） | 人均补给、照护能力、生产起点、组织留存（预案＋组织者存活） | 逐项检查 |
| **被追踪到的风险**（追踪 T） | 筹备暴露累计（修服审计、划拨异常、演练可见性、信道噪音）、撤离方式、Silo 1 注意力 | 阈值判定 |

**容量 D 的结算顺序**【项目外推】：

```text
route_capacity  = 批次容量 × 批次数（路线事实：未确认→0；受损→折减；完好→全额）
org_capacity    = 可动员人口 × f(预案完备度, 演练水平)      TODO(balance)
suit_capacity   = 路线全封闭段时不限；含暴露段时 = 可用防护服套数 × 单套可掩护通行次数 TODO(balance)
D = min(route_capacity, org_capacity, suit_capacity)
出发人数 N = min(愿意离开的人口, D)
```

愿意离开的人口由既有叛乱/亲外/派系动员状态导出（属逃离模型主体职责，本设计只固定接口）。**容量门的意义**：准备不足时"少带走一些"是自动发生的——不是判负，是门把人数压下去。

**存活率 S**【项目外推】：

```text
S = S_base
  × suit_factor(防护服覆盖率)      # 暴露段：覆盖率低的队伍损耗陡增 TODO(balance)
  × route_factor(路线知识档位)     # 先遣完好=1.0；受损<1；未确认=地板值 TODO(balance)
  × drill_factor(演练水平)         TODO(balance)
  × order_factor(撤离秩序)         # 有序占用=1.0；全面暴乱<1（与楼层损耗同源）TODO(balance)
幸存人数 = round(N × S) → 写入 EscapedGroup.Population
```

**维存 M**【项目外推，对应 R-5"成为事实的瞬间"——接应点确认他们仍有物资、照护、组织和明日】：

```text
M1 人均补给 ≥ 阈值_supplies            TODO(balance)（人·月口径）
M2 照护能力 ≥ 阈值_care（按幸存规模）   TODO(balance)
M3 生产起点已备（Agricultural 对接 + 材料划拨载体）
M4 组织留存（落地后）：预案完备度 ≥ 阈值_org 且 组织者存活   TODO(balance)
   # 出发时刻的组织前提由顶层立场塑形的人数承担（§3.2，裁决更新）；M4 只查落地之后
```

四项全过 → 群体记为存续（`Surviving = true`）；部分未过 → 分级降级（§4.1）。维存不是一次性判定就终结：落地后进入**堡外月度维持检查**（补给消耗、照护缺口、追踪后果），属逃离模型主体，本设计固定其输入为账本＋群体状态。

**追踪 T**【项目外推】：

```text
筹备暴露 E_prep：修服/划拨/演练/信道动作各自累积，账本字段        TODO(balance)：各动作暴露增量
   # 裁决更新：立场为"配合"时本地暴露源（IT 审计、秩序侧注意）大降，E_prep 主要剩 Silo 1 侧（§3.2）
追踪强度 = f(E_prep, 撤离方式可见性, Silo 1 注意力)             TODO(balance)
判定档位：无追踪 / 延迟追踪（群体标记脆弱，月度风险）/ 截击（人口折减）/ 歼灭（群体覆没）
反制入口：既有"反制藏进日常小动作"（roadmap）产出追踪折减；终止信道干扰类内容只免疫对应信道，不普遍免疫
```

### 3.4 逃跑结算级联（总览，裁决更新）

```text
开窗事实成立（既有链的终点）
  → 出发（顶层立场已塑形下列各级输入，§3.2；无显式判定闸）
  → 容量门 D → 出发人数 N（阻挠下可 → 0）
  → 存活率 S → 幸存人数 → EscapedGroup.Population（同时记 Departed = N）
  → 维存检查 M → 存续 / 脆弱 / 落地即散
  → 追踪判定 T → 无 / 脆弱标记 / 折减 / 覆没（"配合"立场下本地追踪大降，剩 Silo 1 报复窗口，§3.2）
  → 堡外月度维持检查（逃离模型主体，持续）
```

每一级只读账本＋立场塑形的输入＋既有事实，输出写回 `EscapedGroup` 与（追踪侧）既有反谍轨道。**结算的唯一读取对象是逃出人数**；仲裁在任何时候都只读 `EscapedGroup` 的最终事实，不读立场、也没有显式判定闸（裁决 F）。

### 3.5 外溢：三个成果侧面

**【用户裁决 · 外溢重定位，只登记不动设计】** "外溢计划"的说法不成立——特工自己已经见识过外溢的后果，所以外溢是**逃跑失败之后退而求其次的退路**，不是与逃跑并行的第二套准备。本条只登记该定位：外溢的具体机制属后话、本期不做，下文既有设计**不改**；但今后不得再把外溢当成与逃跑并行的准备线来设计。

| 成果侧面 | 读取的准备输入 | 换算形态 |
| --- | --- | --- |
| **能触及几个堡**（触达 R） | 已建立信道条目（种类×目标堡×可靠度） | 逐条投递结算 |
| **对方能否独立接收并再复制**（接收 P） | 包裹质量（五种能力完备度）× 目标堡自身状态 | 目标堡侧结算（未来模型） |
| **暴露代价**（暴露 E） | 每条信道的建立/使用暴露成本 | 累加进既有 Silo 1 注意力/反谍轨道 |

**触达结算**【项目外推】：每条信道一次传输尝试按可靠度确定性结算（种子派生，不摇骰）；成功投递追加一条 `OutboundSignals`【现状日志格式】。**接收结算**属外溢模型主体（roadmap：外部接收方独立核验与再复制），本设计固定其输入接口：包裹质量 P ＋目标堡模拟状态（碎片基础、开放程度、IT 控制强度）。**暴露结算**立即生效：每次建立/使用信道累加 `Silo1State.Attention`/`StationOps.Exposure`，直接接入既有 Silo 1 反应链（通牒→终止/轰炸）——这就是 I-7"外溢使异常流量与可操作观察增加"的机制投影。

**与既有加权的关系**【现状＋项目外推】：仲裁已有 `PlayerPerSpilloverSilo`（每个被驻地来源信号到达的不同地堡 +Information 分，TODO(balance)）。外溢模型落地后，把计数口径从"到达"收紧为"到达且独立接收"；准备度通过"信道数×可靠度→实际触达"与"包裹质量→独立接收率"进入该计数，**不新增任何资格路径**。

## 4. 失败与部分成功

### 4.1 降级档位表

| 准备缺口 | 结果形态 | 机制路径 | 对《越岭》资格的影响 |
| --- | --- | --- | --- |
| 顶层立场阻挠（市长或 IT，裁决更新） | 防护服/物资/监控/通道被压 → 逃出人数 0 或近 0 | §3.2 立场塑形 D/S/T | **无资格**（人数 0 = 无群体，自然结算，非显式否决） |
| 路线未确认强行出发 | 路上近乎全损 | `route_factor` 地板值 | 群体不成立→无资格 |
| 防护服覆盖不足 | 路上损耗：幸存 ≪ 出发 | `suit_factor` 曲线 | 规模折减，仍可成立（成规模阈值 `TODO(balance)`） |
| 补给不足 | 落地即散：群体在数月内解体 | M1 失败→`Surviving` 延迟置假 | 结算时已散→无资格 |
| 无照护 | 落地后持续损耗：月度人口衰减 | M2 失败→脆弱标记＋衰减 | 资格成立但群体脆弱，尾声与分数折减 |
| 无生产起点 | 能活一季，没有"明天" | M3 失败→维存期限受限 `TODO(balance)` | 结算时点敏感：窗口内成立，长期不成立 |
| 落地后组织崩坏（预案/组织者缺位，裁决更新） | 走出去的是人群，不是群体 | M4 失败→群体解体 | **无资格**（延迟定性失败） |
| 暴露过高 | 追踪：折减或歼灭 | T 判定 | 歼灭→无资格；折减→规模折减 |
| 全部齐备 | 完整成功 | — | 资格成立＋高质量加权 |

**关键设计判断（裁决 F 更新）**：**定性**的判据只剩一条——**有没有存续的逃出群体**（逃出人数 > 0 且落地后未解体），由结算自然产出，不由任何显式门投票。顶层立场阻挠不再是"一道否决门"，而是把容量/存活/追踪压向 0、让逃出人数自然为 0 的**成因**；**落地后组织/维存崩坏**则使已离开的群体解体、失去《越岭》资格所要求的事实。除此之外的一切准备缺口与立场档位都是**定量**影响（少带走、路上折、落地散、被追踪）——这正对应"准备不足时应该是少带走一些、路上损耗、落地即散，而不是一刀切判负"；准备项与立场都只"决定成得多好"，成不成由逃出人数自然结算。

### 4.2 硬失败的保留

1. **路线未确认＋强行出发**：存活率地板可使出发群体全灭；若原驻地随后也被处置，无任何幸存社会，照判《寂堡》。
2. **追踪歼灭**：群体在堡外被消灭，`Surviving` 置假；此后原驻地的毁灭/重置/崩坏不再触发惨胜例外（P0 照旧先读逃出群体【现状】）。
3. **修复被反制**：IT 审计把胶带换回/没收，出发时防护服实际失效——这是反制交互而非数值惩罚，内容层用事件表达（审计事件读筹备暴露阈值触发）。IT 立场为"不阻挠/配合"时此风险消失（IT 自身不再阻挠，§3.2）。
4. **宿主先死**：准备再好，开窗前宿主被终止/重置，逃离未成事实，按《寂堡》《遗忘》处理（12 §5.5、§5.2 既有口径）。
5. **阻挠下的玉石俱焚（裁决更新）**：叛乱胜利但 IT 核心拒绝放下阻挠，触发终止信号/重置/隧道灌毒——逃离人数为 0，且驻地本身被毁/被重置，按既有事实键落《寂堡》《遗忘》（§3.2 残余情况表）。
6. **阻挠下强行出发（裁决更新）**：结算为人数 0 或极小＋重损耗，不构成逃出群体（【待裁决】3）；若驻地随后被处置，无幸存社会例外可言，照判《寂堡》。

### 4.3 与既有仲裁的对接

1. **资格判定不改**：《越岭》资格仍读 `EscapedGroup.SurvivingEscapeGroup()`；准备度结算只决定这个群体**长什么样**（人口=幸存者、存续=维存结果、新增质量字段）。
2. **资格事实的产生受立场塑形（裁决 F 更新）**：仲裁代码不读立场也不读门，只读逃出群体；但逃出群体的**产生**由出发结算塑形，而立场决定其输入（§3.2）——市长或 IT 阻挠时逃出人数自然为 0，产不出逃出群体。这是资格事实产生条件的塑形，不是资格读取改动，也没有显式否决步骤；具体口径见 §3.2【待裁决】清单。
3. **P0 例外不改**：`deathFact && escapeAlive → 惨胜` 的既有分支原样保留；追踪歼灭只是让 `escapeAlive` 变假。
4. **P2 加权接口**：新增一条玩家贡献项，读逃出群体质量（规模档位、维存裕度、是否脆弱），系数 `TODO(balance)`；外溢侧保留 `PlayerPerSpilloverSilo`，口径收紧为"独立接收"（§3.5）。两条都只对合格候选计分（既有 pool 过滤），不碰资格。
5. **外溢不进胜负判定**【用户指定＋既有裁决】：外溢为零同样可以判胜；外溢准备度只改变触达堡数与接收质量，进而只影响结算分与尾声演出。本设计不新增任何把外溢变成资格的路径。
6. **结算分落点**：逃跑质量与外溢触达分别进入 REBELLION / INFORMATION 候选的加权分，经既有 `GameScore` 结算呈现；不新增结局类型、不新增主体。


`EscapeGroup` 在逃离模型落地时补两个审计字段：`Departed int`（出发人数，供路上损耗的尾声与审计）与 `Fragile bool`（脆弱存续标记，供堡外月度检查）。

**顶层立场状态（裁决 F 更新）**：立场不新增聚合结构，由两个内部事实表达——`top_stance:mayor`、`top_stance:it`（各 ∈ 阻挠/不阻挠/配合，进入既有内容状态体系，仲裁不读，出发结算的输入层读；不对玩家呈现为交互选项）。立场由带权重随机决策产出，随机源走地堡种子；权重读既有状态（`MayorLegitimacy`、叛乱、`W`、Silo 1 状态等），不新造状态。存档升级后零值 = 阻挠，与旧档语义一致。

**存档升级**：`CurrentSaveVersion` 9 → 10。v9 档经备份＋单事务＋回读校验升级，新账本零值起步、不回填任何推测状态——与 v8→v9 的口径一致。旧档升级后行为逐位不变（账本在逃离/外溢结算落地前没有消费方）。

### 6.2 引擎效果与触发器（封闭集扩展）

| 新增 | 类型 | 语义 |
| --- | --- | --- |
| `preparation_delta` | 效果 | 按字段白名单写账本程度量/整数量（未知字段 = 校验失败） |
| `preparation_transfer` | 效果 | 资源划拨：`Supplies`/`Materials` → 封存账本；余额不足**显式失败** |
| `preparation_gte` | 触发器 | 账本字段 ≥ 阈值，供后续节点门控 |
| `spillover_channel_add` | 效果 | 登记一条受限信道（Layer 3 启用） |
| `escape_group_depart` 扩展 | 效果 | 现有按人数离堡；逃离模型落地时改为读结算级联输出（不破坏现语义） |

JS helper 与校验开关按既有 `escape_group_*` 的三处落点（校验、执行、脚本 helper）同步扩展。

### 6.3 内容事件与行动（行动门控）

准备动作按 R-2 功能位表门控（部门关系＋阶段），全部是情境化动作而非通用按钮：

- **修服链**：接触供应链（IT 侧关系/职务便利）→ 换胶带修复（Mechanical 关系门控）→ IT 审计反制事件（读 `PrepExposure` 阈值）；
- **划拨链**：Supply 关系门控下的补给/材料封存（`preparation_transfer`），立即扣减堡内资源；
- **预案链**：逐功能位对接（Mechanical/Mines/Supply/Medical/Agricultural/Mayor-Police 各一接触卡），每对接一位写 `PlanCompleteness` 增量；
- **演练**：可见性成本（+`PrepExposure`）换 `DrillLevel`；
- **照护与生产起点**：Medical/Agricultural 对接＋物资载体；
- **接应建设**：与先遣链（13 分册既有设计）共用完成键，写 `ReceptionStage` 档位；
- **信道建立与包裹组装**（外溢侧）：三种信道各一条接触卡；包裹五能力各一完成键；
- **顶层链（裁决更新，生产立场事实）**：叛乱结算（开窗事实）→ 市长/IT 立场带权重随机漂移与持续磋商接触卡（停火/赦免谈判/交接；谈判本期留空占位；权重读 `MayorLegitimacy`、叛乱、`W`、Silo 1 状态与保障动作；玉石俱焚回摆分支）→ 写 `top_stance:mayor`/`top_stance:it` 立场事实（内部状态，不作交互选项、不作显式闸）。立场塑形出发结算输入；"配合"立场下准备链转公开口径（§3.2）。

### 6.5 分层与顺序（推荐）

```text
Layer 0  纯内容，今天可写：路线事实与准备里程碑用完成键 + silo_flag 表达（现有效果即可）
Layer 1  账本状态 + 效果 + 有成本的准备动作（v10）——推荐最先做，最快看到效果
Layer 2  逃离模型主体：出发级联 + 堡外维持 + 追踪 + 仲裁读群体质量
Layer 3  外溢模型主体：信道投递 + 独立接收 + 暴露结算 + 仲裁口径收紧
```

- **Layer 1 是最快的可见效果层**：准备度从此是有状态、有成本、有反制的真实投入（UI 可见账本与功能位缺口），且是 Layer 2/3 的接口前置。但必须遵守一条纪律：**Layer 1 阶段仲裁不读账本**——准备度在逃离/外溢结算落地前不产生任何结局影响，防止"囤准备"变成假胜利进度。
- Layer 2 与 Layer 3 互相独立、可并行，都只依赖 Layer 1 的账本接口；两者的主体模型（路线与批次、外部接收方模拟）仍需各自的详细设计，本设计只固定输入输出契约。
- Layer 0 的路线事实节点在 13 分册已经设计到"开窗"，其后的批次节点继续维持注释预留，等 Layer 2 落地。

## 8. 明确不做

1. 不新增结局类型，不新增投票主体，不让准备度成为第五类贡献者。
2. 不让准备度进胜负判定；外溢永远只是评分项。
3. 不做准备度被动积累、不做 AP→准备度直接兑换、不做概率摇骰。
4. 不把防护服写成丰饶物资，不削弱 IT 对处刑工具供应链的暗权。
5. 不在逃离/外溢主体模型落地前让账本影响任何结局（Layer 1 纪律）。
6. 本轮不改代码、事件、配置与数值；本文只产出机制设计与接口契约。
7. 不把叛乱胜利当成自动产出"不阻挠/配合"立场（裁决更新）——立场转变是带权重随机的过程，读市长与 IT 的立场，不读固定阈值。
8. 不把无门的离开当作逃出群体，不为逃跑开辟顶层立场之外的第二种成立路径（裁决更新）。
9. 不把市长/IT 的配合做成玩家按钮或显式判定闸（裁决 F）——立场是内部状态、是影响人数的成因，结算只看逃出人数。
