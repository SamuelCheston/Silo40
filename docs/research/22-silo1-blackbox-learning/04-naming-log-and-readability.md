## 0. 前提回顾（最新裁决）

- 旧模型「静态单峰曲线靠试探找峰」作废：AI 对 AI 几回合即可试出静态峰，难度失真。
- 每堡维护一个 0–1 隐藏量：0=完全按 Order 办事，1=公开叫板，中段=消极、拖延、阳奉阴违。
- 它不是 safeguard 风险 `r` 的比例函数；`r` 只决定其增长速度（`r` 高→涨快，`r` 正常→向 0 回落），有月级以上时间常数。
- 执行强度 `E` 对 `r` 仍单峰（中段死心塌地、两端不干活），但峰由隐藏量间接决定。
- 1 号只维护分箱后验信念（估计值 + 不确定性），观测延迟、带噪、可被伪装。

## 1. 命名候选与选择

### 1.1 这个量到底测什么

三种候选语义，先辨清再命名：

| 语义 | 层次 | 问题 |
| --- | --- | --- |
| 「随时可能被牺牲」的主观感受 | 情绪层（因） | 情绪不直接决定执行：同样的恐惧既可能让人更死心塌地抓住 Order，也可能让人躺平拖延，映射双向、机制不确定；且情绪不可见，玩家只能感知行为。 |
| 自保倾向 | 姿态层（果） | 执行链把「保全自己」排到「执行 Order」之前。三档天然连续：无需自保→全力执行；开始自保→拖延、阳奉阴违；自保压倒一切→公开叫板。与 `r` 的驱动关系闭环：`r` 正是「可能被牺牲」的风险，风险高→自保动机涨，风险退→自保松弛回落。 |
| 对 Order 本身的不信任 | 信念层 | 能覆盖中段（怀疑→拖延），但「不信任」指向权威的正当性；而本量的驱动前提是牺牲风险——一个堡可以完全相信 Order 正当，仍因害怕被牺牲而拖延。语义隔了一层。 |

结论：本量测的是**执行链对 Order 指令的自保姿态**——不是情绪，也不是对权威的信念，而是「执行指令时给自己留多少后路」的组织姿态。

### 1.2 候选清单

每个候选均做世界观合规自检：措辞不得暗示底下人知道 1 号地堡存在（服从对象只是 Order 本身）。

#### 候选 1：`sacrifice_dread` · 惧牺（主观感受语义）

- **测的语义**：全堡弥漫的「随时可能被牺牲」的恐惧强度。
- **玩家感知**：事件文案——「部门里开始有人悄悄把家属名字写进遗物登记册。」界面——「对牺牲的恐惧在蔓延。」
- **合规自检**：恐惧无需指明对象（怕的是指令里的风险，不是某个堡），合规。
- **弱点**：情绪层，映射双向；玩家看到的是行为不是情绪，命名与呈现错位。

#### 候选 2：`self_preservation` · 自保（自保倾向语义）

- **测的语义**：执行链把自保排在执行 Order 之前的程度。0=无需自保、全力执行；中段=以拖延、阳奉阴违的方式自保；1=自保压倒指令、公开叫板。
- **玩家感知**：事件文案——「检修队把指令压了三天，理由是人手不够——可那周没有人请假。」界面——「各部门开始给自己留后路。」
- **合规自检**：自保的对象是「指令附带的风险」，不需要知道风险来自谁，合规。
- **弱点**：无显著弱点；需注意与个体层面的「求生」区分，文案中始终写组织（部门/执行链）而非个人。

#### 候选 3：`order_doubt` · 疑令（对 Order 不信任语义）

- **测的语义**：对 Order 权威正当性的怀疑，从信服到否定。以 Order 为词根（允许用法：怀疑对象是 Order 本身，不涉及 1 号）。
- **玩家感知**：事件文案——「主任照例宣读新条款，这一次没有人动笔。」界面——「对指令的怀疑在加深。」
- **合规自检**：怀疑对象明确是 Order 而非 1 号，合规。
- **弱点**：信念层，与驱动前提（牺牲风险）隔一层；且与既有 `Protocol`（Order 条款信念体系）语义重叠，易混淆。

#### 候选 4：`compliance_erosion` · 侵蚀（行为层）

- **测的语义**：对 Order 的执行被侵蚀的程度，纯行为描述。
- **玩家感知**：事件文案——「本月的报表晚了一天，也薄了两页。」界面——「执行正在被侵蚀。」
- **合规自检**：不涉及任何主体，合规。
- **弱点**：「侵蚀」暗示不可逆，与「`r` 正常→向 0 回落」的可恢复性矛盾；纯行为层丢失动机，伪装行为（报表过于干净）难以归类。

#### 候选 5：`restiveness` · 桀骜（对抗端语义）

- **测的语义**：从服从到桀骜不驯的对抗程度。
- **玩家感知**：事件文案——「仓库拒绝开门，理由是没见到盖章的指令。」界面——「桀骜正在滋长。」
- **合规自检**：对抗对象可写成指令本身，合规。
- **弱点**：语义偏向 1 端（公开叫板），盖不住中段——拖延与阳奉阴违恰恰不是桀骜；且与既有 `Rebellion`（叛乱值）过近，玩家会混淆两个量。

### 1.3 选择与理由

**选定：`self_preservation` · 自保。**

四条标准逐一满足：

1. **语义准确**：三档恰是自保强度的三档（无需自保→软自保→自保压倒一切）；与 `r` 的驱动关系闭环（风险生机动、风险退机动松弛），可恢复性自然。
2. **玩家可感知**：拖延、囤积、阳奉阴违、报表粉饰、公开抗命全是可写进事件文案的具体行为。
3. **措辞合规**：自保不需要知道谁可能牺牲自己——对象是「指令上的风险」，全程无需提及 1 号。
4. **与既有词汇不冲突**：不占用 Pact / Legacy；Order 只在候选 3 中作引用性词根；与 `Rebellion`（自下而上的民众叛乱）、`SafeguardRisk`（风险本身）、`OrderDeviation`（IT 幕后威势偏离）、`Cohesion`（凝聚力）语义正交（见 §1.4）。

### 1.4 与既有量的边界

| 既有量 | 语义 | 与 `self_preservation` 的区别 |
| --- | --- | --- |
| `safeguard_risk`（`r`） | 风险本身（输入） | 自保是对风险的响应（慢存量）；`r` 涨不等于自保立刻涨（月级时间常数）。 |
| `rebellion` | 自下而上的民众叛乱 | 自保是执行链对指令的姿态；`Θ=1` 公开叫板≠叛乱成功，只表示执行链不再执行。 |
| `OrderDeviation`（ShadowAuthority） | IT 幕后威势对 Order 的偏离（IT 内部量） | 自保是全堡执行链量，不限于 IT。 |
| `cohesion` | 内部凝聚力 | 自保可与高凝聚力并存（全堡一致地阳奉阴违）。 |

**使用口径**：代码/存档/调试用标识符 `self_preservation`；叙事文本（事件文案、界面提示）用中文叙事名「自保」；1 号对它的信念估计在后验字段中单独表述（「估计」「区间」），不复用叙事名，避免暗示对面知道真值。

## 2. 决策日志格式（1 号信念决策日志）

### 2.1 定位与先例

- 结构先例：`NegotiationLogEntry`（`internal/model/models.go`）——归一化权重 + 因子摘要、环形上限 24、随存档持久化、可复盘。
- 审计先例：LLM 决策日志（`references/llm-npc.md`）——append-only、经调试端点查询（`/debug/game/llm/decisions` 先例）、回放按日志还原决策点。
- **与谈判日志的关键区别**：谈判日志的决策方（市长/叛乱方/IT）是玩家可见的本地行动者，日志可上前端；1 号信念是远端的特权内部状态，**原始日志不进玩家界面、不进玩家可见文本**，只供审计（调试端点）与回放。「1 号是黑箱」本身就要求它的信念表不可被玩家直读。
- 观测噪声与后验更新的取样纪律（是否消耗 RNG、取样顺序）由本系列形式化各卷裁决，本卷不覆写。

### 2.2 字段清单

| 字段 | 含义 |
| --- | --- |
| 年/月 | 1 号作出本次指派的月份（注意：不是观测所属月份，延迟在观测字段中体现） |
| 堡 | 目标堡编号与名称 |
| 观测摘要 | 本月到达的观测：所属月份（延迟几月）、自报/稽查带噪读数、交叉验证来源与一致性 |
| 后验摘要 | `Θ̂` 估计（分箱名 + 数值）、区间 `[lo, hi]`、不确定性档位（高/中/低） |
| 指派 `r` | 本月指派的风险度（档位名 + 数值） |
| 理由码 | `exploit` / `explore` / `event` |
| 因子摘要 | 决策时刻的因子读数：观测延迟、伪装嫌疑、距上次分箱变化月数、试探冷却剩余、试探预算消耗等 |

**环形上限**：每目标堡独立环形保留，上限与 `NegotiationLogCap = 24` 对齐（每堡约两年信念史）；随存档持久化。

### 2.3 理由码

| 理由码 | 含义 | 日志必须写明 |
| --- | --- | --- |
| `exploit` 利用 | 按当前后验（区间中点/分箱）指派 `r`，用既有信念办事 | 依据的分箱 |
| `explore` 试探 | 故意指派偏离后验惯常点的 `r`，制造执行响应差异以换信息 | 试探方向与目的（收窄区间/验证伪装/…）；须满足冷却与预算约束 |
| `event` 事件驱动 | 外生事件（危机、线路中断、制度变动、一次性转折——`perception.go` 的 news-worthy 三类）打断常规节奏，被迫响应 | 事件来源 |

### 2.4 完整示例条目（中文）

```text
123 年 2 月 · 17 号堡
到达观测：1 月自报（延迟 1 月），叛乱带自报「低」；与该堡供应报表交叉验证：一致
后验：估计 0.38（档「拖延」），区间 [0.22, 0.55]，不确定性：高
指派：r = 0.55（档「重点关注」）
理由：explore——区间过宽，抬高风险度一档，观察执行强度变化以收窄区间
因子：观测延迟 1 月；伪装嫌疑低；距上次分箱变化 4 月；试探冷却已到期；本季试探预算 1/2
```

### 2.5 日志如何体现「1 号在猜而不是全知」

1. **估计与不确定性同时可读**：每条都有区间与不确定性档位——读者看到「1 号不确定」，而不是「1 号判定了」。
2. **观测总是旧的**：观测字段显式标注延迟月数，决策依据是过去的剪影，不是当下真相。
3. **理由码区分试探与利用**：`explore` 条目写明试探目的，暴露指派是学习手段而非已知结论；`exploit` 条目则显示 1 号在可能错误的信念上照常行动。
4. **`event` 条目显示 1 号被事件推着走**，而不是预见事件。

## 3. 玩家侧可读性设计

**总口径**：玩家应感觉到「对面在摸索」——会迟疑、会过度反应、会被骗、会滞后；而不是面对一个全知最优者。玩家永远看不到 `Θ` 与 `b` 的任何数值、区间、档位估计；玩家可见文本的主体是 Order/专线/稽查组/指令，不是「1 号」（既有「截获：1 号地堡部门信号」情报产品是单独门控的例外通道，本卷不扩展它）。

### 3.a `r` 变化的可见呈现（透过 Order 渠道）

- **渠道**：玩家本堡的 `r` 档位变化以 Order 指令措辞到达（风险评级调整通知，专线/部门层面表现为：核查请求增多、稽查组到访、供应与保障等级调整）；邻堡的变化走谣言/线路杂音渠道（`perception.go` 口径：IT 特工听「线路杂音」，其他人听「谣言」，改写为间接感知表述）。
- **传播阈值**：只有关键变化传播——`r` 跨越评级档位算制度变动；档内小幅波动不传播、不可见。与 `neighborNewsworthy` 口径一致（危机/制度变动/一次性转折才传得出）。
- **措辞示例**：
  - 本堡指令：「Order 风险通告：你堡的保障等级由『常规』调整为『重点关注』。指令没有说明原因。」
  - 邻堡杂音：「经线路杂音听到：17 号堡这个月的专线流量多了一倍，全是核查请求。」
- **节奏感**：月级时间常数 + 档位阈值 → 玩家感到「评级很少变，一变就有原因」，而不是每月跳数字。
- **统一展示**：档位变化只在指令/情报记录单点呈现一次，不在多个面板重复（跨线共享事实只统一展示一次的既有纪律）。

### 3.b 伪装的可见破绽

玩家（或邻堡）伪装后，1 号信念不动或走偏，以下异常可被玩家察觉。**全部只陈述已发生事实，不解释「因为对面信念滞后」**，推理留给玩家：

1. **报表过于干净**：玩家堡伪装成功后对面反应异常平静——「连续三个月的『无异常』报表递上去，没有等来一次补充核查。」堡内明明出过事，平静本身就是信息；文本不判断伪装是成功了还是对面根本没在看。
2. **稽查结果与实际脱节**：稽查结论与堡内实况不符——「稽查组的结论是储备充足。仓库的实际存量撑不过两个月。」对面在按旧的或错的信念行动。
3. **指派与实际脱节**：`r` 指派与堡内实际状态明显不符——堡内已危机四伏而评级仍「常规」（对面被伪装骗住或滞后），或堡内平静而突然升「重点关注」（对面的信念被别处事件带偏）。
4. **反应慢半拍**：异常已发生数月，核查指令才姗姗来迟——观测延迟以事实形式可见。

### 3.c 与失败线征兆的衔接

- 既有征兆集合（`lines_progress.go` 的 `failureOmenKeys`）全部是已实现的内容事件键，快照只读点亮状态、不新造预警机制。信念驱动的表现沿用此先例：**挂到既有征兆键的触发资格上，不新造征兆**。
- 候选衔接（资格判定，具体阈值 `TODO(balance)`，由实现卷落地）：
  - 后验跨过「叫板」档 → 《寂堡》线既有征兆（`strike_reconnaissance` / `termination_channel_test`）获得点亮资格；
  - 后验长期停留「拖延」档且 `r` 高 → 《遗忘》线既有征兆（`silo1_purge_omen` / `archive_purge_order`）获得点亮资格；
  - `r` 跨入高档（对应既有 `safeguard_protocol_warming` 的 `safeguard_risk` 阈值口径）→ 保障机制升温征兆维持既有触发，不重复呈现。
- **呈现纪律**：只展示已发生的具体征兆事实（「稽查组进驻」「专线静默了三天」），不点名结局、不给概率——提示的分寸止于「事实已被看见」（既有口径）。

### 3.d 明确禁止项

- **不点名结局**：文本永不提及结局名，不暗示「接下来会发生什么」。
- **不给概率**：玩家可见文本不出现数值概率、百分比、置信度；不确定性只存在于审计日志。
- **不教程弹窗/强制引导**：一切说明经由界面原生渠道（指令、情报记录、事件文本），无弹窗、无引导。
- **不展示 `Θ` 与 `b`**：玩家永不接触隐藏量真值与后验数值/区间/档位估计。
- **不以「1 号」为主语**：玩家可见文本的主体是 Order/专线/稽查组/指令（§4 清单约束）。
- **不读心反馈**：对面永不响应玩家未经常规报告/观测渠道暴露的事实；凡有响应，必须有可追溯的信息来源（哪月的报告、哪次稽查）。

## 4. 世界观合规清单

**口径**：下面的人不一定知道 1 号地堡的存在，他们表面服从的对象只是 Order 本身；只有极少数主任终其一生才参悟背后是活人指挥。玩家可见文本必须满足：句子主体是 Order/系统/专线/指令/稽查组，或以传闻来源转述（「传言……」「经线路杂音听到……」），不得是「1 号」或「背后的人」。

正例/反例表：

| # | 正例（合规：服从对象是 Order） | 反例（泄漏：暗示底下人知道 1 号存在） |
| --- | --- | --- |
