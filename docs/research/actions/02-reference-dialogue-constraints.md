# 参考案例：对象化对话、地点行动与情境约束

> 范围：Disco Elysium、Pentiment、Citizen Sleeper、The Occupation。只分析动作呈现、身份和机会成本。
>
> 硬判据：**动作参数必须参与结算，不能只参与文案。**对白变长、选项变多或动画变慢，本身都不算对象化设计。

## 1. Disco Elysium：借“检定附着于当前对象”，不复制人格系统

### 实际做法【参考事实】

玩家点选具体人物或高亮物件。调查尸体时，可以分别对脚印进行 Visual Calculus、对尸体进行 Endurance 等检定；也可先向旁边的人索取或去店里购买氨水，再回来继续验尸。技能和属性虽然在角色页配置，实际使用却附着于当前对白、尸体、脚印等对象。NPC 会记住玩家的言辞并作出反应。时钟不随闲逛自然流逝，而由交谈、阅读、坐长椅等行为推进，NPC 入夜后会回屋。[cite:1][cite:2][cite:3]

### 可借鉴层

1. **技能是修饰器，不是按钮**：先选择对象和话题，再决定哪个身份、背景或技能参与。
2. **对白是世界状态输入**：玩家说出的具体内容会成为 NPC 记忆，而非只改变玩家资源。
3. **准备动作改变后续选项**：找到工具、材料或证人后，回到同一对象可出现新处理路径。
4. **时间由行为推进**：时间与具体谈话、阅读和等待绑定，不是独立“推进时间”万能键。

### 不借的部分

- 不复制高密度人格技能、思维内阁和超长对白。
- 不让每次小行动都做一次骰检，避免职务行动变成随机验证器。
- 不把 NPC 记忆简化成“喜欢/讨厌玩家”两种状态。

### 对本作的映射

```text
先选《异常申领单》→ 选择“向 Judicial 调查员出示”
→ 根据单据来源、玩家身份、此前是否被质疑决定回应
→ 记录调查员见过该单据及玩家是否解释来源
```

技能只改变回应和可用分支，不能把不存在的材料变成有效证据。

## 2. Pentiment：借“帮助、共餐、守密构成关系”，不复制村落日程

### 实际做法【参考事实】

玩家到具体人物或物件前问话、调查。盐矿调查、共餐等关键行动会结束一个祈祷时段。游学地、专业和爱好等背景增加情境选项，也可能惹恼对方；说服依赖此前正负互动，而不是通用口才按钮。帮人砍柴、摆肖像、读法律文件可换得动机线索；共餐和合适回应可让对方开口。最后选择报告或隐瞒哪些发现，泄露私事会招致相关人物怨恨。[cite:4][cite:5]

### 可借鉴层

1. **关系由事件组成**：帮助、共同生活、保守秘密和泄密都是可回溯的关系事件。
2. **身份提供情境能力**：专业背景让玩家看懂特定材料或说对话，而非提供全局成功率。
3. **关键活动占用时段**：共餐和调查的意义在于放弃另一段日程，不是播放更长动画。
4. **信息使用影响关系**：把材料交给谁、隐瞒哪部分，比“是否分享”更重要。

### 不借的部分

- 不复制祈祷时段、长年代跨度和大型村落群像。
- 不把所有关系都做成多阶段个人剧情；普通联系人只需少量真实记忆。
- 不用背景选项绕过材料与对象，专业人士也不能凭空知道未接触的事实。

### 对本作的映射

Medical 巡诊时，玩家可选择是否向患者透露另一楼层的配给说法。该选择同时影响：

- 当前患者是否愿意继续叙述；
- 患者所属群体对玩家的记忆；
- 该说法是否开始跨楼层传播；
- 玩家后续是否被追问消息来源。

这四个结果必须由实际人物、材料和传播路径结算，不能只播放不同对白。

## 3. Citizen Sleeper：借“地点行动与有限行动槽”，不复制骰子外壳

### 实际做法【参考事实】

地点图标各自展开行动。每周期依 Condition 获得预掷 D6，放入当地行动的 dice slot，骰值与技能影响结果。Clocks 追踪玩家及他者进程，Drives 组织可追随的故事和 NPC 线。工作在特定地点耗骰换钱，购买补给则在具体摊贩或医生处换食物、稳定剂等资源，形成地点、劳动、交易和下轮行动数的闭环。[cite:6][cite:7][cite:8]

### 可借鉴层

1. **地点决定动作集合**：不同地点不是同一动作列表的皮肤。
2. **有限行动槽形成互斥**：投入一处就不能同时推进另一处。
3. **他者 clocks 持续推进**：玩家不行动时，世界也在改变，但结果应由规则而非纯惩罚计时器驱动。
4. **NPC 故事落在具体地点**：关系和故事通过“去哪里、帮什么忙”推进。

### 不借的部分

- 不复制预掷骰、生存消耗或地点图标界面。
- 不以为有限行动槽自动消除公式化。重复打工仍会公式化，后期压力减弱后尤其明显。[cite:7]
- 不让 clocks 只负责倒计时惩罚；每个 clock 都应有可观察进展和可干预节点。

### 对本作的映射

本月选择 Medical 巡诊，意味着无法在同月完成 Mechanical 全网检修。两者都应返回真实主结果，并使相关事件 clock 前进。若玩家仅因某按钮提供稳定 connection 而反复点击，仍属设计失败。

## 4. The Occupation：借“实时日程、门禁与实物链”，不借不可回退惩罚

### 实际做法【参考事实】

游戏主体由实时时段构成，NPC 作息、临时离席与定时访谈持续推进。动作受房间和实物约束，例如找密码、登录电脑、把邮件存到软盘、在受限区打印。门卡、密码、员工区和保安限制进入，也可通过通风管、窗或断电旁路。公文包保存证物，手表管理提醒，寻呼机提供目标。[cite:9]

### 可借鉴层

1. **NPC 日程是动作条件**：何时能找到某人，与人在哪里同等重要。
2. **权限与物件组合**：门卡、密码、电脑、存储介质和打印地点构成可理解的实物链。
3. **替代路径**：正式准入、访谈获得信息、旁路进入都可成为不同风险的路径。
4. **持续机会成本**：做一件事时，其他预约与日程仍在推进。

### 不借的部分

- 不复制第一人称操作、复杂实物搬运和实时等待。
- 不把首发版章节末存档、长时间不可回退当作深度；故障和重复长段流程只会放大挫败。[cite:10]
- 不让错过一次预约直接摧毁整局，应有迟到后果和替代接触方式。

### 对本作的映射

Supply 联系人在配给交接后才出现在仓库。玩家可以：

- 在交接时到场，直接询问异常申领单；
- 错过交接后，通过库存记录找到同一批次；
- 请另一联系人转交材料，但增加信息经手人和泄露路径。

三条路径使用不同对象、权限与风险，不是同一结局按钮换皮。

## 5. 四个案例的共同结论

1. 身份和技能应改变具体对象的可用选项，而非提供全局动作。
2. 关系需要可回溯的互动，信息使用也会反过来改变关系。
3. 时间限制必须产生取舍，同时保留可理解的替代路径。
4. 动作多步不等于有深度；只有每一步都改变权限、材料、对象状态或后续选择，步骤才有意义。
5. 本作应借结算结构，而不是复制对白长度、骰子、第一人称或不可回退机制。

## 6. 本文反例

```text
“向 Supply 联系人说好话”
“向 Mechanical 联系人说好话”
```

若两者只替换 NPC 名称和肖像，最终都调用同一个 `increaseAllRelations()`，不读取当前话题、此前帮助、材料、日程和对方诉求，则仍是公式化按钮。即使每个 NPC 有独立数值，只要输入与结果结构完全相同，仍然缺乏情境。
