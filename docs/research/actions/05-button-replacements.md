# 八个抽象按钮的逐项替换清单

> 范围：Build Network、Share Info、Gather Info、Conduct Propaganda、Incite Rebellion、Publicize Faction、STATION_DECEIVE、STATION_TRADE。
>
> 硬判据：**动作参数必须参与结算，不能只参与文案。**后台可以保留 connection、fragment、propaganda、rebellion 等结果，但玩家入口必须改为对象明确的情境动作。

## 1. Build Network → 帮具体的人做一件具体的事

### 旧入口为什么不成立

“建立人脉”是系统结果，不是人在现实里执行的动作。点击后不知道该找谁、说什么、做什么，也无法解释为什么同一方式能经营所有部门。

### 新动作族

| 情境动作 | 必要参数 | 直接结果 |
| --- | --- | --- |
| 帮仓管核对异常配给 | Supply 联系人、仓库、交接时段、异常批次 | 完成核对；形成帮助记忆；可能得到物流 Observation |
| 归还维修单 | Mechanical 联系人、设施、维修单原件、当前持有人 | 单据易主；形成归还记忆；打开设备话题 |
| 替病区联络人整理就诊顺序 | Medical 联系人、病区、集中就诊事件、玩家身份 | 改善处置秩序；形成协助记忆；可能听到患者说法 |
| 在交接班时与值班工程师核对设备 | 值班人、设施、设备异常、当前日程 | 确认一个问题；形成共同工作记忆 |

### 后台仍保留

- `Connection` 或部门关系数值可以保留，用于门槛和派生指标。
- 新增/保留 `RelationshipMemory`，说明关系为何变化。
- 联系人对玩家的材料披露、委托和准入权限可以随真实帮助改变。

### 防公式化规则

同一联系人、同一未完成问题不重复刷关系。只有新的工作对象、新的材料或新的互动方式才产生新记忆。若“核对配给”和“归还维修单”最终都只加同一全局数值，没有对象记忆和不同后续，判失败。

## 2. Share Info → 向具体对象出示、转述或交付指定材料

### 旧入口为什么不成立

“分享情报”没有说明分享给谁、哪份材料、用何方式、希望对方如何使用。把同一份材料交给 Judicial、Mayor 和 Supply，后果不应相同。

### 新动作族

| 情境动作 | 必要参数 | 直接结果 |
| --- | --- | --- |
| 向 Judicial 调查员出示异常申领单 | 调查员、案件未结、Observation 原件/副本、来源说明 | 记录司法披露；核验程序或追问来源 |
| 向 Supply 仓管归还并核对申领单 | 仓管、仓库、对应批次、单据 | 增加部门内核验记录；补充经手信息 |
| 向 Mayor 转述 Lower 患者的配给说法 | Mayor 联系人、具体 Version、巡诊来源、当前会面 | 记录官方渠道获知的说法；产生接受、质疑或要求复核 |
| 请联系人转交材料副本 | 转交人、最终接收人、副本、披露路径 | 新增经手链和潜在泄露路径，不等于本人直接告知 |

### 后台仍保留

- Observation/legacy fragment 的持有与分享投影。
- 接受率、思潮、恐慌、怀疑等结果，但必须由材料、受众和披露方式决定。
- 每次披露的 `disclosure_state`、受众和经手路径。

### 防公式化规则

已读材料重复出示只显示已知回应，不重复产生接受、关系或思潮效果。若选择的 Observation ID 在执行时被忽略，改由 `known_fragments >= 1` 随机替代，判失败。

## 3. Gather Info → 履行当前职务，材料作为伴随结果

### 旧入口为什么不成立

本作已决定不再有专门的“收集情报”按钮。玩家不是到任意部门按一下就拿随机碎片，而是在行医、维修、配给、执法等工作中遇到材料。

### 新动作族

| 情境动作 | 职务主结果 | 可能的伴随材料 |
| --- | --- | --- |
| 在 F76–80 巡诊 | 患者处置、恐慌和生产力结果 | 症状、病史、患者叙述、不同楼层的说法 |
| 检修 F124 冷却泵 | 设备、稳定与资源结果 | 非授权改动、维修记录、管线声音 |
| 核对异常配给批次 | 库存与配给结果 | 申领单、替代物、经手记录 |
| 处理一宗合规搜查 | 物件处置与程序结果 | 物件法律状态、现场记录、证词 |
| 维护 IT 链路 | 链路状态与权限结果 | 访问日志、异常时段、索引缺口 |

### 后台仍保留

- Observation 获取与 KnownFragments 兼容投影。
- `first_signal` 等阶段可消费首份有效本地 Observation。
- 主行动的 AP、时间、职务效果和门控。

### 防公式化规则

没有合法材料时主行动仍成功，不出现“调查失败”。同一来源去重后不重复计数。若行动唯一主奖励仍是材料，即使改名为“巡诊”，也仍是被否决的情报按钮。

## 4. Conduct Propaganda → 在具体受众与渠道中传播指定版本

### 旧入口为什么不成立

“进行宣传”没有说明宣传什么、对谁、在哪里、由谁出面。没有受众与材料时，直接增加全局宣传力度会让传播变成无实体的数值积累。

### 新动作族

| 情境动作 | 必要参数 | 直接结果 |
| --- | --- | --- |
| 在食堂交接班时朗读材料 | 地点、班次、具体 Observation/Version、在场人群 | 记录一次公开传播与受众覆盖 |
| 请 Supply 联系人夹带传单 | 联系人、下一次配给、传单内容、经手链 | 形成传播委托，到期后计算实际覆盖 |
| 在部门会议上提交复核请求 | 会议事件、具体材料、适用程序、发言人 | 让指定 Version 进入正式议程 |
| 与病区联络人讨论统一解释 | 联络人、患者群体、选定 Version、当前事件 | 形成地方口径，可能与其他楼层版本冲突 |

### 后台仍保留

- `propaganda_level` 可作为长期能力或历史积累。
- 思潮、恐慌、受众 belief、怀疑和传播后果。
- 实际受众、材料版本、渠道与覆盖范围。

### 防公式化规则

相同材料、相同渠道、相同受众的重复传播不重复产生完整效果。传播结果必须能追溯到具体受众，不允许按钮一按就让所有部门同时接受同一 Version。

## 5. Incite Rebellion → 推动既有主体在具体时机提出诉求

### 旧入口为什么不成立

“煽动叛乱”把所有平民部门视为一个待点火整体，既没有组织者，也没有诉求、地点和时机，更容易误变成专门反抗组织按钮。

### 新动作族

| 情境动作 | 必要参数 | 直接结果 |
| --- | --- | --- |
| 请 Mechanical 代表在夜班停工前宣读诉求 | 既有代表、具体 demand、班次、现场人群 | 形成一次有主体、有诉求的集体行动 |
| 帮助既有派系公开一项劳动诉求 | 真实派系、当前 demand、材料与公开渠道 | 派系开始公开推动诉求，留下明确归因 |
| 在配给争议中支持工人拒绝一批替代物 | 当前事件、具体批次、在场联系人、诉求 | 形成局部抵制，可能扩散或遭处置 |
| 保护一名公开诉求者到下一时段 | 真实人物、当前威胁、转移/掩护资源 | 改变该人物与集体行动的后续窗口 |

### 后台仍保留

- rebellion、panic、思潮、派系 influence/cohesion 和反制结果。
- 既有结局仲裁读取的真实政治状态。
- 具体主体、诉求、事件和后果链。

### 防公式化规则

没有既有主体和具体诉求时不能执行。不能新造一个专用反抗组织，也不能让一次按钮直接覆盖所有平民。结果范围由实际参与者与传播路径结算。

## 6. Publicize Faction → 在具体公开场合支持既有派系

### 旧入口为什么不成立

“公开派系”忽略谁在公开、公开什么、向谁公开，以及公开后谁承认它。公开身份是政治事件，不是自我声明数值。

### 新动作族

| 情境动作 | 必要参数 | 直接结果 |
| --- | --- | --- |
| 在部门会议上公开支持既有派系诉求 | 真实派系、会议事件、代表/玩家身份、具体诉求 | 派系获得公开受众和正式记录 |
| 通过公开广播确认派系存在与主张 | 派系、广播渠道、主张、实际听众 | 派系进入公共视野，产生支持与反对反应 |
| 公开签署并发布共同声明 | 多个真实签署者、声明文本、发布渠道 | 记录公开联盟和各自责任 |

### 后台仍保留

- `Faction.IsPublic`、Prestige、影响力与后续结局资格。
- 公开范围、公开方式、参与者和事件记忆。
- 公开后的支持、压制、关系变化与门控。

### 防公式化规则

不存在真实派系、具体主张或公开受众时不能执行。公开一次后同一渠道不重复刷威望。派系公开不等于全体居民自动了解或支持。

## 7. STATION_DECEIVE → 向驻地指定链路投放指定伪造材料

### 旧入口为什么不成立

“欺骗驻地”是 operation 名称，不是具体执行动作。必须说明伪造什么、投到哪里、经谁之手、何时会被谁读取。

### 新动作族

| 情境动作 | 必要参数 | 直接结果 |
| --- | --- | --- |
| 把伪造库存记录混入指定配给批次 | 伪造 Observation、Supply 链路、批次、投放窗口 | 下单并记录经手链；到期后按实际读取范围结算 |
| 在维护回报中替换设备状态版本 | 指定 Version、Mechanical/IT 链路、当前维护周期 | 形成延迟 operation，并留下记录不一致风险 |
| 通过已知联系人递交伪造档案 | 联系人、档案、目标读者、交付时间 | 联系人进入经手链，operation 与 Exposure 开始计算 |

### 后台仍保留

- 驻地的延迟 operation、目标恐慌/叛乱/思潮等真实 delta。
- 即时怀疑、结算怀疑、Exposure、反间谍与 operation 状态。
- 伪造内容、投放渠道、经手人、目标读者和失效条件。

### 防公式化规则

没有具体伪造材料、链路和读取窗口时不能执行。目标失效或正典状态不允许覆写时按既有规则处理。不能只把 STATION_DECEIVE 改名“投放”，实际仍不选择材料和渠道。

## 8. STATION_TRADE → 与具体联系人交换具体物品和承诺

### 旧入口为什么不成立

“驻地交易”没有说明交易对象、物品、数量、交付地点和附加承诺。交易不是凭空消耗资源换稳定与威望。

### 新动作族

| 情境动作 | 必要参数 | 直接结果 |
| --- | --- | --- |
| 向 Supply 联系人交付一批物资换取配给掩护 | 联系人、物资批次、仓库、交接窗口、掩护内容 | 资源易主；形成交易记忆；获得具体协助 |
| 用维修零件换取 Mechanical 的停机窗口 | 联系人、零件、设施、窗口、双方条件 | 零件消耗；设施获得维护/操作窗口 |
| 提供药品换取病区代为转交材料 | Medical 联系人、药品、材料副本、最终接收人 | 形成交换与转交链，增加经手风险 |

### 后台仍保留

- Supplies 等资源变化、驻地稳定、威望、关系和 Exposure。
- 延迟 operation、结算怀疑与反间谍。
- 具体交易物、联系人、承诺、交付状态和违约后果。

### 防公式化规则

交易双方、物品和承诺缺一不可。相同资源在不同联系人处不应兑换同一种万能结果。没有实际交付就不能提前增加威望或稳定。

## 9. 总替换表

| 旧按钮 | 新入口的最小粒度 | 后台概念是否可保留 |
| --- | --- | --- |
| Build Network | 人 + 当前问题 + 帮忙方式 + 地点/时机 | 是，作为关系结果 |
| Share Info | 接收人 + Observation + 披露方式 + 用途 | 是，作为材料流转 |
| Gather Info | 设施/事件 + 当前职务 + 实际接触 | 是，作为伴随 Observation |
| Conduct Propaganda | 材料 Version + 受众 + 渠道 + 时机 | 是，作为传播结果 |
| Incite Rebellion | 既有主体 + 具体诉求 + 现场 + 时机 | 是，作为政治后果 |
| Publicize Faction | 既有派系 + 主张 + 公开场合 + 受众 | 是，作为公开状态 |
| STATION_DECEIVE | 伪造材料 + 投放链路 + 读取窗口 | 是，作为延迟 operation |
| STATION_TRADE | 联系人 + 物品 + 承诺 + 交付窗口 | 是，作为交换结果 |

最终验收不看按钮名称，而看执行请求中是否仍有这些参数、结算是否实际读取它们。
