# 信息生产链：从实际行为到 Observation

> 目的：规定“谁在何处经什么行为看到什么”如何进入既有 Fact / Version / Observation 三层，并继续支持出示、核验、公开和委托。
>
> 硬判据：**动作参数必须参与结算，不能只参与文案。**材料的来源、渠道、地点和行为必须决定内容、可靠性、可见范围与后续用途，不能获得随机 ID 后补写来源。

## 1. 三层职责不能混用

```text
Fact：实际发生了什么
Version：某一立场如何解释它
Observation：某个观察者经某渠道得到了哪份材料
Belief：某个主体目前如何相信 Fact 与各 Version
```

- Fact 不由文本生成，也不因玩家相信才成立。
- Version 可以互斥，同一事件可以有官方解释、地方经验和阴谋归因。
- Observation 是玩家或 NPC 实际持有的材料，可靠性与适用范围有限。
- Belief 不由 Observation 正文直接决定，分享和公开还需要受众与传播规则。

## 2. Observation 必须回答的六个问题

| 问题 | 字段 | 结算用途 |
| --- | --- | --- |
| 谁看到 | `observer_ref` | 决定归属、去重、知识访问和后续出示资格 |
| 在哪里 | `source_location` | 限定直接观察范围、传播路径和可核验对象 |
| 经什么行为 | `acquisition_action_id` | 将材料回溯到真实职务/对话/事件，防止凭空获得 |
| 通过什么渠道 | `channel` | 决定材料形式、可靠性、盲点和可用动作 |
| 看到什么 | `fact_id + observation_claim` | 限定它实际支持的命题，不自动给出完整真相 |
| 采用哪个解释 | `version_id + likelihood_scope` | 决定材料支持哪种 Version 及支持程度 |

另需 `observation_id、acquired_at、independence_key、base_text、final_text、disclosure_state`，用于去重、存档、展示和披露。

## 3. 信息生产链

```text
当前事件/设施/联系人提供可观察材料
  → 玩家执行有独立主结果的动作
  → 主行动成功
  → 读取执行者、对象、地点、时机、输入和渠道
  → 过滤当前可观察且未去重的 Fact/Version
  → 形成 Observation
  → 写入 KnownFragments 兼容投影
  → 打开出示、核验、交付、组合、委托等后续动作
```

### 3.1 可观察性先于随机性

只有满足以下条件的事实才进入材料池：

1. 事实已发生或确有历史记录，不是未来剧透。
2. 当前对象、地点和渠道能实际接触其痕迹或转述。
3. 执行者具有理解该材料的最低身份或工具条件。
4. 来源人物/设施仍然存在且能提供材料。
5. 该观察没有命中去重限制。

没有合格材料时不消费 Observation RNG，不生成空卡，也不影响主行动。

### 3.2 渠道决定材料形式

| 渠道 | 材料形式 | 强项 | 天然盲点 |
| --- | --- | --- | --- |
| 巡诊 | 症状、病史、患者叙述 | 身体影响、时间关联、不同楼层版本 | 原始命令、物流全链 |
| 库存/配给 | 申领单、批次、库存差异 | 数量、流向、经手记录 | 最终用途和决策动机 |
| 维修 | 维修单、物理改动、设备异常 | 设施事实、改动时间、技术影响 | 正式解释与命令来源 |
| 对话/证词 | 原话、沉默、矛盾、回避 | 个人经验、立场和关系记忆 | 客观全貌；可能受恐惧影响 |
| IT 日志 | 登录、删除、异常时段 | 系统行为和索引变化 | 离线行为及被清理内容 |
| 正式档案 | 命令、批复、条款、签署 | 程序、官方版本、责任链 | 实际执行是否一致 |

## 4. 同一 Fact 的多版本生产

以“配给变更”为例：

```text
Fact：某批次配给被替换，部分居民出现不适
├─ Version A：这是经过批准的健康管理安排
├─ Version B：这是供应链短缺下的临时替代
└─ Version C：有人借替换掩盖库存亏空
```

不同动作产生不同 Observation：

| 实际行为 | Observation 内容 | 能支持什么 | 不能支持什么 |
| --- | --- | --- | --- |
| Upper 巡诊 | 正式通知和就诊记录 | 官方采用 Version A | 不能证明实际短缺或亏空 |
| Lower 巡诊 | 患者描述替代食物与不适 | 支持身体不适及 Version B 的经验基础 | 不能直接指认责任部门 |
| Supply 核对 | 批次替换和库存差异 | 支持替换发生及物流时间 | 不能单独证明动机 |
| IT 链路维护 | 某条修改记录被删除 | 支持记录被处理过 | 不知道谁实际下令及原因 |

玩家可以逐渐增强对 Fact 的确信，同时仍对 Version C 缺乏证据。材料数量不能自动解决归因问题。

## 5. 材料如何生成后续动作

### 出示

`Observation + 接收人 + 地点 + 时机 + 用途` → 记录接收人看过什么、作何回应。接收人的 access_scope 决定他能否核验或只是转述。

### 组合核验

两份材料只有在参数相容时才能组合：

- 指向同一 Fact 或可连接事实链；
- 时间、地点、批次、人物关系不冲突；
- `independence_key` 不同，避免同一来源转述刷证据；
- 组合命题没有超出各自可靠性范围。

### 交付副本

复制的是材料载体，不是制造新的独立来源。副本保留原 `independence_key`，并新增经手披露记录。

### 转述

转述会生成一条新的传播记录，但不能自动提高事实可靠性。接收人得到的是“某人告诉我”的版本，不是原始现场观察。

### 公开

公开需要实际渠道与受众覆盖。玩家私下高度相信不等于公众已知，更不等于法律证据成立。

## 6. 去重、存档与回放

### 去重

建议键：

```text
observer + fact + version + channel + source scope + acquisition context
```

同一来源重复查看不新增材料、不重复计数、不重复推进门控。不同地点的独立观察可以保留，但必须有真实地点和行为差异。

### 存档

Observation 保存原始预写文本与最终展示文本、来源、获取行动和披露历史。查看时不重新生成，不重新抽版本。

### RNG 与确定性

- 主行动成功后进入固定 Observation 阶段。
- 只有材料池非空且确需选择时才消费现有 RNG。
- 首个里程碑材料应由内容规则保证，不靠反复刷行动。
- LLM 只改变表层文本，不参与材料选择、事实、版本、门控或 RNG。
- 新 hook 实施时建立受控 sim 新基线，同种子双跑验证。

## 7. 界面呈现

行动结果先显示职务主结果，再显示可选材料：

```text
巡诊完成：病区处置已结算。

顺带归档：
《不同版本的配给通知》
Medical · Lower 巡诊 · 患者叙述
支持：通知内容存在地方差异
不能证明：谁决定替换配给
[查看] [稍后处理]
```

行动列表不显示“情报概率”。没有材料时不显示空卡或“本次没有情报”。

档案详情必须能展开来源链：

```text
谁获得 → 何处获得 → 哪个行动 → 原始渠道
→ 支持哪个 Fact/Version → 曾经出示给谁 → 当前谁能使用
```

## 8. 反例与验收

### 反例 A：随机 ID 后补来源

从全局未知池抽到 `Supply_2`，再显示“巡诊时发现”，但 Supply_2 与巡诊对象、地点和事件无关，判失败。

### 反例 B：同一材料无限转述

仓管告诉玩家，玩家告诉 Mayor，Mayor再告诉 Judicial。若每一步都被当成独立证据增加确信，判失败；它们共享来源链。

### 反例 C：出示对象不影响结果

同一材料交给 Judicial 与 Supply 都得到相同接受率和相同思潮变化，判失败。

### 验收

1. 每份 Observation 都能回答六个来源问题，且字段来自实际动作。
2. 同一 Fact 可以保持高确信，同时 Version 仍有分歧。
3. 无合法材料不消耗 RNG、不影响主行动；重复来源不重复计数。
4. 出示、组合、交付、转述和公开产生不同披露与受众结果。
5. 材料文本不能反向修改 Fact、Version、Belief、门控或结局。
