# 界面组织：当前地点的人与物，而不是全局动作目录

> 目的：把对象模型和七元组转成具体界面，规定基础职务、进阶解锁、不可用原因和往返路径。
>
> 硬判据：**动作参数必须参与结算，不能只参与文案。**界面上的对象选择必须进入 ActionInstance；不能只换右侧文字，实际仍提交旧的 `target_dept + global_action`。

## 1. 信息架构顺序

```text
当前地点 / 当前事件
  → 人、设施、物件、材料
  → 选中一个对象
  → 当前可做的 2–4 件事
  → 补齐输入与时机
  → 确认主结果、代价与痕迹
```

五个行动域若继续保留，只能作为次要筛选或档案视图，不能决定玩家每天先看到什么。主视图不再列出全堡所有动作。

## 2. 桌面主界面线框

```text
┌────────────────────────────────────────────────────────────────────┐
│ 当前驻地 · Y124 M2 · 本月剩余行动槽 │ AP │ 怀疑 │ 当前日程         │
├──────────────┬───────────────────────────────┬────────────────────┤
│ 地点/事件    │ 当前对象                      │ 对象详情与动作     │
│              │                               │                    │
│ F76–80 病区  │ [当前事件] 集中就诊          │ 病区联络人         │
│ F81–90 仓库  │ [设施] 诊疗点                │ 当前：集中就诊     │
│ F121–135机械 │ [联系人] 病区联络人          │ 记忆：曾协助巡诊   │
│              │ [物件] 药品申领箱            │                    │
│              │                               │ [进行巡诊]         │
│              │                               │ [核对药品申领]     │
│              │                               │ [询问患者说法]     │
│              │                               │ [隔离病区·未解锁]  │
│              │                               │                    │
│              │                               │ 选择后显示七元组   │
└──────────────┴───────────────────────────────┴────────────────────┘
```

- 左栏是地点与事件，不是动作类别。
- 中栏对象按“当前需要处理”排序，已解决和无新内容对象降低优先级。
- 右栏先显示对象状态与记忆，再显示动作；不是先显示按钮再随便选目标。
- 同屏动作保持少量，更多动作通过具体输入扩展，例如“出示材料”进入材料选择，而不是常驻显示几十项。

## 3. 对象详情与动作草稿

```text
向 Judicial 调查员出示材料
├─ 对象：调查员（案件负责人）
├─ 地点：Judicial 办公室
├─ 时机：本案未结案
├─ 输入：[异常申领单 ▾]
├─ 主结果：核验物流异常；记录本次披露
├─ 代价：AP + 当前时间片
└─ 痕迹：调查员记住材料来源；可能追问经手路径
[取消] [确认出示]
```

所有字段从当前上下文带入，玩家只补必要输入。地点、对象、时间若由系统继承，应显示但不必重复下拉。

## 4. 基础职务怎么呈现

基础职务不是全局常驻按钮，而是**对象满足条件时总会出现的基础能力**。

| 条件 | 界面表现 |
| --- | --- |
| Medical 身份 + 病区 + 当前就诊问题 | 诊疗点上出现“进行巡诊” |
| Mechanical 身份 + 设施故障/维护窗口 | 设施上出现“检修当前问题” |
| Supply 身份 + 配给批次待处理 | 仓库上出现“核对并分配本批物资” |
| 没有当前工作对象 | 不显示空泛“履职”，显示设施状态和需要等待/寻找的问题 |

基础职务仍受 AP、工具、地点和时段限制。常驻指能力身份稳定，不是无条件可点。

## 5. 解锁行动怎么呈现

解锁行动出现在**同一对象的候选动作中**，并显示来源。

```text
诊疗点
✓ 进行巡诊 · 基础职务
! 隔离病区 · 已解锁，当前缺少正式公共卫生事件
  来源：完成首次巡诊
```

- `LOCKED` 默认不占主列表；只在与玩家已知路线相关时显示“能力线索”。
- 新解锁时在原对象上出现一次“新动作可用”标记，不弹到无关的全局目录。
- `UNLOCKED` 灰项显示当前缺项，不能写成仍未解锁。
- 条件回落只灰置，不重新隐藏。
- 已解锁来源可回看，但不要求所有历史都在首版补建。

## 6. 材料档案如何使用

档案不是第二个 Share Info 按钮列表。每份 Observation 显示：

1. 来源与可靠性范围；
2. 关联 Fact/Version 和已知对象；
3. 当前可出示、核验、交付或组合的具体动作。

```text
《异常申领单》
[向 Judicial 调查员出示]
[与同批次维修单组合核验]
[归还 Supply 仓管]
[查看披露历史]
```

没有当前合法接收人时，不显示通用分享按钮，只说明缺少什么对象或时机。

## 7. 当前事件如何使用

事件卡展示“发生了什么、谁参与、何时变化”，点击后定位对象：

```text
配给争议 · 下次交接时推进
涉及：Supply 仓管 / 异常批次 / Lower 病区
[查看批次] [前往仓库上下文] [查看患者说法]
```

不提供“解决事件”万能按钮。每个处理动作仍需具体对象、材料与结果。

## 8. 往返与不迷路

- 从对象进入材料选择，取消后回到同一对象。
- 从档案进入接收人，完成后返回该 Observation 的披露历史。
- 从事件进入设施，返回时保留事件与楼层。
- 执行成功后保留对象，已解决动作消失或变为已读，新结果按优先级出现。
- Esc 先取消草稿，再关闭对象详情，最后返回地点，不直接清空全部上下文。

## 9. 小窗口

```text
[地点] [事件] [对象] [档案]
当前：F76–80 病区 / 诊疗点
────────────────
集中就诊
病区联络人 · 曾协助巡诊
[进行巡诊]
[核对药品申领]
[更多对象]
────────────────
AP / 时间 / 怀疑
```

小窗口改为单栏对象流，不把所有动作塞进底部固定栏。当前对象和返回路径始终可见，执行按钮与主结果、代价一起固定到底部草稿。

## 10. 反例与验收

### 反例 A：对象化外壳，旧全局提交

界面先选联系人，提交时仍只发送 `action_type=BUILD_CONNECTION&target_dept=Supply`，没有联系人、当前问题、材料和记忆，判失败。

### 反例 B：按钮换位置，不换内容

把原来的八个全局按钮从右侧移到楼层弹窗，参数与结果完全不变，判失败。

### 反例 C：对象菜单爆炸

每个对象固定显示十几个动作，大多长期不可用。应优先显示当前可做的少量动作，其余按输入和状态展开。

### 验收

1. 首屏主要是当前地点的人与物，无全局 Build/Share 按钮。
2. 任一执行请求都能还原完整七元组。
3. 基础职务与解锁动作在同一对象上有明确区别。
4. 材料、事件和对象之间往返不丢失选择。
5. 小窗口仍能完成选对象、补输入、看代价、执行和返回。
