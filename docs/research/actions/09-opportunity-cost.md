# 机会成本与情境约束：时间、地点、身份和 NPC 日程

> 目的：限制“全部点一遍”的公式化行为，同时避免把耗时和不可回退误当深度。
>
> 硬判据：**动作参数必须参与结算，不能只参与文案。**时间、地点和身份必须改变可选动作、结果或后续世界状态，不能只增加等待和文字说明。

## 1. 可用动作的统一判定

```text
eligible = actor qualification
         AND target exists and is appropriate
         AND location/access is valid
         AND timing window is open
         AND required inputs are present
         AND event has not already resolved
         AND resource/time cost is payable
```

每个条件都要给出具体不可用原因。不要用一个“剧情条件未满足”覆盖所有情况。

## 2. 时间：让选择互相排斥

### 2.1 行动槽与时段

玩家在一个时间片内只能选择有限行动。选择巡诊就意味着不能同时完成全网检修或参加另一场会面。行动槽是抽象调度，不要求主角手动走楼。

| 时间参数 | 结算作用 |
| --- | --- |
| `start_window` | 决定动作何时可开始 |
| `duration` | 决定占用哪个行动槽和事件推进次数 |
| `resolve_at` | 决定主结果、材料和痕迹何时生效 |
| `expiry` | 决定过期后的替代路径或失效 |
| `exclusive_with` | 明确不能并行的行动和日程 |

### 2.2 时间不能只做惩罚

有效时间压力应带来：

- 先处理哪个对象的真实选择；
- 不同时间能遇到不同人、材料与事件；
- 可预期的行动后果和至少一条替代路径。

无效时间压力只是让玩家多等动画、重复同样动作或错过唯一窗口后死档。

## 3. 地点：决定对象、材料和风险

地点至少影响一项：

1. 能遇到谁、使用什么设施；
2. 能直接观察什么，材料来源如何标记；
3. 谁能目击行动、信息如何传播；
4. 哪些权限、工具或身份要求生效；
5. 哪些部门和人群受到主结果。

```text
Upper 巡诊：正式通知与决策层患者
Lower 巡诊：基层患者、替代配给经验、另一套 Version
```

如果只是背景楼层名不同，患者池、材料池和结果完全一样，地点没有参与结算。

## 4. 身份：限定合理能力，而非提供全局加成

| 身份维度 | 正确作用 | 错误作用 |
| --- | --- | --- |
| 职业 | 看懂专业记录、执行基础职务、使用专业设施 | 任意对象都获得高成功率 |
| 公开身份 | 决定合法准入、官方话题、被怀疑方式 | 一键通行所有区域 |
| 背景/特质 | 增加特定情境选项或解释角度 | 代替材料和权限 |
| 联系人权限 | 允许转交、核验、委托某类事项 | 把个人许可扩大为全部门许可 |
| 工具与许可 | 打开具体设施、物件和程序 | 永久解除所有风险 |

身份条件必须由后端校验，不能由前端根据职业字符串自行放行。

## 5. NPC 日程：只模拟有玩法价值的人

不需要全堡居民都拥有日程。只为能改变玩家选择的真实联系人维护少量日程：

| 字段 | 用途 |
| --- | --- |
| `person_id` | 与真实联系人及记忆关联 |
| `location_schedule` | 何时在哪个 zone/设施，未知时可只给模糊范围 |
| `availability_windows` | 可交谈、交接、巡诊、会议等窗口 |
| `commitments` | 他自己的任务、委托和事件 clocks |
| `interruptions` | 临时离席、审查、伤病、设施事故 |
| `alternate_contact` | 错过后的转交、留言、材料路径或其他联系人 |

玩家看到的信息可以不完整，但后端必须使用真实日程，不能为了制造难度临时随机让 NPC 离开。

## 6. 世界 clocks 与玩家选择

每个 clock 必须回答：

1. 谁在推进？
2. 当前进展是什么？
3. 玩家能看到哪些迹象？
4. 玩家能在哪些节点干预？
5. 不干预会发生什么，是否有替代路径？

```text
配给争议
├─ 下一次交接：异常批次将被签收
├─ 交接前可核对单据 / 联系仓管 / 通知病区
└─ 交接后仍可追查库存，但无法再阻止本批签收
```

clock 不应只是“剩两个月，失败”的倒计时文本。

## 7. 替代路径与防死档

每个关键目标至少保留两类路径：

| 目标 | 直接路径 | 替代路径 |
| --- | --- | --- |
| 找到联系人 | 在交接时到场 | 通过工作记录、转交材料或另一联系人 |
| 核验异常 | 当面出示单据 | 与同批次记录组合核验 |
| 进入设施 | 获得正式许可 | 申请陪同、远程处理或承担违规风险 |
| 完成委托 | 在窗口内履行 | 接受延期后果并开启补救事件 |

替代路径可以有更高成本或不同后果，但不能只是同一全局函数换个入口。

## 8. 约束公式化点击的有效手段

### 8.1 已完成内容退出主列表

已核对批次、已读材料、已解决事件不再提供相同收益按钮，只保留历史与后续问题。

### 8.2 对象状态变化

行动后设施恢复、联系人日程改变、材料披露状态更新，下一次面对的不是同一菜单。

### 8.3 行动互斥

有限时间片使“全点一遍”必然放弃某些对象。选择必须基于当前目标与材料，而不是无成本扫图。

### 8.4 关系记忆

同一联系人不再对重复帮助和重复出示提供完整收益，新的进展需要新的问题或材料。

### 8.5 多条情境路线

不同职业和材料可以从不同对象达到目标，避免只找唯一最高收益按钮。

## 9. 风险边界

- 不通过实时等待拖长游戏。
- 不让关键任务只有一个不可逆时刻。
- 不用不可预测的 NPC 离席反复惩罚玩家。
- 不因为玩家没按作者预想顺序点击就锁死主线。
- 不用高失败率迫使重复同一动作。
- 不让所有行动都带时间压力；普通职务应允许玩家理解和规划。

## 10. 反例与验收

### 反例 A：耗时伪深度

两个动作只有持续时间不同，等待后调用同一个全局结果，判失败。

### 反例 B：日程只是拒绝提示

NPC 是否出现完全随机，玩家无法预知、准备或替代接触，判失败。

### 反例 C：身份只是文字

Medical 与 Mechanical 点击同一设施，虽然按钮名称不同，但权限、输入和结果完全相同，判失败。

### 验收

1. 时间、地点、身份和日程各至少改变一个真实结果。
2. 同一时段不能无成本完成所有动作。
3. 关键目标存在可解释的替代路径。
4. 玩家能在执行前知道主要时间窗口和不可逆点。
5. 重复同一对象与话题不会继续提供完整收益。
