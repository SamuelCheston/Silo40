# 动作七元组：字段定义与结算职责

> 七元组：执行者、对象、地点、时机、输入、即时结果、代价与痕迹。
>
> 硬判据：**动作参数必须参与结算，不能只参与文案。**七元组不是展示模板，而是动作校验、结算、存档和回放的统一输入。任何字段若只用于生成按钮描述，不属于有效实现。

## 1. 动作模板与动作实例

必须区分：

- **ActionTemplate**：作者定义的动词模板，例如“巡诊”“出示材料”“检修设施”。
- **ActionInstance**：玩家在某次上下文中绑定完整七元组后的可执行动作。

```text
模板：出示材料
实例：玩家特工 → Judicial 调查员 → Judicial 办公室
      → 本案未结案 → 异常申领单 Observation
      → 核验物流并记录披露 → AP/来源追查
```

模板可以复用，实例不能直接复用。相同模板在不同对象上必须重新求值。

## 2. 字段一：执行者 `actor`

### 定义

执行动作的真实主体。当前主要是玩家特工，但未来 NPC 行动也应使用同一结构。

| 子字段 | 结算职责 |
| --- | --- |
| `actor_id` | 决定谁的 AP、材料、关系和记忆被修改 |
| `profession` | 决定基础职务、专业理解和设施权限 |
| `traits/background` | 只修饰符合条件的情境，不提供全局万能加成 |
| `current_identity` | 当前公开身份与掩护，决定门禁、话题和怀疑 |
| `resources` | AP、工具、物品、材料等实际可用输入 |
| `location_ref` | 决定是否能到场或需要委托他人 |

### 失败反例

按钮写着“Medical 巡诊”，实际却不校验执行者职业、药品、身份或地点，任何职业都得到相同结果，则执行者字段未参与结算。

## 3. 字段二：对象 `target`

### 定义

动作直接作用的 Person、DepartmentContact、Facility、Item、Material 或 CurrentEvent，必要时可有主次对象。

```text
primary_target：被出示材料的人
secondary_target：被出示的材料
```

| 子字段 | 结算职责 |
| --- | --- |
| `type + id` | 决定能力模板、状态读取和结果写入位置 |
| `state` | 决定当前是否可行动及实际分支 |
| `access_scope` | 决定对象能提供或接受什么 |
| `memory_ref` | 决定此前互动如何改变本次结果 |
| `consequence_scope` | 明确谁会受到主结果与后续影响 |

### 失败反例

玩家选择具体联系人，执行时却把目标转成全局 `DEPT`，使同部门任何联系人都得到相同记忆，则对象被 UI 伪装了。

## 4. 字段三：地点 `location`

### 定义

动作实际发生的地点。可以从对象继承，不要求玩家重复选择。

| 子字段 | 结算职责 |
| --- | --- |
| `silo_id` | 确定材料、人物、事件和规则所属世界位置 |
| `floor_id/zone` | 确定行动范围、传播路径、准入和材料来源 |
| `facility_id` | 确定当前设施状态和可用功能 |
| `access_policy` | 决定合法进入、违规进入或远程处理 |
| `local_conditions` | 封锁、恐慌、停电、日程等现场条件 |

### 失败反例

按钮写“Lower 巡诊”，材料却标为 Upper，且没有权威移动或转述链；或者同一动作在任何楼层产生完全相同的设施结果，都是地点未参与结算。

## 5. 字段四：时机 `timing`

### 定义

动作何时可开始、持续多久、何时结算、与哪些窗口冲突。

| 子字段 | 结算职责 |
| --- | --- |
| `available_window` | 联系人是否在岗、事件是否未结束、设施是否开放 |
| `start_time` | 与 NPC 日程、其他 operation 和事件排序 |
| `duration` | 占用哪个时间片，期间哪些行动不能并行 |
| `resolve_at` | 主结果、材料、痕迹分别何时生效 |
| `expiry` | 过期后动作是失效、改变分支还是进入替代路径 |

### 失败反例

只把 `duration_months` 显示在按钮上，却不推进时钟、不改变 NPC 日程、不占用互斥行动槽，则时机只是文案。

## 6. 字段五：输入 `inputs`

### 定义

动作消耗的物件、材料、工具、权限、话题或选择。输入可以多个，但必须各自参与校验或结果。

| 输入类型 | 例子 | 结算职责 |
| --- | --- | --- |
| Observation | 异常申领单、患者证词 | 决定可讨论的事实、版本、可靠性和披露对象 |
| Item | 药品、门卡、维修零件 | 决定能否执行、是否消耗、交付后持有者 |
| Tool | 维修工具、存储介质 | 决定设施动作和替代路径 |
| Permission | 搜查令、停机许可 | 决定合法性、痕迹和对象反应 |
| Topic | 某次事故、某项诉求 | 限定对话与记忆，避免“随便聊聊” |
| Choice | 接受、拒绝、隐瞒、公开 | 写入不同事件键并产生不同后续 |

### 失败反例

玩家选了具体 Observation，执行时却只检查 `known_fragments >= 1`，随机接受另一份材料，则输入没有参与结算。

## 7. 字段六：即时结果 `immediate_result`

### 定义

动作成功时直接发生的主结果，不包含未来的延迟后果。

| 结果类别 | 例子 |
| --- | --- |
| 设施/资源 | 设备恢复、库存变化、病区处理完成 |
| 对象状态 | 联系人交付物件、患者接受处置、设施解除停机 |
| 关系记忆 | 记录一次帮助、一次质疑、一次材料披露 |
| Observation | 由实际接触生成材料，可为空 |
| 事件状态 | 推进当前事件、打开下一节点、关闭已解决分支 |
| 门控 | 解锁新对象选项或改变实时可用状态 |

主结果必须在动作按钮上可理解。伴随 Observation 不应取代职务主结果。

### 失败反例

按钮写“修复冷却泵”，实际只增加政治威望，设备状态没有变化，则即时结果与动作语义不一致。

## 8. 字段七：代价与痕迹 `costs_and_traces`

### 定义

执行动作所付出的成本，以及谁在何时知道玩家做过什么。

| 子字段 | 结算职责 |
| --- | --- |
| `ap_cost` | 从实际执行者扣除，执行前与执行时两次校验 |
| `time_cost` | 占用时间片并推动相关 clocks |
| `input_consumption` | 物件耗尽、权限使用、材料披露，而非一律消耗材料 |
| `suspicion_delta` | 特工全局怀疑，按动作、对象和身份计算 |
| `exposure_delta` | 写入对应 operation track，不与怀疑混合 |
| `witnesses` | 谁在场、谁经手、谁能转述，决定后续追查路径 |
| `memory_events` | 对象记住什么，何时记住，是否公开 |
| `delayed_hooks` | 何时产生后续事件，不能用即时文案提前宣称已发生 |

### 失败反例

动作写“秘密交付”，实际却向全堡广播；或者显示零痕迹，实际有见证人却没有记录，均判失败。

## 9. 七元组的统一数据结构

以下是设计结构，不要求原样落代码：

```text
ActionInstance
├─ actor: ActorRef
├─ target: ObjectRef + optional secondary targets
├─ location: LocationRef
├─ timing: Window + Duration + ResolveAt
├─ inputs: ObservationRef[] + ItemRef[] + PermissionRef[] + ChoiceRef
├─ immediate_result: ResultSpec
└─ costs_and_traces: CostSpec + WitnessSpec + TraceSpec
```

`ObjectRef` 必须包含 type 与稳定 ID；`LocationRef` 只允许权威楼层或 zone；`ResultSpec` 不允许引用不存在的“全功能”。

## 10. 结算顺序

```text
1. 绑定：从当前对象生成实例，不接收前端自造的权限和结果
2. 校验：七元组逐项验证，收集具体不可用原因
3. 预留：锁定 AP、物件、窗口和事件防重入状态
4. 主结算：应用职务/物件/对话主结果
5. 伴随结算：按固定顺序处理 Observation、关系记忆、见证和痕迹
6. 时钟与事件：推进 duration，调度延迟结果，写完成事件键
7. 门控：重新计算对象选项与可用状态
8. 呈现：返回主结果、可选材料、关系变化和实际痕迹
```

任何一步失败都不能靠另一套全局函数补上相同结果。需要随机选择时，应在主行动成功后、固定阶段消费现有 RNG；无合法材料时不消耗 Observation RNG。

## 11. 同一模板的两个实例对照

```text
A：向 Judicial 调查员出示异常申领单
B：向 Supply 仓管出示异常申领单
```

| 字段 | A | B |
| --- | --- | --- |
| 对象权限 | 能判断程序与法律用途 | 能核对库存和经手记录 |
| 即时结果 | 打开案件核验或追问来源 | 确认批次、补充经手信息 |
| 关系记忆 | “玩家提交过案件材料” | “玩家归还/核对过单据” |
| 材料变化 | 增加司法披露记录 | 增加部门内核验记录 |
| 后续事件 | 审查、正式核验或来源追查 | 库存修正、委托或物流线索 |

二者可以共享“出示材料”模板和底层披露 primitive，但不能得到同一全局结果。

## 12. 字段验收清单

- 执行者：换成无权限身份，动作会失效或改变结果。
- 对象：换成另一联系人/设施，结果或记忆会不同。
- 地点：换楼层/zone，材料来源、传播或设施状态会不同。
- 时机：错过窗口，动作进入明确失效或替代路径。
- 输入：换材料/工具/权限，可用性和结果不同。
- 即时结果：按钮承诺的主结果真实写入状态。
- 代价与痕迹：AP、时间、见证、披露和 Exposure 都有正确归属。

任一列只在 UI 文案中不同，都不能算七元组落地。
