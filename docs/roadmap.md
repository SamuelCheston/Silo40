### 逃出群体与《越岭》逃离模型

**状态：未实装（用户裁决：本轮不做）。** 最小状态基础已随结局链机制底座落地（`Silo.EscapedGroup`、`escape_group_depart/status` 效果、仲裁对幸存群体的例外读取）；但完整逃离模型比现有事件链所写的复杂得多，需要单独设计：

- 路线事实（先遣往返、接应点、可重复通行）与分批撤离的组织结算；
- 堡外存续判定（物资、照护、组织与"明天"的持续条件）；
- 逃出群体与原驻地的后续关系（回传、沉默或原驻地毁灭后的独立存续）。

设计完成前，事件链中一切依赖逃离模型的节点只以注释预留，不写成看似可运行的内容；仲裁侧继续以最小状态基础结算《越岭》资格与硬失败例外。准备侧（逃跑前的防护服、补给、预案等投入如何换算为逃离成果）的机制设计已完成，见 [16-preparation-outcome-design.md](research/16-preparation-outcome-design.md)；其账本字段与结算级联契约是逃离模型主体的输入接口。

### 《共证》外溢准备工作

**状态：未实装（用户裁决：本轮不做）。** 裁决口径：**外溢不进胜负判定——外溢为零同样可以判胜，外溢数量只影响结算分数**（仲裁已按此实现：出站信号到达的不同地堡数只进《共证》加权，不进资格）。外溢准备工作与逃离模型同样复杂，需要单独设计：

- 受限渠道的选择与建立（专线、跨堡信号、实体交接各自的因果与风险）；
- 外部接收方的独立核验与再复制结算（跨堡编排、接收堡模拟状态与"独立复制一代"的判定）；
- 外溢暴露与宿主风险的结算（异常流量、可操作观察与处置升级）。

设计完成前，《共证》资格只读本地活链与跨部门公共事实；外溢相关节点只以注释预留。准备侧（受限信道、包裹质量与暴露代价如何换算为外溢触达与接收）的机制设计已完成，见 [16-preparation-outcome-design.md](research/16-preparation-outcome-design.md)；外溢维持既有裁决口径，只影响结算分数，不进资格。

### IT 幕后威势、Order 与 Judicial 三方附着

**状态：设计完成，尚未实现。** 公式、原著边界、验收与 `TODO(balance)` 目标见 [10-it-control-credibility.md](research/10-it-control-credibility.md)。

1. **威势与 Judicial 骨架**：实现 `W/S/F/A/T`、Mayor/pact 两档开门、个人附着回摆、pact 锁定与存读档；功能关闭保持 parity。
2. **碎片与检测**：实现获取概率、连续 `B/π`、观察去重和 `UNSAMPLED/SAMPLED/DIRECT_ORDER`；矿工结构性不采样，AP 与怀疑独立。
3. **分层曝光与公开证据**：实现部门/具名人物 belief、`E/Q` 和两份独立法警调度公开证据链，杜绝私下确信直接加曝光。
4. **Order 与 Silo 1 认知**：加载版本化条款，实现违反/未贯彻/未达成、 believed/true 副本、主任认知 `G` 及稀有可预警介入。
5. **二元联盟与隐蔽维护**：仅接入 Judicial 法警和 IT 内部，落实有限 `R_op`、弱势成本曲线、七类隐蔽动作、双动机 utility 和资源枯竭反击衰减。
6. **玩家拆台路线**：接调查、执行失败、核验、公开发布和 IT 反击，按首档 4–5 次有效操作、pact 累计 8–10 次的 `TODO(balance)` 目标校准。
7. **法治结局与批量验证**：新增以 `pact_locked` 为资格条件、仍由四类主体加权的 `RULE_OF_LAW` 候选；补齐动机/介入/证据/附着解释，跑熟练策略、回摆、pact→法治结局、Order 偏离和 Safeguard 竞赛，验证确定性与 Silo 18 正典 parity。

### LLM 上下文档位可调

**状态：待做，尚未实现。**

允许用户调整喂给模型的上下文档位，与已有的 LLM 参与度档位正交：参与度决定“什么时候问”，上下文档位决定“问的时候给多少料”。

| 档位 | 上下文内容 |
| --- | --- |
| 极简 | 仅当前 NPC、候选动作、输出契约 |
| 标准 | 在极简基础上，加地堡大局指标、相关派系人物、近期事件摘要 |
| 丰富 | 在标准基础上，再加本堡主线经过 |
| 世界观 | 在丰富基础上，再带 silo 设定、其他地堡关系、长期剧情线 |

档位之外保留独立开关或配置项：个人记忆、条文法规、事件摘要条数、是否携带其他地堡情报。

动机：预算紧张的用户可压到很小的上下文，预算宽裕的用户可放开上下文，在成本与决策信息丰富度之间自行取舍。
