# 《共证》收束段与终局呈现设计

> [返回总索引](../silo40-endings.md) · [节点设计](./23-information-nodes.md) · [字段级规格](./24-information-event-spec.md)
> 性质：设计文档＋本批可直接落地的内容。凡依赖未落地机制（暴露水位 E 可读、完成键可逆）之处，只留注释指向依赖，不假装已实现。碎片淡忘已实现（恒定淡忘系数，17 号经济文档 §3）。
> 口径：终局叙事按原书口径书写，不引入影视改编的人名与设定。

## 1. 收束段：P-1 点亮之后到终局判定

P-1（跨部门公共事实）点亮不是终点，而是进入**收束段**：真相已经站住，剩下的是让它活过结算。

### 1.1 还需要什么条件

| 条件 | 读什么 | 现状 |
| --- | --- | --- |
| 宿主活到结算 | 驻地未被毁灭（无 DEATH 事实）、未被重置（无 `reset_completed`） | 既有仲裁口径，直接可用 |
| 活链未被掏空 | 核心复制者未整体离开（否则转《越岭》事实） | 既有仲裁口径 |
| 公共事实未被拆除 | 登记与信念层未被清洗清零 | 部门信念层按恒定淡忘系数衰减（已实现，17 号经济文档 §3）：流通跑赢淡忘，覆盖才维持在门槛之上；清洗/重置直接拆除 |

### 1.2 玩家此时能做什么

- **维持宿主**：资源、楼层稳定度、恐慌管理，全部走既有职务与情境化动作；收束段不新增按钮。
- **控制偏离**：不把叛乱推过 0.8（喂大侦察与整肃链），不在通牒后新增高暴露动作。
- **反制**：渠道反制按分渠道结算（干扰远程终止不免疫物理手段），见《寂堡》链。
- **外溢准备**：预留，roadmap；收束段不实装。

### 1.3 错失窗口会怎样

结算不等人：窗口走完或结算条件满足即进仲裁。

| 错失形态 | 结果 |
| --- | --- |
| 宿主在结算前被毁／被重置 | 按《遗忘》《寂堡》等硬失败结算；公共事实成立过也不追授 |
| 活链停滞、制度收束抢先 | 《公议》（约章锁定）或《人治》（警察服从＋正统性）按事实成立 |
| 什么都没保住 | 《深闭》：默认落点 |

### 1.4 收束段节点：守夜

`events/special/info_vigil_eve.js`（本批落地）：P-1 已亮、叛乱未过 0.8 时点亮一次。它是纯叙事节点：告诉玩家链已经自转，剩下的事情是守住宿主到结算。无机制效果（`apply` 返回空），不引入数值。

点亮窗口有二（修复4）：

- **最后一年**：相对 Y7（代码 `year ≥ 129`）——原口径。
- **铺垫窗口**：结局在信念门槛满足的当月即结算，快线到不了 Y7；因此当部门信念覆盖距门槛不足一个部门（缺 ≤3 份事实，`TODO(校准)`）时提前点亮，作为结局到来前的铺垫。时点判定在 `canTrigger` 中读部门信念层（24 号规格 §3 的 department-belief readability 已随修复4落地）。

## 2. 终局叙事：落回现有判定输出

### 2.1 现状问题

终局画面只有一行公式：`VictoryStatus.Description` 被写成"多主体终局仲裁：X。P2 加权：得分…达到最低分…"。`weighted_endings.go` 里的 `endingDescriptions` 叙事表早已写好，但从未被使用（死代码）。

### 2.2 落点（不新造机制）

- `resolveWeightedEnding` 选出主结局后，把 `decision.Reason` 设为 `endingDescriptions[Selected]` 的叙事文本；《共证》另附外溢结算行（§3）。
- 引擎侧 `applyWeightedEnding` 把 `VictoryStatus.Description` 设为 `decision.Reason`（为空时回退旧公式串）。
- 前端无需改动：既有界面已经渲染 `victory_status.description`。
- P0 硬失败保留既有审计语句（它们本身是可读句子，不是公式）。
- 审计不损失：分数、贡献、资格池、排除原因仍在 `EndingDecision` 的结构化字段里，决策面板照常渲染。

### 2.3 触发方式

`victory_check` 请求终局评估 → 仲裁选中 `INFORMATION` → 叙事写入 `Reason` → 引擎写入 `Description` → 终局画面显示。没有新触发器、没有新展示通道。

### 2.4 《共证》终局文本（原书口径）

> 核心真相已经成为跨部门、可独立复核的公共事实：它有了自己的来源说明、自己的核验路径、自己的保管人。你的沉默、离开或失忆，都不再能把它收回——链不再需要你，这正是任务要的结果。驻地之外是否有人接过这份事实，只写进结算，不改变这个结局。《共证》成立。

文本不出现任何人名：特工、接收者、驻地都是功能位。外溢结算行按 §3 动态追加。

## 3. 外溢评分簇的呈现

外溢不进胜负判定（裁决）。呈现原则：**送出去多少、到了几个堡，作为结算信息可见**。

- 仲裁在《共证》叙事末尾追加一行：`本局共有 N 条信号送出驻地，到达 M 座他堡。`（N 取驻地来源的出站信号总数，M 取 `spilloverSiloCount`。）
- N=0 时写：`本局没有信号送出驻地——外溢为零，不影响本次裁决。`
- 加权明细（`PlayerPerSpilloverSilo` 贡献）已在决策审计的贡献列表里，面板可查。
- 信道、包裹、独立接收的细节呈现等外溢模型（roadmap），本轮不做。

## 4. 留存与再玩

### 4.1 结局之后玩家看到什么

1. **终局叙事**（§2.4）＋外溢结算行。
2. **决策面板**：六个候选的分数、四类主体贡献、资格池与排除原因——"为什么是这个结局"完全可查。
3. **链的痕迹**：本局点亮的节点与"被事实锁定"的分支（树呈现待 UI 批次，本轮以决策审计与事件史为准）。

### 4.2 缺什么信息会让人想再开一局

再玩动力来自**看不见的东西**，不来自解锁项：

- **接收者的明天**：链在玩家缺席后继续成立，但玩家看不到之后发生什么——结局文本只写到结算瞬间。另一局可能看到同一种子之外的另一种承接方式。
- **外部回声**：送出去的信号是否被接收、被谁接收，本局不揭晓（残余应答母题：应答不等于建制恢复，也不许诺）。
- **没走的路**：被锁定的分支保留"被事实锁定"的痕迹——互斥点另一侧的世界只能重开一局去看。
- **另一座驻地**：不同种子、不同驻地、不同锚点节奏，同一棵树长出不同的形状。

### 4.3 明确不做

不做成就解锁项、不做跨局成长（meta-progression）、不做结局图鉴收集——本轮都不在树上。
