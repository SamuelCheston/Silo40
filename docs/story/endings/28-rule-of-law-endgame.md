# 《公议》收束段与终局呈现设计

> [返回总索引](../silo40-endings.md) · [节点设计](./26-rule-of-law-nodes.md) · [字段级规格](./27-rule-of-law-event-spec.md)
> 性质：设计文档＋本批已落地的内容。沿用 [25《共证》收束段与终局呈现](./25-information-endgame.md) 的格式与纪律。
> 口径：终局叙事按原书口径书写，功能位、无人名；锁定是单向事实（引擎保证）；结算行只报事实，不作胜负。

## 1. 收束段：K-1 点亮之后到终局判定

锁定日（K-1）点亮不是终点，而是进入**收束段**：约章已经锁进程序，剩下的是让驻地带着它走到结算。

### 1.1 还需要什么条件

| 条件 | 读什么 | 现状 |
| --- | --- | --- |
| 宿主活到结算 | 驻地未被毁灭（无 DEATH 事实）、未被重置（无 `reset_completed`） | 既有仲裁口径，直接可用 |
| 约章锁定未被撤销 | 无此风险：`PactLocked` 是单向事实，Mayor 更替与普通威势回升不撤销（引擎保证，[authority.go](../../../internal/engine/authority.go) `resetJudicialForNewMayor`） | 不需要玩家维持 |
| 公共事实底座未被拆除 | 登记与司法信念层未被清洗清零 | 与《共证》同忧：清洗/重置直接拆除；信念层按恒定淡忘系数衰减，流通跑赢淡忘才维持 |

### 1.2 玩家此时能做什么

- **维持宿主**：资源、楼层稳定度、恐慌管理，全部走既有职务与情境化动作；收束段不新增按钮。
- **控制偏离**：不把叛乱推过 0.8（喂大侦察与整肃链）；清洗链是约章底座的唯一现实威胁，反制走《遗忘》链的反制完成键。
- **继续喂证**：流通不停，司法层信念与 Q 不掉——锁定虽不可逆，但结算时的证据底座数字（§3）反映的是收束段结束时的状态。

### 1.3 错失窗口会怎样

| 错失形态 | 结果 |
| --- | --- |
| 锁定日前宿主被毁／被重置 | 按《遗忘》《寂堡》等硬失败结算；P0 护栏先于制度成就 |
| 锁定窗始终未开（W 未降） | 约章锁不定：K-1 不点亮，线停在起草；按实际权力状态滑向《人治》或《深闭》。**依赖**：W 离散负冲击通道（并行轨）落地后此窗才有稳定打开路径 |
| 锁定完成但《共证》也成立 | 两候选同池；同分时《共证》优先（既有 P3 顺序），约章作为制度尾声候选 |

## 2. 终局叙事：落回现有判定输出

### 2.1 落点（不新造机制）

与《共证》同一链路（25 号文档 §2.2 已接通）：`resolveWeightedEnding` 选出主结局后把 `decision.Reason` 设为 `endingDescriptions[Selected]` 的叙事文本，《公议》另附约章证据底座结算行（§3）；引擎侧 `applyWeightedEnding` 把 `VictoryStatus.Description` 设为 `decision.Reason`；前端无需改动。

### 2.2 触发方式

`victory_check` 请求终局评估 → 仲裁选中 `RULE_OF_LAW`（资格读 `Judicial.PactLocked`，既有）→ 叙事写入 `Reason` → 引擎写入 `Description` → 终局画面显示。没有新触发器、没有新展示通道。

### 2.3 《公议》终局文本（原书口径）

> 裁决依据从隐蔽命令与个人正统性转向了可公开复核的规则。第一次按约章裁决的案件里，裁决者引用约章与公开证据，而不是等待上级指示；隐蔽调度不再能进入执行——法警第一次问"依据哪一条"。约章有本地主人，以不可被单方收回的程序锁定；你坐在旁听席，不在裁决席。约章法庭迟早会遇到一个它回答不了的问题——"这条命令到底从哪里来"——答案通向专线与控制网的另一端，但本结局停在这个问题被第一次提出之前。《公议》成立。

文本不出现任何人名：特工、裁决者、法警都是功能位。诚实余波（剧情台阶 01 §3 的必写项）已含在内：约章种下《共证》的问题，但不回答它；结局停在问题被第一次提出之前。证据底座结算行按 §3 动态追加。

## 3. 约章证据底座的呈现

对应《共证》的外溢结算行（25 号文档 §3）：《公议》的结算信息是**约章锁在什么证据底座上**。

- 仲裁在《公议》叙事末尾追加一行：`本局约章的证据底座为 N 项独立公共事实，公开证据强度 Q=x.xx。`（N 取 `Judicial.IndependentPublicFacts`，Q 取 `Judicial.PublicEvidenceQ`，均为结算时刻的读数。）
- 该行只报事实，不作胜负：RULE_OF_LAW 资格只读 `PactLocked`（既有）。
- 加权明细（四类主体贡献）已在决策审计的贡献列表里，面板可查。
- 事实键清单（`PublicFactKeys`）本轮不上屏：键名是机制 ID，呈现层转译等 UI 批次。

## 4. 留存与再玩

### 4.1 结局之后玩家看到什么

1. **终局叙事**（§2.3）＋证据底座结算行。
2. **决策面板**：候选分数、四类主体贡献、资格池与排除原因——"为什么是这个结局"完全可查；《人治》与《公议》同池竞争时，两者的资格与分差直接可见。
3. **链的痕迹**：本局点亮的节点与完成键（树呈现待 UI 批次，本轮以决策审计与事件史为准）。

### 4.2 缺什么信息会让人想再开一局

- **约章回答不了的问题**：终局文本停在"这条命令到底从哪里来"被提出之前——另一局若走《共证》，会看到这个问题被回答的代价。
- **中间地带**：威势退场而约章未锁（18 < W ≤ 30）的驻地会走向《人治》——同一座驻地换一种喂法，秩序换一种形状。
- **拒绝的那扇门**：接触卡选了拒绝或暂缓的局，材料转喂 Mayor 圈层的世界只能重开一局去看（转线路径等《人治》节点群）。
- **另一座驻地**：不同种子、不同锚点节奏，锁定窗打开的时机与证据底座的数字都不一样。

### 4.3 明确不做

不做成就解锁项、不做跨局成长、不做结局图鉴收集——与《共证》同口径。
