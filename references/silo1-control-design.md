# Silo 1 控制力：分渠道强制能力、协作免疫与挂载点设计

> 本文档由 AI 维护（project-source）。本轮只做设计，不改代码、配置、事件或数值。
>
> 适用范围：Silo 40 的开放模拟；Silo 18 正典事件仍按绝对时间权威覆写。仅使用小说事实与项目外推，不把游戏外推写成原著事实。

## 0. 结论摘要

1. **不采用一个全局 `信息不对称 × 惩罚可用性` 作为权威状态。** 正确结构是先按强制渠道分别相乘，再跨渠道加权求和得到展示值。切断毒气只使毒气渠道归零，不影响远程打击或其他打击渠道。
2. **控制力不挂在 IT 身上，也不挂在某个“反抗主角”身上。** 它是 `Silo 1 → 目标地堡` 的关系状态；协作联盟只拥有反制项目的执行记录，不拥有 Silo 1 的控制力。
3. 三个候选中，推荐**方案 2 的修正版：当前反制成果及其协作联盟**。底层保留稀疏的群体覆盖率，必要时可投影成“渠道 × 群体”矩阵，但不做全量矩阵权威状态。
4. **免疫不是部门标签，而是反制成果产生的实际保护。** 参与者、贡献、实际保护和“知道自己安全”是四个不同概念。反制可以保护全堡，包括未参与者；参与者通常只是更确定保护已经生效。
5. 不新增“反抗者阵营”。用临时协作记录、跨部门关系边、反制里程碑、知情差异和 Silo 1 的可见 fallback，表达“反抗正在成形”。
6. 首个实现切片应是**毒气反制**：一个渠道、一个反制成果、任意部门或个体组成的协作记录，以及与 Safeguard 渠道结算的衔接。不要先上完整矩阵、通用夺回系统或全部渠道。

## 2. 指标语义与数学形式

### 2.1 先区分“控制”与“杀伤”

`Silo 1 控制力` 衡量的是 Silo 1 **迫使目标地堡改变行为的能力**，不是单纯的杀伤能力。毒气仍能杀死目标，不等于目标仍会服从；反之，目标已经知道如何反制却尚未执行，也不等于已经获得实际保护。

因此需要两个读出，不能混为一个数：

- **行为控制力 `C`**：信息优势与可用强制渠道共同产生的胁迫能力。
- **渠道可伤害性**：由上游可用性和实际保护决定，只在具体 Safeguard/打击结算中使用，不另做一个每月影响民心的全局指标。

物理轰炸只进入终局破坏事件，不进入常态 `C`：摧毁一个地堡不等于持续控制它。Reset 只有在隐蔽的本地执行链仍存在时才计入 `C`。按用户设定，在“反制 + 躲开远程打击”的开放路线中，Reset 的这条执行链也必须已经失效，因此 Silo 1 的常态控制力真正归零；若未来允许 Reset 继续可用，就不能同时宣称 Silo 1 已彻底失去控制。

### 2.2 分渠道公式

对目标地堡 `s`、常态控制渠道 `m∈{reset, safeguard_toxin, remote_strike}`、群体 `g` 定义；`bombing` 只走独立终局事件：

| 符号 | 范围 | 含义 |
| --- | --- | --- |
| `o_s,m` | `[0,1]` | Silo 1 对目标偏离、目标状态和该渠道执行条件的可操作观察质量 |
| `k_s,m` | `[0,1]` | 目标方对该渠道当前运作、反制方式与时机的可行动认知，不是“听说过毒气” |
| `ρ_m` | `[0,1]` | 渠道对反认知的敏感系数 |
| `I_s,m` | `[0,1]` | Silo 1 在该渠道上的信息优势 |
| `a_1,m` | `[0,1]` | Silo 1 及该渠道必需执行链的可用性；Silo 1 覆灭时全部归零 |
| `h_s,m,g` | `[0,1]` | 反制成果给予群体 `g` 的实际保护 |
| `ω_s,g` | `[0,1]` | 群体在目标地堡中的覆盖权重，首版取人口份额，`Σgω=1` |
| `ν_m` | `[0,1]` | 渠道在展示总量中的严重度权重，`Σmν=1` |

计算为：

```text
I_s,m   = clamp01(o_s,m · (1 - ρ_m · k_s,m))
H_s,m   = clamp01(Σg ω_s,g · h_s,m,g)
c_s,m   = I_s,m · a_1,m · (1 - H_s,m)
C_s     = 100 · Σm ν_m · c_s,m
v_s,m,g = a_1,m · (1 - h_s,m,g)
```

- `c_s,m` 是权威渠道向量；AI、行动门控和具体介入结算不得只读总量 `C_s`。
- `C_s∈[0,100]` 仅用于 UI 总览和审计摘要。`ν_m` 是展示权重，不是 Safeguard 概率。
- `v_s,m,g` 是具体渠道对具体群体的可伤害性，只在对应打击结算中使用；它不进入 `W`、`R_s` 或民心计量。
- 渠道内部使用乘法，保留“信息优势 × 可用性”的核心判断；渠道之间使用加权和，避免反制后总量被错误清零。
- 首版 `a` 与 `h` 可以采用离散 `0/1`，公式已支持以后引入部分破坏和部分覆盖，但不应提前实现连续衰减。

为什么不直接在全局使用 `C=I×P`：它会把不同渠道压成一次结算，无法表达“毒气归零、远程打击仍在”。为什么不在渠道之间继续连乘：任一渠道被切断都会让总量归零，直接违背原著情境。

### 2.3 信息与保护的输入来源

`o_s,m` 从 Silo 1 对目标的真实 Observation/Fact 聚合，至少区分：

- 目标是否发生 Order 偏离；
- Silo 1 是否知道偏离及责任链；
- 当前渠道的执行条件是否仍成立；
- Silo 1 是否知道反制位置、状态和负责人。

`k_s,m` 从目标方可行动知识的覆盖聚合：

```text
k_s,m = clamp01(Σe qK_m,e · B_e · π_e,actionable · coverage_e)
```

同一事实只有在包含可执行位置、步骤或时机时才提供高 `qK`；“Silo 1 很可怕”不提供反认知。玩家自己的确信不直接等于全堡 `k`，仍使用受众覆盖。

`k` 与 `h` 不重复计算：知道渠道位置只改变 `k`；实际反制才改变 `h`。反制事件可以同时产生参与者的知识 Observation 和物理反制结果，但两类写入必须有各自的原因与字段。

### 2.4 参数位置

建议未来集中于单一 `silo1_control` 配置资产，逻辑字段如下；本文不创建该文件，也不预设未经 sim 的数值：

| 参数位 | 内容 |
| --- | --- |
| `methods[].id` | 常态控制渠道：`reset` / `safeguard_toxin` / `remote_strike` |
| `methods[].weight` | 展示用 `ν_m`，仅跨常态控制渠道归一化，标注 `TODO(balance)` |
| `terminal_events[].id` | `bombing` 等一次性破坏事件，不进入 `C` 的权重 |
| `methods[].counterknowledge_sensitivity` | `ρ_m` |
| `methods[].observation_fact_tags` | 生成 `o` 所需的事实类别 |
| `methods[].counterknowledge_fact_tags` | 生成 `k` 所需的事实类别 |
| `methods[].initial_availability` | 新局上游可用性 |
| `countermeasures[].coverage_defaults` | 各反制成果的稀疏群体覆盖 |
| `countermeasures[].required_capabilities` | 项目所需能力槽，不写死部门 |
| `reclaim.*` | 夺回所需事实、操作资源、延迟、暴露与附带后果 |

功能开关关闭时必须保持原有逐位行为；功能开启而配置缺失或非法时必须显式失败，禁止静默回退为全渠道开放。

## 3. 免疫力：协作成果，而非部门标记

### 3.1 四个必须分离的概念

| 概念 | 挂载粒度 | 含义 | 不应承担的语义 |
| --- | --- | --- | --- |
| **参与记录** | 部门、具名个体或既有 faction | 谁参加过某项反制项目 | 不等于永久政治阵营 |
| **贡献/角色** | 项目参与者 | 谁提供情报、权限、工程、掩护或执行 | 不按贡献比例瓜分物理免疫 |
| **实际保护 `h`** | 稀疏群体覆盖 | 反制成果实际使谁免受该渠道伤害 | 不代表知道自己安全 |
| **可行动认知 `k`** | 观察者及其受众覆盖 | 谁理解反制并确信其有效 | 不直接改变物理结果 |

反制的物理效果可以覆盖全堡。参与者与未参与者获得相同的毒气保护，但参与者通常有更高 `k`。不同群体对反制效果的知情程度不同，实际保护与主观安全感仍需分开计算。远程打击规避若依赖特定条件、时机或预警，则不同群体可以拥有不同 `h`。

这同时修正两种错误：既不能把“特定部门执行”推成“只有该部门免疫”，也不能把“大家共同反制”推成“每个参与者都按贡献获得不同百分比的毒气免疫”。

### 3.2 协作记录不是新阵营

推荐的逻辑结构：

```text
CoalitionRecord
  id / method_id / countermeasure_id / status
  participants[]
    subject_type / subject_id
    capabilities[] / role / contribution
    joined_at / left_at

CountermeasureState
  id / method_id / status / integrity
  coalition_id
  coverage_by_group{group_id -> h}
  created_by_event / last_changed_by_event
```

`CoalitionRecord` 只是一次或一系列行动的值对象：

- 没有阵营名称、公开政治身份、意识形态、Demands、结局权重或永久忠诚；
- 不向 NPC 提供“我是反抗者”的全局标签；
- 可以只有一个参与者，因此能表达单个主体独自完成反制；
- 可以包含 IT、Judicial、Mayor 或任何既有部门，不预设谁必然反抗；
- 项目结束后记录保留用于审计与知识传承，不自动变成常设组织。

### 3.3 联合完成与角色转移

反制项目声明 `required_capabilities`，而不是 `required_departments`。例如“信息获取、执行权限、渠道停用、行动掩护”是【合理外推】的能力槽示例，不对应任何原著角色名单。一个主体可以满足多个槽，多方也可共同满足一个槽。

状态变化只由实际行动或正典事件触发：

1. 参与者加入时写入角色与能力，不写部门免疫标记。
2. 项目完成时原子写入 `CountermeasureState`、群体覆盖和参与者 Observation。
3. 参与者离开后，历史贡献与本人知识保留；实际保护是否变化只取决于反制是否失去关键维护条件。
4. 角色交接需要显式行动，记录知识传递、权限转移和接收者；禁止空转月份自动转移或自动恢复。
5. 关键人物死亡按现有规则处理；Silo 18 具名人物仍只能由正典节点改变生死。

### 3.4 Silo 1 能否夺回

原著资料未提供一套通用的“夺回免疫力”流程，因此以下全部为【合理外推】，而且必须按渠道实现，不能使用一个 `reclaim += x` 的通用按钮。

| 渠道 | 可设计的夺回链 | Silo 1 必须付出 |
| --- | --- | --- |
| 毒气 | 确认反制状态 → 获取恢复条件 → 恢复终止渠道可用性 → 验证结果 | 可操作情报、执行资源、时间窗口；制造可观测事件，并承担暴露、附带伤害或触发其他渠道反制的代价 |
| 远程打击 | 恢复目标观察 → 识别规避条件覆盖 → 压缩有效规避窗口或迫使目标暴露 → 重新验证 | 侦察资源、执行窗口、持续信息优势；不得无条件远程清除 `h` |
| 物理轰炸 | 当前没有已设计的成功防御，故首版没有夺回对象 | 若以后新增防御，再单独定义，不能复用远程打击规避 |
| Reset | 重建本地 IT 执行链、投药/减口条件和档案清理能力 | 本地代理、执行资源与隐蔽性；不能由 Silo 1 远程一键完成 |

夺回状态建议只用 `ACTIVE → CONTESTED → BROKEN` 的反制状态迁移，每一步都由事件驱动。资源字段至少包括 `required_facts`、`operation_cost`、`delay_months`、`exposure_effect` 与 `collateral_effect`，具体数值留待 sim。

## 4. 指标挂载点三方案比较

| 方案 | 实现复杂度 | 玩法收益 | AI 决策影响 | 评价 |
| --- | --- | --- | --- | --- |
| **A. 挂在 IT** | 低：复用部门状态即可 | 低：玩家会学到“打击 IT 即可获得全部免疫” | 最简单，但目标函数会错误聚焦 IT | **否决。** 主角从 Mechanical → Police/Sheriff → Mayor，从未掌管 IT，却是反抗主角；该方案会直接否定这条经验。[S5] |
| **B. 挂在当前免疫力持有者** | 中：需要反制成果、多人参与和角色更替 | 高：任何部门都能贡献，剧情可自然倒戈与交接 | 中：AI 面向具体项目和角色选择，不需理解全局政治阵营 | **推荐修正版。** “持有者”改为一个或多个协作参与者，控制力本身仍挂在 Silo 1→目标堡关系上。 |
| **C. 全局渠道×群体矩阵** | 高：不仅是存储，还包括内容、迁移、解释和行动目标组合 | 最高：可表达非常细的覆盖差异 | 高：每个动作都要评估目标群体、渠道、覆盖和外溢，候选空间显著扩大 | **不作为首版权威状态。** 矩阵本身仍不能表达联合因果，仍需协作记录；可由推荐方案投影生成。 |

推荐结构的逻辑所有权：

```text
Silo1ControlState（每个目标地堡一份）
  channels{method_id -> 信息、上游可用性、反制引用、派生 c}
CountermeasureState（每个已完成反制一份）
CoalitionRecord（每个反制项目一份）
coverage_by_group（稀疏存储；矩阵仅为只读视图）
```

这不是计算性能上的“矩阵爆炸”——当前渠道和部门数量有限，真正昂贵的是内容组合、AI 候选解释、状态迁移和验收用例。不应以性能为理由砍矩阵，而应以联合因果和落地成本为理由选择更准确的真源。

## 5. 与现有机制的衔接

### 5.1 幕后威势 `W`

`W` 是本地 IT 的极小关键联盟对其协调、赏罚和收场能力的预期；`C` 是 Silo 1 对目标堡的外部行为控制。两者不是上下级分数，也不互相乘算。

唯一推荐桥接是**事件输入**：

- Silo 1 的一次异常通牒若被本地 IT/Judicial 关键联盟知悉，并形成“IT 能靠上级收场”的预期，可按现有规则产生 `X` 或其他合格事实输入。
- Silo 1 介入失败、渠道被公开证明失效，也只有被关键联盟观察并归因后，才影响 `D/P/X`。
- 禁止每月直接执行 `W += f(C)`，禁止把 `C` 加进 Judicial sigmoid。

当前代码把 `SafeguardRisk` 暂作 `W` 的 `E` 代理；既有 IT 设计已经明确目标语义应为本地阴谋曝光。新系统不得利用这个临时代理再把 `C` 与 SafeguardRisk 相连，否则会固化错误语义。

### 5.2 信息曝光 `E`、公开证据 `Q` 与 Judicial 三方附着

- `E`：本地居民/关键联盟对“IT 幕后掌权”的曝光高水位。
- `Q`：支持 pact 的公开证据质量。
- `k_s,m`：目标方对 Silo 1 某一强制渠道的可行动反认知。

三者可以消费同一 Fact/Observation，但必须使用不同归因标签、受众和聚合参数。知道 Silo 1 存在不自动证明本地 IT 非法调度 Judicial；证明本地 IT 非法也不自动提供反制能力。

Judicial 附着继续只由现有 `W`、Mayor 个人正统性和 `Q` 等规则驱动。`C` 不直接增加 `A_IT/A_Mayor/A_pact`，只能通过已经发生、被观察且符合现有输入条件的事件间接影响。

### 5.3 Safeguard 风险与硬失败

`SafeguardRisk/R_s` 回答“是否进入介入评估”，`c_s,m` 回答“某渠道还能造成多少行为控制”，实际保护与渠道可用性回答“这次介入能否生效”。三者必须串联而非重复加分：

```text
Order 偏离 → R_s / 介入分
介入评估 → 选择情境合法的渠道
渠道结算 → 检查 a_1,m、目标覆盖 h、情境条件
```

- 禁止 `R_s *= C`、`R_s += C` 或用低 `C` 直接取消既有硬失败判定。
- 毒气反制后，毒气渠道不可选；远程打击只有在实际情境满足其条件时才可作为 Fallback，不能把堡外远程打击证据外推成无条件堡内攻击。
- 若所有合法渠道都不可用，应产生可观测的“介入未奏效/无法执行”结果，而不是仍按原毒气动画判全堡死亡，也不能静默显示成功防御。
- Silo 1 覆灭时所有 `a_1,m=0`，后续只走既有覆灭事实与结局逻辑，不再额外扣一次 `C` 或 `W`。

### 5.4 既有叛乱、派系与结局

`Rebellion` 继续表示公开动荡，不代表有组织反制能力。低叛乱可以存在高效秘密协作，高叛乱也可能完全不会反制。

不为协作记录新增结局主体或“反抗者贡献”。它只通过已有玩家、派系、具名人物和 Silo 1 的真实状态变化影响结局。任何派生“反制数量/保护人口”只用于展示和审计，不直接加分。

## 6. 不设反抗者阵营时，如何表达“反抗在成形”

### 6.1 可见的是能力网络，而不是新徽章

在每个具体反制项目下建立稀疏关系边：

```text
主体 A --提供可行动事实--> 项目
主体 B --提供进入权限-----> 项目
主体 C --完成工程操作-----> 项目
主体 D --掩盖执行痕迹-----> 项目
```

这些边属于项目，不改写主体的永久政治身份。UI 可以展示“谁开始与谁合作、还缺什么能力、哪些知识已经跨过部门边界”，而不是展示“反抗阵营已成立”。

### 6.2 用连锁反应代替阵营进度条

一次成功反制应产生以下可观察链条：

1. **行动前**：不同主体分别掌握不足的事实、权限或能力，单方无法完成。
2. **协作中**：跨部门关系、目击记录、异常调度和风险上升；参与者可退出或交接。
3. **完成时**：特定渠道控制力和可伤害性下降，参与者获得知识，未参与者未必知情。
4. **Silo 1 响应**：旧通牒失效、重新侦察、改用仍合法的其他渠道，或暴露其无法执行。
5. **社会后果**：目击者开始重新评估 Silo 1；恐惧并未同步消失，信息差成为后续剧情张力。

玩家看到的是“反制成功 → 毒气威胁消失 → 远程打击风险上升 → 另一批人开始评估后续风险”，而不是一个 Resistance 数值上涨。

### 6.3 只读派生信号

可提供四个不设政治身份的只读信号：

- 当前有效反制渠道数；
- 参与跨部门项目的独立主体数与能力槽覆盖；
- 各渠道实际保护覆盖；
- 被目标方观察到的 Silo 1 介入失败次数。

它们不得合并成新的“反抗度”，不得直接驱动结局，也不取代 `Rebellion`。

### 6.4 NPC 如何参与而不获得阵营身份

NPC 对每个具体项目候选独立评估：

```text
U_join = w_b·可行动确信
       + w_r·与发起者关系
       + w_c·自身能力匹配
       + w_i·既有开放/忠诚等思潮影响
       - w_risk·感知风险
       - w_cost·行动成本
```

AI 只判断“是否参与这次反制/规避/交接”，不判断“是否加入反抗者”。候选按稳定主体 ID 排序并沿用现有共享 RNG；Silo 18 正典人物不参与这种自由改写。

## 7. 分阶段 roadmap

### 第 1 步：毒气反制最小纵切

- 增加单目标堡的 Silo 1 渠道状态、一个 `safeguard_toxin` 反制成果和协作记录。
- 支持任意一个或多个主体完成能力槽；不绑定 Mechanical、Mines 或 IT。
- 反制只改变毒气覆盖，生成参与者知识；远程打击、轰炸和 Reset 不变。
- 接入 Safeguard 渠道结算，反制后不能再按毒气成功执行。
- 功能关闭保持 parity；功能开启时跑同种子对照。

**这是第一步。** 它同时验证挂载点、联合免疫和 Safeguard 分工，避免先造完整公式却没有实际玩法。

### 第 2 步：协作网络与知情差异反馈

- 加入参与、退出、显式交接、稀疏群体覆盖和项目关系图。
- 展示渠道分解、实际保护与“哪些群体知道”的差异，不展示全知视角下玩家无权知道的事实。
- 完成“非参与居民仍受物理保护但不一定知情”的 UI 与审计。

### 第 3 步：远程打击渠道与合法 Fallback

- 独立加入 `remote_strike`，不继承毒气覆盖。
- 只为有明确内容的规避方式建立反制项目；缺少依据的能力与参与者继续标为外推。
- 接入 Silo 1 重新评估、可见响应和 W 的事件式 `X/D/P` 桥接；不增加直接 `C→W` 公式。
- 物理轰炸保持独立，不复用远程打击规避成果。

### 第 4 步：Reset 执行链

- 把 Reset 作为需要本地执行链的渠道接入，区分 Silo 1 指令与本地 IT 实施。
- 只有反制流程获得明确设计裁决后才实现玩家阻断；不得从反制规则复制一套“单一反制即全免疫”。
- 验证信息曝光 `E/Q`、本地 IT 的 `W` 与 Silo 1 反认知 `k` 不重复聚合。

### 第 5 步：夺回、AI 与批量平衡

- 按渠道逐一实现夺回链、资源成本与可观察后果，不做通用夺回按钮。
- AI 只接收当前可执行的项目角色候选，不遍历完整矩阵。
- 跑同种子 sim、熟练策略、单人反制、多人协作、人员更替、介入失败与多种子平衡；通过后再调 `ν/ρ/成本`。

每一步都应原子提交并满足：存读档字段完整初始化、稳定 ID 排序、无被动月份推进、功能关闭 parity、Silo 18 正典逐位不变。新存档语义若不能无损迁移，应明确升版本或拒绝旧档，不伪造历史反制记录。

## 8. 必须砍掉的复杂度及损失

| 砍掉项 | 保留的替代 | 会损失什么 |
| --- | --- | --- |
| 全量渠道×群体矩阵作为真源 | 渠道状态 + 稀疏覆盖 + 只读矩阵投影 | 极端细致的默认群体差异；以后确有内容需要时可补稀疏项 |
| 每个居民的独立实际免疫 | 群体实际保护 + 个体知识/贡献 | 个体特殊掩体、独特防护等例外；应由明确事件按需增加，而非全民模拟 |
| 按月连续转移、衰减和夺回 | 显式行动/正典事件驱动状态迁移 | 无操作时的缓慢自然变化；换来因果清楚、可回放和不会空转变成熟反抗 |
| 通用夺回机制 | 分渠道夺回链 | 开发复用度较低，但避免“同一招恢复所有控制”的伪逻辑 |
| 供应链、社会操纵等额外渠道 | 仅使用已核实渠道；未来单独立项 | 潜在玩法广度，但避免把外推伪装成原著并提前扩张 AI 行动空间 |
| 单一总量参与全部结算 | 总量展示、渠道向量结算 | UI 需要多展示一层渠道明细，但杜绝反制误免全部打击 |

首版最大的取舍是：**放弃“所有群体在所有渠道上的连续精确数值”，保留“谁通过什么协作取得了哪种实际保护”这一核心因果。** 损失的是数值细密，不是原著关键经验。

## 9. 验收用例清单

1. 反制后 `c_toxin=0`，远程打击、轰炸、Reset 的渠道状态不变。
2. 多部门共同完成时，每个参与者有独立贡献；任何一个部门都没有永久免疫标签。
3. 单个主体可以独立完成；多个主体也可以加入同一项目。
4. 贡献比例不决定毒气保护比例；未参与者可被物理保护但保持低知识。
5. 远程打击覆盖可以因群体而异，且不改变毒气覆盖。
6. 成员退出不会自动删除反制；关键角色只能经显式交接或新行动改变。
7. `C` 不直接修改 `SafeguardRisk` 或 Judicial 附着；只有合格事实事件能进入 `W` 输入。
8. 毒气不可用时，远程打击只有满足自身情境条件才可 Fallback；无合法渠道时不得照旧判毒气死亡。
9. Silo 1 覆灭后所有上游可用性归零，不重复扣减。
10. Silo 18 的参与者、覆盖和结果只由正典节点权威写入，AI 不改变具名人物生死或制造矛盾结果。
11. 功能关闭、空邻堡与既有单堡行为保持逐位一致；同种子双跑逐字节一致。
12. 存读档恢复所有 map/slice 和协作引用，不出现首月空列表 panic 或反制丢失。
13. 双反制完成且 Reset 执行链失效后 `C=0`；一次性轰炸事件不向常态 `C` 加回数值。
